## 1. 작업 개요 (Mac Pro Agent가 해야 할 일)

DEV Asterisk(Docker `kibal-dev-asterisk`)에서 **회의실 6000 참가자의 원격 스트림에
오디오 트랙이 누락**되는 상황을 조사/수정합니다.

**증상 (클라이언트 측 확정 로그):**
- 1:1 통화: `video=1 audio=1` 정상 (SIP/SDP 경험 코드가 없는 단일 채널)
- 6000 회의: 세 개 클라이언트 모두 `remoteStreamAdded video=1 audio=0`
- 완료 이력: 2026-11-09 는 첫 원격 스트림 `video=1 audio=1` 이었으며, 현재 `audio=0`
  → 11-09 이후 서버 bootloader/ConfBridge 설정 변경이 의심됨

**가설:**
- Asterisk ConfBridge(이 명인: `kibal_bridge`/`kibal_user` 프로파일)에서
  video mode 활성화로 인해 SDP renegotiation시 `m=audio` 삭제 / `a=inactive`화가 되었을 가능성
- 또는 server `pjsip.conf` / `sip.conf` UUID 맴버 장치 재정의로 audio 라인 누락

## 3. 조사 (Dev-Diagnostics)

### 3-1. SSH 접근 (기존 리포 경로 존재)
컨테이너 내 아래 명령을 확인 순서대로 실행하세요:

```bash
docker exec -it kibal-dev-asterisk asterisk -rx "core show version"
docker exec -it kibal-dev-asterisk asterisk -rx "pjsip show endpoint 6000"
docker exec -it kibal-dev-asterisk asterisk -rx "pjsip show endpoint 1101"
docker exec -it kibal-dev-asterisk asterisk -rx "pjsip show endpoint 1102"
```

특히 `pjsip show endpoint 6000` 출력에서:
- `m=audio` 서셜 있습니다: **audio가 send/recv 되고 있는지 아래 커맨드로 확인**
- 이 출력이 비어 있거나 `6000`이 정의되지 않는다면: dialplan(styles: `from-internal`) 확인

### 3-2. confbridge 설정 확인

```bash
docker exec -it kibal-dev-asterisk cat /etc/asterisk/confbridge.conf  | head -100
```

- `[kibal_bridge]` 프로파일 읽고:
  - `type = bridge` / `bridge_profile` …
  - **`video_mode = ` (none | participant | talker | mux … )** ← 여기가 핵심
  - `jitterbuffer`, `sound_only_person` 등

**현재 목표**: video_mode가 `none`이 아닌 값이라면 클라이언트에게
2개의 video m-line만 들어오는 현상이 이 설정 때문일 가능성이 높습니다.

### 3-3. SDP 로깅 켜서 다수 참가자 회의 접속 시 캡처

```bash
docker exec -it kibal-dev-asterisk asterisk -rx "pjsip set logger on"
docker exec -it kibal-dev-asterisk asterisk -rx "rtp set debug on"
```
이후 웹 및 macOS 클라이언트로 **1102, 1103 두 계정이 동시에 6000 회의**에 접속.

아래 형태의 파일을 찾아보고 `200 OK`/`INVITE` SDP 본문에서 뽑을 것:
```
m=audio 44700 RTP/AVP 0 8 111 9
m=video 52621 RTP/AVP 96 31
```
- `m=audio`가 **아예 없다면**: 서버 설정 문제 확정 (D2-A 가설B)
- `m=audio`가 있으나 `a=recvonly` / `a=inactive`라면: 동일

### 3-4. dialplan 확인 (conf-시작/끝 및 전송)

```bash
docker exec -it kibal-dev-asterisk cat /etc/asterisk/extensions.conf | grep -A8 6000
```

**예상 코드:**
```
exten => 6000,1,NoOp(Kibal conference 6000)
exten => 6000,2,Answer()
exten => 6000,3,ConfBridge(6000,kibal_bridge,kibal_user)
```

- `Answer()` 단계에서 video no handling가 `RTP video` 협리만 두고 audio 안 뷰와 하는 경우가 있음

## 4. 원본별 약효 분집

### (A) `confbridge.conf` video_mode 조정 (제일 확률 높음)

우선 **video_mode를 명시적으로 none 으로 시작**해 검증:

```bash
docker exec -it kibal-dev-asterisk sed -i 's/^video_mode.*/video_mode = none/' /etc/asterisk/confbridge.conf
docker exec -it kibal-dev-asterisk asterisk -rx "core reload"
```

이후 두 클라이언트로 6000 재접속 → `remoteStreamAdded video=? audio=?` 변화 관찰.

### (B) dialplan 점검

`from-internal` Extention 6000 라인이 위 예상 형식과 동일한지 재연결 빌드.
(가끔 `Progress()` / `Ringing()` 혼재로 인해 SDP가 특이해지는 문제 있음)

### (C) RTP/core 설정

```bash
docker exec -it kibal-dev-asterisk asterisk -rx "rtp show rtcp stats"   # 송/수신 통계
docker exec -it kibal-dev-asterisk asterisk -rx "pjsip show transport"  # WS/TCP 상태
```

오디오 RTP 수신은 뜬다면 재협상의 문제는 아님 → client 단 (이미 v0.0.4 대응)

## 6. 하지 말아야 할 일

- **`sip.conf`/`pjsip.conf` 의 `audio/video` 절의 삭제 금지** — 단순 얼 눌击로 전 데이터 유실 우려
- **`Answer()` 제거 금지** — conf 없이 다이렉트 서멍 조정되면 client가 RID 가능성
- Restart `kibal-dev-asterisk`는 재접속관련 끊김이 클라 계정 스냅오피에 기록되므로, **조사 후 client 3개 접속이 접속 보류 중인 상태면 연결 제어**
