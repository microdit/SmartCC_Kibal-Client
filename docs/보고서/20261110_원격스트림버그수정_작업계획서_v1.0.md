## 1. 목적

Mac Pro DEV 서버 작업 프롬프트를 분석·정정하고, **ConfBridge 6000 다자간 회의에서 원격 스트림 audio 누락(`remoteStreamAdded video=1 audio=0`)** 현상의 재현·원인 확정·수정·검증 계획을 수립한다. 서버 설정 변경 가설에 의존하지 않고, **클라이언트 최신 버전 재검증과 SDP 증거 기반 진단**을 우선한다.

## 2. 범위 및 전제

| 구분 | 포함 | 제외(별도 승인 필요) |
|------|------|----------------------|

**전제**
- 1:1 통화는 `video=1 audio=1` 정상(프롬프트/버그분석 기준). 회의만 증상이라는 가정하에 ConfBridge 경로를 우선 분석한다.
- 서버 저장소는 현재 `운영콘솔OPS` 브랜치(`0e18c49`)에 있으나, **서버 미디어 수정은 운영콘솔 변경과 분리된 브랜치**(권장: `fix/confbridge-remote-audio`, `main` 기준)에서 수행한다.
- 컨테이너 내부 임시 수정(`sed -i`, `core reload`)은 **진단용 A/B에 한해** 허용하며, 최종 반영은 소스 수정 + 이미지 재빌드/재배포로 한다.

## 3. 원 프롬프트 분석 및 정정 사항

### 3.1 핵심 증상(프롬프트/버그분석)
- 1:1: `remoteStreamAdded video=1 audio=1`
- 6000 회의: 3대 모두 `remoteStreamAdded video=1 audio=0`
- 회귀 주장: 2026-11-09에는 audio=1 → 이후 audio=0

### 3.2 기술적 정정 (작업 수행 시 반드시 적용)

| 원문/가정 | 문제 | 정정/대응 |
|-----------|------|-----------|
| "11-09 이후 서버 bootloader/ConfBridge 설정 변경 의심" | **git 이력과 불일치**: `confbridge.conf` `video_mode=sfu`는 2026-10-30(`fa239e4`) 이후 변경 없음, `pjsip.conf.template` WebRTC/스트림 설정은 2026-11-01(`d3742a0`) 이후 변경 없음 | 런타임 컨테이너 설정이 repo와 다른지 **md5/내용 비교**로 확인. 회귀 상관관계는 클라이언트 변경(v0.0.2→v0.0.3, `34410e8`)을 우선 검토 |
| `pjsip show endpoint 6000` | 6000은 PJSIP endpoint가 아니라 dialplan extension/ConfBridge room | `dialplan show 6000@from-internal`, `confbridge list 6000`, `confbridge show bridges`, `pjsip show endpoints`, `pjsip show endpoint 1101/1102/1103` |
| `rtp show rtcp stats` | 표준 CLI가 아님(환경에 따라 미존재) | `rtp show settings`, `pjsip show channelstats`, `core show channels verbose`, 필요 시 `rtp set debug on` |
| `sed -i 's/^video_mode.*/video_mode = none/' ... && core reload` | 컨테이너 레이어 임시 변경(재생성 시 유실). `video_mode=none`은 **영상 비활성화**로 오디오 수정책이 아님 | 진단용 A/B만 허용, 결과 기록 후 원복. 최종 수정은 `server/asterisk/config/confbridge.conf` 소스 변경 + dev 재배포 |
| `docker exec -it ...` | 비대화형 자동화/스크립트에 부적합 | `docker exec kibal-dev-asterisk ...` 또는 `-i` 사용 |
| "Answer() 제거 금지" 등 외 가독성 문제/깨진 문구 | 원문 일부 인코딩·오탈자(예: "scoreboard→설정 변경", "보당→복귀") | 본 계획서에서 정규화. `Answer()`/인증/pjsip 핵심 속성 임의 삭제 금지 원칙 유지 |

### 3.3 현행 기준선 스냅샷 (분석 시점)

**서버 (`SmartCC_Kibal`, 분석 기준 HEAD `546ea26`/현재 브랜치 `운영콘솔OPS`)**
- `confbridge.conf`: `default_bridge`, `kibal_bridge` 모두 `video_mode=sfu`, `max_members=10`
- `extensions.conf`: `exten => 6000,1,NoOp... / n,Answer() / n,ConfBridge(6000,kibal_bridge,kibal_user) / n,Hangup()`
- `pjsip.conf.template` (1101~1103 webrtc-endpoint): `webrtc=yes`, `direct_media=no`, `rtp_symmetric=yes`, `force_rport=yes`, `rewrite_contact=yes`, `media_use_received_transport=yes`, `max_audio_streams=1`, `max_video_streams=8`, codecs `ulaw,alaw,opus,vp8,h264`
- `rtp.conf.template`: `rtpstart/end`, `icesupport=yes`, `strictrtp=yes`
- `http.conf.template`: WS `bindport=${SIP_WS_PORT}` (dev 기본 8088)

**클라이언트 (`SmartCC_Kibal-Client`, `feature/macOS-version` HEAD `ce96203`)**
- `macos-client/lib/src/media/media_manager.dart`: 세션별 복수 스트림 보관(`_remoteSessions: sessionId -> List<MediaStream>`), `_rebindAllRemoteRenderers()`로 영상 스트림 바인딩, **addTrack 미사용**(nil 스트림 크래시 회피), 오디오 트랙은 스트림 보관으로 네이티브 재생 유지 의도
- `34410e8`에서 D1/D2/D4/D5(P0) 수정 반영(v0.0.3). 이후 `8f2a8d0`, `ce96203` 추가 변경 존재 → **최신 HEAD로 재검증 필수**

| H4 | WS/ICE/DTLS/RTP 경로 문제로 오디오 RTP 미수신(수신은 되나 패킷 0) | `rtp set debug on`, `pjsip show channelstats`, 클라이언트 webrtc stats | P1 |
| H5 | 계정 혼선/중복 등록(D3)으로 잘못된 세션을 관측 | 버그분석에서 1102 중복 등록 확인. 테스트 전 계정-기기 1:1 매핑 필수 | P0(테스트 통제) |

```bash
docker exec kibal-dev-asterisk asterisk -rx "pjsip set logger on"
docker exec kibal-dev-asterisk asterisk -rx "rtp set debug on"
# 1101/1102/1103 6000 동시 접속 후 INVITE/200 OK/ACK, re-INVITE 캡처
# 종료 후:
docker exec kibal-dev-asterisk asterisk -rx "rtp set debug off"
docker exec kibal-dev-asterisk asterisk -rx "pjsip set logger off"
```
**확인 포인트**: 각 레그 SDP에 `m=audio` 존재 여부, 코덱/포트, `a=sendrecv|sendonly|recvonly|inactive`, `m=video`와의 관계, 재협상 전후 차이. `m=audio` 부재/비활성이면 H2 확정.

### 5.4 클라이언트 증거 수집
- 3대 각각 고유 계정(1101/1102/1103) 1:1 매핑 확인(quickConnect 혼선 금지)
- 최신 빌드(HEAD 기준, 버전 명시)로 6000 접속
- AppLogger/실행 로그에서: `remoteStreamAdded` 시점 `video/audio` 트랙 수, 세션별 스트림 개수, `getAudioTracks().length`, renderer 바인딩, 종료/재접속 시 정리 로그
- 가능하면 WebRTC stats(오디오 bytesReceived/packetsReceived) 수집

- 서버: CLI 원문, SDP 캡처(`m=audio`/direction), `confbridge list`, 채널 stats
- 변경 시: 소스 diff, 배포 명령/이미지 태그, 롤백 절차
