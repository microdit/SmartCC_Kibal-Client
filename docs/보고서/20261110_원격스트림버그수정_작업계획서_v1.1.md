## 2. 원인 가설 및 우선순위

| ID | 가설 | 우선순위 | 판정 근거 |
|----|------|----------|-----------|
| H1 | 클라이언트가 오디오 수신/보유하나 UI·렌더·세션 매핑에서 누락(또는 스트림 단위 로그 오판) | **P0** | 프로브 정상/UI 비정상, 세션 합계 audio 존재, SDP/RTP 정상+재생 누락 |
| H5 | 계정 혼선/중복 등록으로 오관측 | **P0(통제)** | contacts/로그 불일치, 의도 계정 미등록 |
| H2 | ConfBridge/PJSIP 재협상으로 `m=audio` 누락·inactive/recvonly | **P1(증거대기)** | SDP 캡처에서 m-line/direction 이상 |
| H3 | dialplan/endpoint 속성(`max_audio_streams` 등) 조합 문제 | P1 | 1:1/회의 SDP 비교, 런타임 설정 대조 |
| H4 | ICE/DTLS/코덱/RTP 경로 문제 | P1 | RTP bytes 0, stats/디버그 로그 |

## 3. 측정지표·분기표

### 3.1 지표
| 지표 | 측정 위치 | 정상 기준(초기) |
|------|-----------|------------------|
| 오디오 이벤트/트랙 | `remoteStreamAdded`(스트림 단위) + 세션 합계 `sessionVideo/sessionAudio`, 프로브 `remoteAudioTracks` | 세션 기준 audio 관측(단일 이벤트 0 허용 가능성 있음) |
| SDP | 클라이언트 remote description, 서버 `pjsip set logger` 캡처 | `m=audio` 존재, `a=sendrecv`(회의 정책 내) |
| RTP 수신 | WebRTC `inbound-rtp/audio bytesReceived/packetsReceived` | 증가, 지속 |
| 실청취/품질 | 3자 상호 발화 | 양방향 가청, RTCP loss 목표 <2%(보정) |

### 3.2 분기
| 관측 | 판정 | 다음 조치 |
|------|------|-----------|
| 프로브 audio=1, UI audio=0(동일 조건) | H1 | F2(클라이언트) 직행, 서버 A/B 보류 |
| SDP `m=audio` 없음 | H2 | 서버 협상 조사(F3), 소스 수정/재배포(F4) |
| `m=audio` + `inactive/recvonly` | H2 | 재협상/브리지 상태 조사(F3) |
| `m=audio sendrecv`, RTP 증가, 트랙/재생 없음 | H1 | F2 |
| `m=audio sendrecv`, RTP 0 | H4 | ICE/DTLS/RTP 경로 |
| 중복 등록/계정 불일치 | H5 | 통제 후 전 단계 재실행 |

## 4. WBS (목표 5~8h, 환경 변동)

| 단계 | 작업 | R(실행)/A(승인)/C/I | 산출물/완료 기준 |
|------|------|---------------------|------------------|
| S0 | 프로브 재실행 + UI 동일조건 재측정, 버전/커밋/계정 기록 | R: 클라이언트 / A: 담당자 | 비교가능성 결과, H1/H2 초기 분리 |
| W1 | 계정-기기 1:1 매핑, 중복 등록(D3) 제거, 테스트 조건 고정 | R: 운영/테스트 / A: 담당자 | contacts/로그 증거 |
| W2 | 서버 런타임 기준선 수집, 정적 md5 + pjsip 구조 비교 | R: 서버 / A: 담당자 | CLI 원문, 비교표(마스킹) |
| W3 | 최신 UI 3대 재검증(F1), 지표 4종 수집 | R: 클라이언트 | 로그/스크린샷/stats |
| W4 | 필요 시 SDP/RTP 캡처, 분기표 판정 | R: 서버+클라이언트 | SDP 발췌(마스킹), 판정 |
| W5 | 원인별 수정(F2 우선, H2 확정 시 F3/F4) | R: 해당 개발 / A: 리뷰 | diff, 재배포/빌드 기록 |
| W6 | T1~T5 회귀 검증 | R: 테스트 | 합격/불합격 로그 |
| W7 | 보고서 작성(`20261110_서버원격스트림_보고서_v1.0.md`) | R: 서버 작업자 / A: 리뷰 | 원인·증거·diff·결과·롤백 |

## 5. 수정 방안

- **F1(P0)**: 무변경 재검증. S0 결과로 서버 변경 필요성 판단.
- **F2(P0/P1)**: 클라이언트 스트림/트랙 수신·재생·렌더 정합성 보강, 로그 지표 개선(스트림 단위 vs 세션 합계), 계정 혼선 UX/절차 보강.
- **F3(P1)**: H2 증거 시 ConfBridge/PJSIP 협상 A/B(진단용 임시, `video_mode=none` 최종안 금지).
- **F4(P1)**: 서버 소스(`server/asterisk/config/*`) 수정 + dev 재배포. 브랜치 `fix/confbridge-remote-audio`(main 기준, 운영콘솔OPS 분리) 권장.
- **F5(P2)**: WS 핸드셰이크(D8), identity IP(D7), 프로브/도구 개선.

## 6. 테스트·합격 기준

| ID | 시나리오 | 합격 기준 |
|----|----------|-----------|
| T1 | 1101↔1102 1:1 | `video=1 audio=1`, 양방향 가청, 종료 후 미디어 해제 |
| T2 | 1101/1102/1103 6000 | 원격 표시, 세션 기준 audio 수신, **양방향 실청취**, RTCP loss 목표 <2% |
| T3 | 입/퇴장 재협상 | audio/video 유지, 크래시/누수 없음 |
| T4 | 종료 후 재진입 | 재바인딩 정상, placeholder/셀프 누수 없음 |
| T5 | 등록 정합성 | 기기-계정 1:1, 중복 등록 없음 |

## 7. 리스크·롤백·보안

- 서버 변경은 소스 기반 + 이전 이미지/커밋 롤백 경로 확보. 진단용 컨테이너 변경은 기록 후 원복.
- `pjsip set logger on`, `rtp set debug on`은 캡처 후 즉시 off.
- 증거 마스킹: Authorization/nonce/response/password/secret/token/개인정보. 경로 `docs/_작업이력/evidence/20261110-remote-audio/`.
- 금지: 인증·pjsip 핵심 속성 임의 삭제, `Answer()` 제거, 증거 없는 `video_mode=none` 고정, 무통보 재시작.
