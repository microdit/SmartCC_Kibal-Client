## 1. 목적 및 범위

v2.0(`RV-20261110-REMOTE-AUDIO-002`)의 지적사항을 항목별로 검토하여 **수용(Accept)**, **부분 수용(Partially Accept)**, **비수용/유보(Reject/Hold)**로 분류하고, 그 근거와 반영 조치를 정의한다. 본 문서는 v2.0을 대체하지 않으며, 실행 착수 전 기준선으로 사용한다.

| 작업계획서 v1.0 | 조건부 승인(B) | **수용 — 보완 후 착수** | Evidence-First 골격은 타당하나 기준선 버전·비교가능성·측정지표·분기·비교 방법 보완 필요 |

### 6.2 측정지표(합격/판정)
| 지표 | 위치 | 정상 기준(초기) |
|------|------|------------------|
| 오디오 이벤트/트랙 | `media_provider` 로그, `getAudioTracks()` | 세션당 오디오 트랙/스트림 관측 또는 오디오 수신 확인 |
| 원격 SDP | 클라이언트 remote description, `pjsip set logger on` 캡처 | `m=audio` 존재, direction `sendrecv`(회의 정책 범위 내) |
| RTP 수신 | WebRTC `getStats()` `inbound-rtp/audio.bytesReceived`, `packetsReceived` | 0이 아니고 증가 |
| 실청취/품질 | 3자 상호 발화 테스트 | 양방향 가청, RTCP loss 목표 <2% (환경에 따라 보정) |

### 6.3 증거→원인→조치 분기
| 관측 | 판정 | 조치 |
|------|------|------|
| 프로브 `audio=1`, UI `audio=0` (동일 조건) | H1 우선 | F2(클라이언트 렌더/스트림/세션 처리) 직행, 서버 A/B 보류 |
| 서버/클라 SDP `m=audio` 없음 | H2 유력 | ConfBridge/PJSIP 협상 조사(F3), 소스 기반 수정(F4) |

| `m=audio sendrecv`, RTP bytes 증가, 트랙/재생 없음 | H1 유력 | 클라이언트 재생·바인딩·세션 매핑 수정(F2) |
| `m=audio sendrecv`, 트랙 있으나 RTP bytes 0 | H4 유력 | ICE/DTLS/코덱/포트/RTP debug |
| 중복 등록/계정 불일치 | H5 | 계정 통제 후 재시험(다른 결론 보류) |

### 6.4 런타임 비교 방법
- **정적 파일(md5/diff 가능)**: `confbridge.conf`, `extensions.conf`, `rtp.conf.template`, `http.conf.template` (런타임 대응 파일)
- **치환 파일(구조 비교)**: `pjsip.conf.template` ↔ `/etc/asterisk/pjsip.conf`는 민감값 마스킹 후 항목 비교 + `pjsip show endpoint/transport/aor` 런타임 출력 대조

### 6.5 보안/증거
- 캡처 경로: `docs/_작업이력/evidence/20261110-remote-audio/`
- 마스킹: `Authorization`, nonce/response, password/secret/token, 개인식별 정보
- `pjsip set logger on`, `rtp set debug on`은 캡처 직후 off 확인
