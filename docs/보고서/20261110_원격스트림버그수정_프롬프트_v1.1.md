## 1. 목적과 성공 기준

**증상**: 6000 회의에서 원격 스트림이 `video=1 audio=0`으로 관측됨(보고서 기준). 1:1은 `video=1 audio=1` 정상 사례 존재.  
**목표**: (1) S0/재검증으로 클라이언트·계정·비교가능성 배제/확정, (2) 필요 시 SDP/RTP 증거로 서버 원인 확정, (3) 원인별 수정 후 3자 회의 audio/video 복귀.

**성공 기준(초기)**: 3자(1101/1102/1103) ConfBridge 6000에서 각 참가자 원격 오디오 수신 확인(트랙/SDP/RTP bytes 증가/실청취), 1:1 회귀 없음. 단일 `remoteStreamAdded` 스트림 로그만으로 판정하지 않는다(트랙별 스트림 이벤트 가능).

## 2. 사전 통제 (착수 게이트)

- [ ] **S0 우선**: `conference_probe.dart`를 현재 기준 클라이언트로 재실행하고 UI와 동일 조건 결과 비교(프로브 정상/UI 비정상이면 H1 우선, 서버 A/B 보류)
- [ ] 계정-기기 1:1 매핑, `pjsip show contacts`/앱 로그로 중복 등록 없음 확인 (D3)
- [ ] 활성 통화/회의 없음 확인: `core show channels count`, `confbridge list 6000`
- [ ] 증거 폴더 준비: `docs/_작업이력/evidence/20261110-remote-audio/` (CLI, SDP, 로그, 스크린샷)
- [ ] **민감정보 마스킹**: SIP Authorization/nonce/response, password/secret/token, 개인식별정보 제거 후 저장
- [ ] 디버그 on/off 계획 수립 (`pjsip set logger on/off`, `rtp set debug on/off` 캡처 직후 해제)

## 3. 조사 절차

### 3.1 런타임 기준선 수집
```bash
docker ps | grep asterisk
docker exec kibal-dev-asterisk asterisk -rx "core show version"
docker exec kibal-dev-asterisk asterisk -rx "core show uptime"
docker exec kibal-dev-asterisk asterisk -rx "core show channels count"
docker exec kibal-dev-asterisk asterisk -rx "dialplan show 6000@from-internal"
docker exec kibal-dev-asterisk asterisk -rx "confbridge show bridges"
docker exec kibal-dev-asterisk asterisk -rx "confbridge show bridge 6000"
docker exec kibal-dev-asterisk asterisk -rx "confbridge list 6000"
docker exec kibal-dev-asterisk asterisk -rx "pjsip show endpoints"
docker exec kibal-dev-asterisk asterisk -rx "pjsip show endpoint 1101"
docker exec kibal-dev-asterisk asterisk -rx "pjsip show endpoint 1102"
docker exec kibal-dev-asterisk asterisk -rx "pjsip show endpoint 1103"
docker exec kibal-dev-asterisk asterisk -rx "pjsip show contacts"
docker exec kibal-dev-asterisk asterisk -rx "pjsip show transports"
docker exec kibal-dev-asterisk asterisk -rx "http show status"
docker exec kibal-dev-asterisk asterisk -rx "rtp show settings"
docker exec kibal-dev-asterisk cat /etc/asterisk/confbridge.conf
docker exec kibal-dev-asterisk cat /etc/asterisk/extensions.conf
```
- **비교 방법**: `confbridge.conf`, `extensions.conf`, `rtp.conf`, `http.conf` 등 정적 파일은 repo 소스와 md5/내용 비교 가능. `pjsip.conf`는 template 치환 결과물이므로 **raw md5 비교 금지** — `pjsip show endpoint/transport/aor/contact` 런타임 출력과 template 항목을 구조적으로 대조(민감값 마스킹).

### 3.2 재현 + SDP/RTP 캡처 (필요 시)
```bash
docker exec kibal-dev-asterisk asterisk -rx "pjsip set logger on"
docker exec kibal-dev-asterisk asterisk -rx "rtp set debug on"
# 1101/1102/1103 순차 6000 입장, 10~20초 유지, 재협상(입/퇴장) 1회, 종료
# 캡처 저장 후 반드시:
docker exec kibal-dev-asterisk asterisk -rx "rtp set debug off"
docker exec kibal-dev-asterisk asterisk -rx "pjsip set logger off"
```
확인: INVITE/200 OK/ACK/re-INVITE SDP의 `m=audio` 존재, 포트/코덱, `a=sendrecv|sendonly|recvonly|inactive`, `m=video`와 동시 협상 상태. 통화 중 `pjsip show channelstats`, `core show channels verbose` 수집.

### 3.3 측정지표 및 분기

| 지표 | 정상 기준(초기) |
|------|------------------|
| 프로브/UI 원격 스트림 | 세션 합계 기준 audio 트랙/수신 확인(스트림 단위 로그 단독 판정 금지) |
| SDP | `m=audio` 존재 + 방향 `sendrecv`(회의 정책 범위) |
| RTP | `inbound-rtp/audio bytesReceived/packetsReceived` 증가, RTCP loss 목표 <2%(환경 보정) |
| 실청취 | 3자 상호 발화 시 양방향 가청 |

| 관측 | 판정 | 조치 |
|------|------|------|
| 프로브 정상 / UI 비정상(동일 조건) | H1 우선 | 클라이언트 렌더/스트림/세션 처리(F2), 서버 A/B 보류 |
| SDP `m=audio` 없음 | H2 유력 | ConfBridge/PJSIP 협상 조사, 소스 기반 수정 검토(F3/F4) |
| `m=audio` 있으나 `inactive/recvonly` | H2 유력 | 재협상/브리지/프로파일 조사 |
| `m=audio sendrecv`, RTP 증가, 트랙/재생 없음 | H1 유력 | 클라이언트 수정(F2) |
| `m=audio sendrecv`, RTP 0 | H4 유력 | ICE/DTLS/코덱/포트/RTP 경로 조사 |
| 중복 등록/계정 불일치 | H5 | 통제 후 재시험 |

## 4. 수정 지침

- **F1**: 최신 클라이언트/프로브 재검증(무변경) 결과를 먼저 확정.
- **F2**: 클라이언트가 오디오 스트림/트랙을 수신하나 UI/재생에서 누락되는 경우 수정.
- **F3/F4(서버)**: SDP 증거로 서버 원인 확정 시에만 수행. 변경은 `SmartCC_Kibal/server/asterisk/config/*` 소스 수정 + 재배포. `운영콘솔OPS`와 분리된 브랜치(권장 `fix/confbridge-remote-audio`) 사용.
- **`video_mode=none`**: 최종안 금지. 진단 최후수단으로만, 임시 적용 시 영상 중단 영향 고지·즉시 원복·증거 기록.
- **금지**: `pjsip.conf`/인증 속성 임의 삭제, `Answer()` 제거, 증거 없는 설정 변경, 활성 통화 중 무통보 restart, 디버그 off 누락.
