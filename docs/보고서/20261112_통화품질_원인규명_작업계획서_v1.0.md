## 1. 목표

1. `1102 → 1103` 발신 `404 Not Found`의 근본 원인을 서버 근거로 확정하고 재발 방지책을 적용한다.
2. A10(1201)이 ConfBridge에서 원격 영상을 수신하지 못하는 지점을 SDP/브리지/스트림 중에서 특정한다.
3. 클라이언트 코드 결함 2건(re-INVITE 옵션 누락, 원격 스트림 누적)을 수정한다.
4. 장시간 통화의 `freeze`/out-fps/손실 현상을 재분류하고 인코더 부하 가설을 검증한다.
5. **이전 분석의 오진 6건을 문서로 정정**한다(분석보고서 2장).

## 4. WBS — C → A → D → B

### C. A10(1201) 원격 영상 미표시 【최우선】

| ID | 작업 | 산출물 / 완료 기준 |
|----|------|-------------------|
| C0 | 현행 채널 스냅샷 고정 | `core show channels`, `confbridge list 6100`, `core show channel PJSIP/1201-*` 저장 |
| C1 | 1201 SDP·스트림 확인 | `video-1 State: sendrecv / Formats: (h264)` 확인 완료. `NativeFormats (g722\|h264)`, `max_video_streams=1` 기록 |
| C2 | `kibal_bridge_ft` follow_talker 동작 계측 | 발화자 전환 시 A10 수신 `videoBytes` 증가 여부. `confbridge show profile bridge kibal_bridge_ft` |
| C3 | 1103→1201 방향 대조 | `1103.log` `in=1920x1080@30fps` 정상 수신 중 → **1103이 받는 영상은 정상**임을 근거로 방향 특정 |
| C4 | 원인 확정 | ① 발화자 영상 미전달 / ② A10 자기 영상 루프백 / ③ `max_video_streams=1` 제약 중 판정 |
| C5 | 조치 | 브리지 프로파일·`video_mode`·`max_video_streams` 조정안을 ADR로 기록 후 적용 |

**합격 기준**: A10 화면에 1103(또는 발화자) 영상이 표시되고, `1201` 채널의 inbound video `bytesReceived`가 30초간 단조 증가.

### A. `1102 → 1103` 404 【2순위】

| ID | 작업 | 산출물 / 완료 기준 |
|----|------|-------------------|
| A0 | 근거 고정 | `messages:1261-1265`(16:05:02/19 UTC) + `security:2200-2203`(AccountID=1102, SessionID=tbfvf26b…/tbfvf7ln…) 교차표 |
| A1 | UTC↔KST 매핑 검증 | 16:05:02 UTC = 01:05:02 KST. 호 ID 앞 20자 일치 확인 |
| A2 | AOR 상태 재현 | `pjsip set logger on` 후 1103 로그인/로그아웃 반복 → `remove_existing=yes` contact 공백 구간 실측 |
| A3 | 설정 개선 | `remove_existing=no` / `qualify_frequency` / `default_expiration` 조합 검토. 서버 ADR-004로 결정 |
| A4 | 재발 방지 | 클라이언트 REGISTER 갱신 주기·WS 재연결 시 재등록 보장 점검 |
| A5 | 회귀 테스트 | 1103 미등록 상태에서 발신 → 명확한 오류 안내, 등록 후 발신 → 200 OK |

**합격 기준**: 1103 등록 직후·갱신 중·만료 직후 3시점 모두에서 발신 성공 또는 의도된 명시적 실패(404 아님).

### D. 클라이언트 코드 결함 2건 【3순위】

| ID | 작업 | 대상 | 완료 기준 |
|----|------|------|-----------|
| D1 | re-INVITE 수락에 ADR-006 옵션 병합 | `sip_client.dart:624-638` `_acceptReinvite`가 `accept({})` 전달 | 재협상 후에도 transceiver video `recvonly` 유지, `SIP transceivers` 로그에 방향 기록 |
| D2 | 통화 중 누적 원격 스트림 정리 | `media_manager.dart:377-410, 575-590` | re-INVITE 3회 후 `_remoteSessions` 스트림 수가 실제 트랙 수와 일치, `session(video=…)`이 누적되지 않음 |
| D3 | 빌드 버전 불일치 해소 | 제공 로그에 `SIP accept video=...`(`:358`) 부재 | `1102.meta.json` app_version 로그 기준선 확정 |
| D4 | 단위·통합 테스트 | `macos-client/test/` | `flutter analyze` 0건, `flutter test` 전 통과, 릴리스 DMG 빌드 |

**합격 기준**: D1·D2 수정 후 3자 6000 회의에서 `videoTracks`=실제 참가자 영상 수, 타일 `inactive` 0.

### B. 장시간 통화 품질 저하 【4순위】

| ID | 작업 | 완료 기준 |
|----|------|-----------|
| B0 | 현상 재분류 | 손실 버스트 2회(`01:37:33`, `01:54:33`) / out-fps 붕괴(`02:44–02:46`) / 첫 키프레임 대기(`01:11:03~28`) 3현상 분리 문서화 |
| B1 | 인코더 부하 계측 | `02:44–02:46` 구간 in 정상(`decodedFrames+900`, `videoKB≈9185`) vs out `12~16fps`, `limit=none` 재현 + CPU/인코더 사용률 수집 |
| B2 | D2 선행 효과 검증 | 누적 스트림 정리 후 동일 1시간 통화에서 out-fps 붕괴 재발 여부 |
| B3 | 해상도 하향 원인 | `01:15:03` `1280x720→640x480`, `qualityLimitationReason=none` → 앱/협상 측 재설정 경로 특정 |
| B4 | 손실 대응 | `nack=0`, `pli` 최대 4 정상 여부 판정(손실 0 구간이므로 NACK 미발생이 정상임을 근거화) |

**합격 기준**: 60분 통화에서 out fps ≥ 25 유지, `session(video)` 누적 없음, 손실 버스트 발생 시 `pli`/`keyframes` 회복 로그 확인.

## 7. 리스크·롤백·보안

- 서버 설정(`pjsip.conf.template`, `confbridge.conf`) 변경은 **반드시 ADR 기록 → DEV 적용 → 통화 회귀 테스트** 순서로 한다. 런타임 `/run/asterisk/*.conf` 직접 수정은 휘발성이므로 금지.
- `pjsip set logger on`은 진단 후 **반드시 off**로 되돌린다(`full` 로그 급증).
- 클라이언트 코드 수정은 `macos-client/`에서 `flutter analyze`·`flutter test` 통과 후 릴리스 빌드한다.
- A10 관리자 비밀번호, `X-Client-Key`, SIP 비밀번호는 문서·로그·커밋에 기록하지 않는다. 증거 캡처 시 마스킹한다.
- A10 모드 변경(공장 초기화 동반)은 금지한다.
- `git-sync.sh`는 `git add -A`를 사용하므로 실행 전 `git status --short`로 포함 파일을 확인한다. NAS(`dev`/`prd`)는 현재 대역에서 미도달 → SKIP 예상, GitHub(`origin`)만 동기화된다.
