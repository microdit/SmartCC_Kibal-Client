## 1. 목표

1. **F1**: `1103 → 1201` 1:1 발신 offer에도 H.264 코덱 정책을 적용해 A10 원격 영상 수신을 복구한다.
2. **F2**: v0.0.23 A4(WS 재연결 시 재REGISTER)를 **롤백**해 `1101` 등록 루프/다자간 튕김을 제거한다.
3. **G3**: `6100` ConfBridge에 참가자 이벤트를 활성화해 참석 카드 갱신 신호를 확보한다.
4. **G2(보류)**: 단독 입장용 상시 영상 소스는 서버 옵션 부재로 **이번 범위에서 제외**, 설계서에 대안으로 기록한다.

> **원칙**: 문서(계획서·테스트 방법·로그·ADR)를 먼저 완성하고 커밋·동기화한 뒤 코드·설정을 변경한다.

## 3. F1 정정 — 타깃 전달 경로 (중요)

선행 분석보고서 v1.0의 F1은 `_currentSession?.remoteParty` 폴백을 제안했으나 **부정확**하다.

```
call(target)                         sip_client.dart
  ├─ _helper.call(target, ...)      ← 이 내부에서 localSdpTransformer(offer) 호출
  └─ _currentSession = SipSession(target)   :313  ← offer 이후에 설정됨
```

즉 offer 생성 시점에는 `remote_identity`뿐 아니라 **`_currentSession`도 null**이다. 따라서 **`call()` 진입 시 타깃을 별도 필드에 먼저 저장**해야 한다.

| 변경 | 위치 |
|------|------|
| `String? _pendingCallTarget;` 필드 추가 | `sip_client.dart` 필드 영역(`:84` 근처) |
| `_pendingCallTarget = target;` | `call()`의 `_helper.call()` 직전(`:303` 직전) |
| `final target = session.remote_identity?.uri?.user ?? _pendingCallTarget;` | `localSdpTransformer`(`:163`) |
| `_pendingCallTarget = null;` | `_cleanupSession()`(`:1055-1059`) |

`sdp_codec.dart:11`의 `12xx → h264First`는 이미 구현돼 있으므로 **변경 불필요**. `videoPolicyFor()`/`applyVideoCodecPolicy()`도 그대로 쓴다.

기대 로그: `SIP codec policy target=1201 type=offer video=h264First`.
기대 서버: `core show channel PJSIP/1103-*`의 `NativeFormats`/`video-1 Formats`가 `(h264)`로 정합.

## 4. F2 — A4 롤백

| 제거 대상 | 위치 |
|-----------|------|
| `bool _needsReRegister = false;` | 필드 영역 |
| `if (_needsReRegister) { ... unawaited(register()); }` + `SIP transport reconnected -> re-REGISTER` 로그 | `transportStateChanged` `CONNECTED` |
| `_needsReRegister = true;` | `transportStateChanged` `DISCONNECTED` |

`DISCONNECTED`의 로그·`_setState(disconnected)`·`_completeTransport(false)`는 **유지**한다(진단 로그 보존).

**근거**: v0.0.22 1103은 A4 없이 `23:52:02 disconnected → 23:52:11 registered`로 sip_ua 자체 재연결만 복구. A5 회귀 합격은 서버 A3(`remove_existing=no`)만으로 달성(ADR-004 Accepted). A4는 불필요 + 회귀 유발.

> **유지**: `_receiveOnlyVideo`(D1/ADR-008), `_needsReRegister`와 무관한 `_acceptReinvite` 옵션 병합, D2 스트림 정리.

## 5. G3 — ConfBridge 참가자 이벤트

`server/asterisk/config/confbridge.conf`의 `[kibal_bridge_ft]`에 추가:

```ini
enable_events=yes
```

현재 `confbridge show profile bridge kibal_bridge_ft`는 `Enable Events: no`. 참가자 입·퇴장 이벤트가 없어 카드 UI가 갱신되지 않는다. `6000`(`kibal_bridge`)은 필요 시 동일 적용(이번엔 6100만).

**반영**: `config`가 `/opt/kibal/config:ro` 마운트 + `entrypoint.sh`가 시작마다 전개 → **컨테이너 재생성 필요**(`docker compose -f compose.yaml up -d --force-recreate asterisk`). 재생성 시 진행 중 통화는 종료된다(사용자 승인 범위).

### G2를 제외하는 이유

- `confbridge show profile bridge` 출력에 **`Video Source` 항목이 없다** → Asterisk 22의 bridge profile에 `video_source` 옵션이 없음. 임의 키를 넣으면 unknown option 경고만 난다.
- `ConfbridgeSetSingleVideoSrc`는 *"all other participants"* 라 **자기 자신만 있는 회의에는 적용 불가**. 상시 소스를 만들려면 **더미 영상 참가자 채널**을 6100에 상시 입장시켜야 하는데, 이는 별도 미디어 소스(정지영상/파일) 설계와 실기 검증이 필요한 독립 과제다.
- → [[wiki/02_Design/20261113_발신타깃_설계서_v1.0]] 4장에 대안으로 기록하고, 이번에는 **G1(2번째 참가자 입장 검증)** 과 **G3** 만 적용한다. 단독 입장 스피너는 "정상 대기"로 문서화한다.

## 8. 리스크·롤백·보안

- F1의 `_pendingCallTarget`은 통화 종료 시 반드시 초기화(`_cleanupSession`). 미초기화 시 다음 통화에 이전 타깃이 남아 잘못된 코덱 정책 적용 위험.
- F2 롤백 후 A4 로그가 사라지므로, 재연결 진단은 기존 `SIP transport disconnected (cause: …)` 로그로 한다.
- G3 컨테이너 재생성은 **진행 중 통화를 종료**시킨다. 재생성 전 `core show channels` 확인, 후 `docker ps` healthy + `verify-sip-auth.py` PASS 확인.
- `pjsip set logger`는 사용하지 않는다(`full` 급증 방지).
- 비밀번호·`X-Client-Key`는 문서·로그·커밋에 기록하지 않는다. `confbridge.conf`에는 비밀값 없음.
- `git-sync.sh`는 `git add -A` → 실행 전 `git status --short` 확인. NAS 미도달은 SKIP 예상, `origin`만 동기화.
- 롤백: F1/F2는 `git revert` 또는 이전 커밋으로 복원, G3는 `enable_events` 줄 제거 후 재생성.
