# SmartCC_Kibal 외부망 접근 (OPS·Asterisk·SIP·WS) 실행 계획 (v1.0)

> 작성일: 2026-11-14 / 대상: iMac `AtomOppa` (192.168.0.7) + Asterisk DEV `192.168.0.3`
> 네트워크: KT망 — IPTime1(`192.168.11.1`, NAS `192.168.11.2`) ↔ IPTime2(`192.168.0.1`, DEV/iMac `192.168.0.x`)
> 공인 IP: `220.121.38.217` (동적) / NAS SSH 포트포워딩(4949→192.168.11.2)은 IPTime1에 이미 설정됨.
> **기존 DDNS 활용**: `appletreeda.synology.me` (Synology) → 공인 IP, `:50000` → NAS DSM `192.168.11.2:5000` 포워딩 확인됨. 신규 DDNS 불필요, 이 호스트명을 Asterisk 외부주소로 재사용.

---

## 0. 토폴로지 (확정)

```
[인터넷/KT] ── [IPTime1 192.168.11.1] ── [IPTime2 192.168.0.1 (WAN=192.168.11.x)]
                       │                              │
                       └── NAS 192.168.11.2 (4949)    └── Asterisk DEV 192.168.0.3
                                                          iMac 192.168.0.7
```

- IPTime1 = 메인 라우터(공인 IP 보유), IPTime2 = 하위 라우터(이중 NAT)
- 따라서 외부 → `192.168.0.3` 은 **IPTime1 → IPTime2 → 단말** 이중 포트포워딩 필요
- IPTime2의 WAN IP는 IPTime1 DHCP로 받음 → **DHCP 예약 필수**(예약 없으면 규칙이 깨짐)

## 1. 노출 포트 매트릭스

| 서비스 | 포트/프로토콜 | 대상 | 비고 |
|--------|--------------|------|------|
| OPS 콘솔 | `8091/TCP` | `192.168.0.3` | 비밀번호+CSRF, docker-proxy(exec) 노출 위험 → VPN 권장 |
| SIP WebSocket | `8088/TCP` | `192.168.0.3` | 클라이언트 신호 (`ws://`) |
| SIP UDP (선택) | `5060/UDP` | `192.168.0.3` | 이 클라이언트는 WS만 사용, 외부 UDP SIP 단말용 |
| RTP 미디어 | `10000-10200/UDP` | `192.168.0.3` | 201포트 범위 포워딩 |

## 2. 안전성 권고

- **OPS(8091)는 가급적 VPN(WireGuard/Tailscale)으로만 접근**, 포트포워딩은 SIP 통화용(8088+RTP)에 한정.
- 불가피하게 OPS를 열 경우: 강한 비밀번호, IP 화이트리스트(가능 시), 실패 시도 제한.
- 공인 IP가 동적 → **DDNS 필수** (IPTime2 DDNS 또는 DuckDNS 등). 클라이언트는 DDNS 호스트명 사용.

## 3. 실행 절차

### Phase A — IPTime2 (하위 라우터) 포트포워딩
관리페이지 `192.168.0.1` → 고급설정 → NAT/포트포워딩:
- `TCP 8088` → `192.168.0.3:8088`
- `TCP 8091` → `192.168.0.3:8091` (OPS 외부노출 시)
- `UDP 5060` → `192.168.0.3:5060` (선택)
- `UDP 10000-10200` → `192.168.0.3:10000-10200`

### Phase B — IPTime1 (메인 라우터) 포트포워딩
관리페이지 `192.168.11.1` → NAT/포트포워딩:
- IPTime2의 WAN IP(= IPTime1 DHCP 예약값)를 확인 후:
- `TCP 8088` → `<IPTime2_WAN_IP>:8088`
- `TCP 8091` → `<IPTime2_WAN_IP>:8091`
- `UDP 5060` → `<IPTime2_WAN_IP>:5060` (선택)
- `UDP 10000-10200` → `<IPTime2_WAN_IP>:10000-10200`

### Phase C — IPTime2 WAN IP 고정 (DHCP 예약)
IPTime1 관리페이지 → DHCP 서버 → IPTime2 MAC 주소에 `192.168.11.x` 고정 할당.

### Phase D — DDNS (기존 Synology DDNS 재사용)
신규 DDNS 불필요. `appletreeda.synology.me` (Synology DDNS, 공인 IP 자동 갱신) 재사용.
- Asterisk 외부주소로 `appletreeda.synology.me` 사용 → `EXTERNAL_IP=appletreeda.synology.me`
- NAS DSM 접근: `appletreeda.synology.me:50000` → `192.168.11.2:5000` (이미 동작 중)
- `doubletree-house.quickconnect.to` → Synology QuickConnect (DSM 릴레이, 포트포워딩 불필요) — **DSM 전용**, SIP/RTP/OPS 임의 포트에는 사용 불가 → Asterisk 외부접근에는 DDNS(`appletreeda.synology.me`) 사용
- 클라이언트 외부 접속: `ws://appletreeda.synology.me:8088/ws`

### Phase E — Asterisk 서버 NAT 설정 (SmartCC_Kibal)
1. `deploy/dev/.env`에 `EXTERNAL_IP=appletreeda.synology.me` 설정 (또는 `--update` 후 수동 추가)
2. `pjsip.conf.template`의 `external_signaling_address`/`external_media_address`가 `${EXTERNAL_IP}`로 치환됨 (이미 반영)
3. 컨테이너 재생성: `cd deploy/dev && ./up.sh` (실통화 종료 후)
4. 검증: `asterisk -rx 'pjsip show transports'` 및 SDP에 공인주소 확인

### Phase F — 클라이언트 설정
- 외부 사용 시 로그인 화면 서버 입력: `ws://<DDNS>:8088/ws`
- 또는 OPS `/api/client/config` 갱신 경로 활용 (`server_config.dart`)

### Phase G — 검증
```bash
# 외부망(휴대폰 테더링)에서
nc -zv appletreeda.synology.me 8088
nc -zv -u <DDNS> 10000
# 앱 등록 → 1:1/3자 통화 → audioBytes>0, recovered=true
```

## 4. 변경된 서버 파일 (이미 반영)

- `server/asterisk/config/pjsip.conf.template` — `external_signaling_address`/`external_media_address=${EXTERNAL_IP}` (transport-udp/ws)
- `server/asterisk/entrypoint.sh` — `EXTERNAL_IP` envsubst 추가, 기본값 빈 문자열
- `deploy/dev/.env.example` — `EXTERNAL_IP=` (선택)
- `deploy/dev/init-env.sh` — `EXTERNAL_IP` 자동 추가

## 5. 보안/주의

- `docker-proxy`(OPS)가 컨테이너 exec 권한 보유 → **8091 외부 노출 시 비밀번호 강화 + VPN 병행 권장**
- RTP 10000-10200 전부 포워딩 → 방화벽에서 이 범위만 허용
- `EXTERNAL_IP` 미설정(빈 값) 시 Asterisk는 내부망 모드로 동작 (기존 동작 유지)
- 실통화 중 컨테이너 재생성 금지 (통화 종료 후)

## 6. 차단/미완 사항

- IPTime2 WAN IP 실제 값 미확인 → Phase B/C에서 확인 필요
- DDNS는 `appletreeda.synology.me` (Synology) 기존 사용 → 신규 불필요
- 외부망 실기검증 미수행 → Phase G
- NAS(192.168.11.2) SSH/SMB는 IPTime1 포워딩(4949)만으로 접근 가능하나 iMac(192.168.0.x)에서 직접 접근 불가 — 필요 시 IPTime2에도 4949 포워딩 추가하거나 VPN 사용
