## 1. 목표

1. A10을 Kibal에 연결하는 **현실적 경로를 확정**한다.
   - 우선: USB-C + Kibal macOS App(B′) — v0.0.21 장치 선택
   - 차선: SIP 1201 + 6100 `follow_talker` — v0.0.22 H.264
2. P1/P2 빌드의 **실기 합격/불합격 판정**과 근거를 남긴다.
3. 실패 시 원인을 케이블·포트·macOS·A10 상태·서버 설정으로 분리한다.

## 3. WBS

| 단계 | 작업 | R/A | 산출물·완료 기준 |
|------|------|-----|------------------|
| S0 | A10/서버/Mac 현재 상태와 증거 고정 | 테스트 | summary, contacts, talking, USB/오디오 캡처 |
| U1 | USB-C 케이블·포트 교체 | 테스트/현장 | USB-C→USB-C, Mac TB3 직결, 허브 제거 |
| U2 | macOS 열거·승인 확인 | 테스트 | System Information USB에 Yealink 표시, 오디오 장치 표시 |
| U3 | Windows 교차 확인 | 테스트 | Windows에서 Yealink 열거 여부 기록 |
| U4 | P1 실기(v0.0.21) | 클라이언트/테스트 | 장치 선택 저장, 1:1·6000 영상/음성 합격 |
| S1 | A10 idle/talking 해소 | 테스트 | `/api/common/info/status/talking` = `false` |
| S2 | T0-C SIP 저장·등록 | 테스트 | `writeconfig` 200, A10 `Registered`, 서버 `1201 Avail` |
| S3 | P2 실기(v0.0.22) | 클라이언트/서버 | 1201↔1101 1:1, 6100 발언자 화면, H.264 확인 |
| D1 | Go/No-Go 판정 | 담당자 | USB/SIP/보류 중 하나로 결정, 보고서 v1.1 |

### 3.1 권장 실행 순서

1. **S0 → U1 → U2 → U3**로 USB 링크를 먼저 판정한다.
2. USB가 열거되면 **U4(P1)**를 완료한다. SIP는 보조 경로로 남긴다.
3. USB가 계속 실패하면 USB-C를 분리하고 **S1 → S2 → S3**로 SIP T0-C를 재시도한다.
4. 둘 다 실패하면 D1에서 하드웨어/케이블/펌웨어 에스컬레이션으로 종료한다.

## 4. 테스트 케이스·합격 기준

### 4.1 USB B′ / P1

| ID | 시나리오 | 합격 기준 |
|----|----------|-----------|
| U-T1 | USB-C 연결 | Mac `System Information > USB`에 `Yealink Room Camera`/`Room Audio` 표시 |
| U-T2 | A10 BYOD 화면 | `No sharing signal`은 화면 공유 신호 기준. P1 필수 조건은 아니며, 카메라/오디오는 U-T1 열거로 판정 |
| U-T3 | 오디오 | Mac 입력/출력에 Yealink Room Audio 표시, 마이크/스피커 동작 |
| U-T4 | v0.0.21 장치 선택 | 장치 설정에 Yealink 추천 표시, 저장 후 통화에 자동 적용 |
| U-T5 | 1:1 영상 | A10 카메라 영상이 상대 앱에 표시, 상대 영상이 A10/앱에 표시 |
| U-T6 | 6000 3자 | A10 포함 3자에서 A10 영상/음성 정상, 앱 크래시 없음 |

### 4.2 SIP T0-C / P2

| ID | 시나리오 | 합격 기준 |
|----|----------|-----------|
| S-T1 | idle 확인 | `talking=false` |
| S-T2 | SIP 저장 | `POST /api/inner/writeconfig` 200, A10 `Registered` |
| S-T3 | 서버 등록 | `pjsip show contacts`에 `1201 Avail` |
| S-T4 | 1:1 | `1201 ↔ 1101` 양방향 음성/영상, SDP H.264 |
| S-T5 | 6100 | `follow_talker` 발언자 전환, 1201+App 영상/음성 |
| S-T6 | 원복 | 실패 시 SIP 필드·스위치 원복, 서버 `1201` 미등록 확인 |

## 5. 실행 체크리스트

### 5.1 S0 — 상태 고정

```bash
# A10
A10_PASS='<관리자 비밀번호>' ./scripts/a10_admin.sh summary
A10_PASS='<관리자 비밀번호>' ./scripts/a10_admin.sh get '/api/account/status?type=sip&acc=1'
A10_PASS='<관리자 비밀번호>' ./scripts/a10_admin.sh get '/api/common/info/status/talking'

# 서버
docker exec kibal-dev-asterisk asterisk -rx 'pjsip show contacts'
docker exec kibal-dev-asterisk asterisk -rx 'pjsip show endpoint 1201'
docker exec kibal-dev-asterisk asterisk -rx 'confbridge show profile bridge kibal_bridge_ft'
```

### 5.2 U1~U2 — USB-C/macOS

- A10 동봉 또는 **USB 데이터 + DP Alt Mode 지원 USB-C→USB-C** 케이블 사용
- Mac Pro **상단 Thunderbolt 3 포트 직결**, 허브/도킹/USB-A 변환 제거
- `System Settings > Privacy & Security > Allow accessories to connect` 확인
- `System Information > USB` 및 아래 명령으로 확인

```bash
ioreg -p IOUSB -l -w 0 | grep -i -E 'yealink|room camera|room audio'
system_profiler SPAudioDataType | grep -i -A6 -E 'yealink|hd20k'
```

### 5.3 S1~S2 — T0-C SIP 저장

- USB-C를 분리하거나 A10을 재부팅해 `talking=false` 확인
- 웹 UI `SIP Account`에서 입력 후 **반드시 `Tab`/blur**로 Vue 모델 갱신
- `Confirm` 클릭 후 DevTools/Playwright에서 `POST /api/inner/writeconfig` 발생 확인
- `writeconfig`가 없으면 `talking` 재확인. `talking=true`면 저장하지 않는다.

> 자동화 스크립트를 사용할 경우 `A10_PASSWORD`, `A10_SIP_PASSWORD`는 환경변수로만 전달하고 화면/로그에 출력하지 않는다.

### 5.4 U4/S3 — 실기

- P1: v0.0.21 설치 → 미디어 테스트 → 장치 설정 → Yealink 저장 → 1:1/6000
- P2: v0.0.22 설치 → 1201 등록 → 1101 1:1 → 6100 `follow_talker`
- OPS 로그에서 `MEDIA device`, `SIP codec policy`, `SIP media summary` 확인

## 7. 리스크·롤백·보안

- 관리자 비밀번호는 **변경하지 않는다**. 문서·로그·커밋에 기록하지 않는다.
- A10 모드 변경은 공장 초기화를 동반하므로 금지한다.
- T0-C는 SIP Account 필드만 변경하는 가역 테스트다. 실패 시 입력값과 스위치를 원복한다.
- USB-C 분리 후에도 `talking=true`면 강제 저장하지 말고 재부팅 전후 상태를 기록한다.
- 증거 마스킹: Authorization, nonce, response, password, secret, token.
