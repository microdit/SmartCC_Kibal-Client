## 3. 원인 분석

### 3.1 [B1·확정] 6000 회의가 1:1 통화 화면으로 열림 — 참가자 선택 불가 (S1)

**근거(코드)**
- 다이얼러에서 어떤 번호를 걸든 `context.push('/call')` — `lib/src/ui/dialer/dialer_screen.dart:517`
- 수신 수락도 `_router.push('/call')` — `lib/app.dart:122`, `lib/src/ui/main_view.dart:98`
- `/call` 화면은 1:1용으로 원격 영상을 **`remoteStreams.first` 하나만** 중앙에 그림 — `lib/src/ui/call/call_screen.dart:154-172`
- v0.0.11에서 구현한 **큰 화면 + 참가자 선택 칩 UI는 `ConferenceView`(`/conference`, 회의 탭)에만** 존재. 6000을 다이얼러로 걸면 이 화면을 거치지 않음

**결과**: 사용자 보고 "중앙 고정 1개, 1102/1103 선택 불가"와 정확히 일치.

### 3.2 [B2·확정] 수신 통화 수락 시 예외 2건 — 1101→1103 직접 통화 실패

OPS 서버 수집 1103 로그(17:33:59):

```
SIP accept <- 1101 voiceOnly=true
ERROR FlutterError: Null check operator used on a null value
  at Navigator.of (navigator.dart:2967)
  #1 _KibalAppState._handleIncomingCall (app.dart:80)
ERROR UnhandledError: Concurrent modification during iteration: Instance(length:0) of '_GrowableList'.
  at ListIterator.moveNext
  #1 RTCSession.answer (sip_ua/src/rtc_session.dart:565)
  #3 KibalSipClient.accept (sip_client.dart:326)
```

| 예외 | 원인 |
|------|------|
| `Navigator.of(context, rootNavigator: true)` Null | `_KibalAppState`의 `context`는 `MaterialApp.router` **위**에 있어 Navigator가 없음. 이미 확보한 `_rootNavigatorKey.currentState`를 써야 함 (`app.dart:80`) |
| Concurrent modification | `voiceOnly`(video=false) 수락 시 `mediaStream.getVideoTracks()`가 반환한 **내부 리스트를 순회하며 `removeTrack`** → 순회 중 수정 (`rtc_session.dart:557-563`, 오디오 분기 동일) |

**결과**: 1103 화면은 수락된 듯 보이나 answer가 완료되지 않음 → 1101은 60초 대기 후 `603 Decline`(17:34:55), 1103은 `487 Canceled`.

### 3.3 [B3·확정] re-INVITE마다 원격 영상 트랙 누적 (S2·S3 일부)

- 1101 `sessionVideo` 2 → 5 → 9 로 증가(17:25 → 17:32 → 17:33), 참가자는 2명뿐
- ConfBridge SFU는 참가자 변동/재협상마다 새 m-line/트랙을 추가하고, 앱은 `_remoteSessions`에 **새 스트림을 계속 추가만** 함
- v0.0.11의 "최신 3개만 표시"는 화면 노출만 줄였을 뿐, **실제 렌더 대상이 죽은 트랙일 수 있고** 메모리/렌더러가 누적됨
- 근본 해결: 재협상 후 `RTCPeerConnection.getReceivers()` 기준으로 **현재 유효한 트랙만 유지**

### 3.4 [N1·확정] 1102·1103 네트워크 품질 불량 — 음성/영상 단절, ICE 실패 (S2·S3·S4)
