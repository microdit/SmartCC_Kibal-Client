## 2. 결함 카탈로그 (로그 근거 → 원인 → 해결)

### D1 — UDP/TCP 전송선택 시 등록 폭주 (P0, 클라이언트 수정)
```
loginPressed transport=udp → SIP op=init ws=ws://192.168.11.39:5060/ws
→ Connection refused × 다수 (1101, 1103 모두)
```
- 원인: (코드 확인) `_webSocketUrl()`은 **항상 `ws://`** 생성, `UaSettings..transportType=TransportType.WS` 하드코딩.
  `SipConfig.udp()`는 wsServer=null → `ws://domain:5060/ws` 조합. 5060은 SIP 포트라 WS 헨드셰이크 거절. sip_ua는 WS(및 TCP fallback)만 지원하지만 UI에 UDP/TCP 옵션 노출.
- 해결(수정됨, v0.0.3): (1) 로그인 화면 UDP/TCP 세그먼트 제거, WS 고정 + 안내문 표시.
  (2) `_webSocketUrl()`은 wsServer 미지정 시 **8088**로 포화(5060 사라지고 기본 ws 포트로 확정), port=5060 등 비 WS 포트 시 WARN 로깅.

### D2 — 회의 원격 음성 유실 (`remoteStreamAdded video=1 audio=0`) (P0, 클라이언트 수정)
```
13:00:55 remoteStreamAdded video=1 audio=0
13:00:55 remoteStreamAdded video=1 audio=0 (동일 session 2회)
```
- 원인: (v0.0.2 코드 확인) `_remoteStreams`가 sessionId를 **단일 스트림**에만 매핑.
  영상 스트림이 먼저 저장되면 나중에 오는 **음성 전용 스트림을 무시** (chosen=prev).
  그 결과 회의에서 상대 음성이 재확인되지 않음.
- 해결(수정됨, v0.0.3): (1) 세션: 스트림 목록(`_remoteSessions: sessionId → List<MediaStream>`) 구조로 변경.
  (2) 렌더러는 세션의 영상 보유 스트림에만 바인딩, 음성은 모두 보관(네이티브 자동재생).
  (3) 영상 없는 스트림 폐기 제거 — addTrack 방식은 nil 크래시(D8)와 교환되므로 방식만 헤제.
- 서버협작(가설 B) Asterisk ConfBridge 영상 브리지 SDP가 audio를 recvonly로 절삭하는지
  `asterisk -rx "pjsip show endpoint 6000"` 및 `confbridge.conf` 영상 모드 점검.

### D3 — 계정 혼선 (iMac이 1102로 등록) → 1:1 통화 실패 (P0, 절차/UX 개선)
```
quickConnectFilled 1103 → quickConnectFilled 1102 (iMac)
loginPressed username=1102 (반복)
→ 1102→1103 : callTerminated FAILED 404 Not Found
→ 1103(=1102의 iMac)→1102 : incoming/outgoing 교차, 408 No Answer → 603 Decline
```
- 원인: 1102 계정이 MacBook과 iMac에 동시 등록, **1103은 등록 안 됨**. quickConnect가 필드만 채우기 때문에 사용자가 어느 계정인지 인지하기 어려움.
- 해결: (v0.0.3 반영 권장사항 — 불가 불가 후속작업) quickConnect 즉시 1회 힌트 토스트(계정명+device) 표시, 동일 계정 중복 등록 시 서버측 경고 옵션.
- 힌트: quickConnect가 이미 `quickConnectFilled` EVENT 로그로 발신하고 있어 **로그로 즉시 확인 가능**.

### D4 — 회의 원격 영상 placeholder (P0, 클라이언트 수정)
```
원격 영상 안보임 (1102 및 1103) — 대신 "아이콘"만 표시
```
- 원인: `_bindRendererForCount(index)`는 taxa 재바인딩만 수행, 세션 삭제/추가의 일부 순서에서
  렌더러와 스트림 불일치 (`srcObject` 미설정 상태 유지). CallScreen에서는 `renderer.srcObject=stream`을 매 rebuild에 재설정하지만 세션 인덱스 배당 불명확.
- 해결(수정됨, v0.0.3): `_rebindAllRemoteRenderers()` — 스트림 추가/제거 시마다 전체 세션→렌더러 재매핑.
  영상 보유 스트림에만 srcObject 배정, 세션 축소 시 잔여 렌더러 해제.

### D5 — "통화가 종료되었습니다" 다이얼로그 자동닫힘/유지 불일치 + 셀프 영상 누수 (P0, 클라이언트 수정)
```
1102: 다이얼로그 뜨는 즉시 자동 종료
1103: 다이얼로그 유지 + 셀프 카메라 계속 스트리밍
```
- 원인: `_handleSipStateChange`에서 `state notifyListeners`가 중복 발생하며 다이얼로그 재트리거/해제 경쟁, `isInCall`이 PROGRESS(true)→FAILED(false) 전환 타이밍불확정. 원격 종료 시 로컬 트랙 정리(terminate 시) 미수행.
- 해결(수정됨, v0.0.3): (1) `_endedDialogShown` 가드로 종료 처리 1회만 수행, 다이얼로그는 "확인" 버튼까지 유지. (2) 원격 종료 검출 시 `releaseLocalMedia()` + `removeAllRemoteStreams()` 명시 정리 → 셀프 영상 누수 방지.

### D6 — 미디어 테스트 디바이스명 한글 깨짐 + `deviceId=default` (P1)
```
1102: '디바이스 선택' 등록장치명 한글 깨져서 보임
micDeviceSelected deviceId=default
```
- 원인: flutter_webrtc가 device label에 대해 시스템 인코딩을 여러 경로로 전달, macOS 텍스처에 따라 깨짐.
  'default'는 Flutter(sip_ua 부속)의 특수 항목이고 exact deviceId로 유효하지 않음.
- 해결: 라벨이 비어있거나 깨진 경우 fallback 표시('기본 마이크/카메라'), 'default'는 exact 매핑 제거(기본장치 로직 사용). (v0.0.3에서 일부 반영 여지 — R1 후속)

### D7 — identity IP가 서버 IP로 표시 (`ip=192.168.11.39`, Mac Pro) (P2)
```
usr=1101@... host=MacPro ip=192.168.11.39 (실 서버가 아닌 VPN/브리지 우치)
```
- 원인: `NetworkInterface.list()`가 docker/VM 브리지 NIC를 먼저 반출.
- 해결 (후속): 우선순위 인터페이스(en0/en1)를 먼저 검토, 다중 IP일 경우 우선 순위 조정.

### D8 — 등록 시점 간헐 WS 헨드셰이크 실패 (P1, 서버 측)
```
Connection refused → `HttpException: Connection closed before full header…` → 재연결 후 성공
```
- 원인(잔여): 서버측 wss/ws 리버스프록시 · Asterisk ws 핸드셰이크 타이밍. (서버 S2 재성사)
- 해결: 서버측 Nginx/iptables ws 타임아웃 및 Asterisk WS `maxexpiry` 자문. 클라이언트는 자동 재연결로 복구.

## 5. 재검증 절차 (v0.0.3)

1. **D1**: 로그인 화면에서 WS 고정 시 표시 내용 확인 → 등록이 ws://…:8088/ws 로만 진행되는지
2. **D2**: 3기기 회의 6000 — `remoteStreamAdded video=1 audio=1`이 나타나는지 서버 SDP 확인 및 서버측 `confbridge audio` 검증
3. **D4**: 회이 상캠에서 원격 영상 타일이 렌더러에 연결되는지 (placeholder 없이) 확인
4. **D5**: 통화 종료 → 창이 닫히지 않고 종료 버튼까지 유지, 셀프 영상이 즉시 해제되는지
5. **D3**: quickConnect 사용 후 실입 업적(계정이 어느 기기/계정인지) 재확인 — 이번 세션 사용자 안내 필요

## 6. 결론

- **클라이언트 P0 3건(D1/D2·D4/D5) 모두 v0.0.3에서 수정 및 배포 완료**
