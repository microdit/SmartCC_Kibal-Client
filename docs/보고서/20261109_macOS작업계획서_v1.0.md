## 1. 개요

### 1.1 배경

Web Client(React + SIP.js + WebRTC)와 Mobile Client(Flutter)를 개발·테스트하는 과정에서 다음 장애요소가 확인되었다.

1. **Web Client**: 브라우저 Secure Context 정책으로 **HTTPS 인증서 없이는 카메라/마이크 사용 불가**(localhost 예외). 외부망·타 IP와의 다자간 테스트가 제약된다.
2. **SIP 인증**: Asterisk PJSIP의 **SIP Digest(MD5)** 인증에서 `401 authentication loop`가 반복된다.
3. **iOS Native**: 시뮬레이터에서 앱 UI는 동작하지만, **SIP 플러그인 미구현으로 REGISTER가 동작하지 않는다**(3.4절 근거).

이에 따라 **플랫폼·권한·미디어 접근을 네이티브로 제어할 수 있는 macOS 앱을 먼저 완성**하여 SIP/미디어 파이프라인을 검증하고, 검증된 구조를 iOS → Windows → Android로 역적용한다.

### 1.2 목표

| 구분 | 목표 |
|------|------|
| **1차 목표 (P0)** | macOS에서 `flutter run -d macos` 빌드/실행 성공 |
| **2차 목표 (P0)** | macOS에서 Asterisk SIP `REGISTER` 성공 (`pjsip show contacts` 확인) |
| **3차 목표 (P0)** | 동일 네트워크에서 1:1 영상통화(양방향 영상/음성) 성공 |
| **4차 목표 (P1)** | macOS + Web/모바일 3자 회의실(ConfBridge SFU) 참여 |
| **5차 목표 (P2)** | 외부망/NAT(TURN) 및 패키징(DMG/ZIP), CI 자동화 |

### 1.3 범위

- **포함**: macOS 데스크톱 앱, SIP 등록/통화/회의, 카메라·마이크 권한, 앱 패키징 기초, 테스트 리포트.
- **제외(후속)**: iOS/Windows/Android 정식 빌드, LiveKit SFU 도입, 백그라운드 VoIP 수신(PushKit), App Store 배포·공증(Notarization), 관리자용 회의실 관리 기능.

- 방향성(웹 우선 → 네이티브 확장)은 유효하나, **현재 네이티브 코드의 SIP 의존성이 macOS/iOS에서 동작하지 않는 치명적 결함**이 확인되었다.

- LiveKit SFU 도입은 macOS 1:1/3자 검증 이후로 보류하고, 1차는 기존 Asterisk ConfBridge를 사용한다.

### 3.4 결정적 발견 — SIP 엔진 플랫폼 지원 불가

의존성 `flutter_sip: 0.0.8`의 플러그인 선언은 **Android 전용**이다.

```yaml
# ~/.pub-cache/hosted/pub.dev/flutter_sip-0.0.8/pubspec.yaml
plugin:
  platforms:
    android:
      package: com.eleadin.sip.flutter_sip
      pluginClass: FlutterSipPlugin
```

`.flutter-plugins-dependencies`에서도 macOS/iOS 등록 플러그인에 `flutter_sip`가 **없음**:

| 플랫폼 | 등록 플러그인 |
|--------|---------------|
| `ios` | `flutter_webrtc`, `path_provider_foundation`, `permission_handler_apple` |
| `macos` | `flutter_webrtc`, `path_provider_foundation` |
| `android` | `flutter_sip`, `flutter_webrtc`, `jni`, ... |

실제 iOS 실행 로그(`mobile/build.log`, `mobile/rebuild.log`):

```text
Unhandled Exception: MissingPluginException(No implementation found for method init on channel flutter_sip)
MissingPluginException(No implementation found for method listen on channel login_status_stream)
```

> **해석**: iOS 시뮬레이터에서 "동작 확인"된 것은 **UI 기동**이며, **SIP 등록/통화는 동작하지 않았다.** 동일 코드를 macOS로 가져오면 SIP는 100% 실패한다.

## 5. 기술 방향 결정

### 5.1 SIP 엔진 선택 — **플랫폼 독립 엔진으로 교체**

| 후보 | 플랫폼 | 전송 | 장점 | 단점 | 판정 |
|------|--------|------|------|------|------|
| `flutter_sip` 0.0.8 | Android only | UDP | 기존 코드 | macOS/iOS 불가 | ❌ macOS 사용 불가 |
| **`dart-sip-ua`** | 전체(순수 Dart) | UDP/TCP/TLS/WS/WSS | 단일 코드로 4개 OS, Digest 구현 | API 학습/재작성 필요 | ✅ **권장** |
| Native PJSIP FFI | 전체(빌드 필요) | 전체 | 성숙 | OS별 바이너리·빌드 복잡, 라이선스 | ⏸ 보류 |
| WebView 임베드(웹 클라이언트) | 전체 | WSS | 빠른 재사용 | 네이티브 권한/통합 제약 | ⏸ 차선 |

**결정**: SIP 계층을 `flutter_sip` → **`dart-sip-ua` 기반 어댑터**로 교체한다. 기존 `KibalSipClient` 공개 API(`init/register/unregister/call/accept/hangup`, `SipEvent`)를 유지하는 **어댑터 패턴**으로 UI/Provider 변경을 최소화한다.

### 5.2 미디어 / 서버 연동

| 계층 | 선택 |
|------|------|
| 미디어 | `flutter_webrtc ^0.11.7` 유지 (macOS 지원) |
| 권한 | `permission_handler` + macOS 시스템 권한 다이얼로그 |
| SIP 전송 | 1차: **UDP 5060**(기존 내선), 2차: **WSS 8088**(웹과 동일 경로) 비교 검증 |
| 영상회의 | 1차: Asterisk **ConfBridge SFU**, 2차(후속): LiveKit 검토 |
| NAT | STUN(기본) → TURN(coturn, P1) |

### 5.3 목표 아키텍처

```text
macOS Flutter App
├── UI (Desktop Layout: TitleBar + Sidebar + Content)
├── SipProvider / MediaProvider      (기존 유지)
├── SipEngineAdapter
│   ├── DartSipUaEngine  ← macOS/iOS/Windows/Android 공통 (신규)
│   └── FlutterSipEngine ← Android 레거시(필요 시)
├── MediaManager (flutter_webrtc)
└── Signaling: SIP(UDP/WSS) + ICE/STUN/TURN
                │
        Asterisk 22 LTS (PJSIP, ConfBridge SFU)
```

## 7. 상세 실행 지침 (P0)

### 7.1 macOS 프로젝트 재생성

```bash
cd macos-client
# 기존 lib/ 보존, macOS 플랫폼만 생성
flutter create --platforms=macos .
flutter pub get
flutter build macos --debug
```

- 생성 후 `macos/Runner.xcodeproj`, `macos/Podfile`, entitlements, Assets가 채워지는지 확인.
- 기존 `lib/`가 덮어써지지 않도록 **반드시 백업 후 실행**하거나, 신규 디렉터리 생성 후 `lib/`를 복사하는 방식을 병행한다.

### 7.2 권한·entitlements 체크리스트

| 파일 | 키/항목 |
|------|---------|
| `macos/Runner/Info.plist` | `NSCameraUsageDescription`, `NSMicrophoneUsageDescription` (기존 존재) |
| `DebugProfile.entitlements` / `Release.entitlements` | `com.apple.security.device.camera`, `com.apple.security.device.audio-input`, `com.apple.security.network.client` |
| Xcode Signing | Development Team / Hardened Runtime |
| 개발용 HTTP/WSS | 필요 시 ATS 예외 또는 WSS 사용 |

### 7.3 SIP 어댑터 골격 (설계 지침)

```dart
abstract class SipEngine {
  Future<bool> init(SipConfig config);
  Future<bool> register();
  Future<bool> unregister();
  Future<bool> call(String target);
  Future<bool> answer();
  Future<bool> hangup();
  Stream<SipEvent> get events;
}
```

- `DartSipUaEngine`을 기본 구현으로, `KibalSipClient`는 엔진을 주입받도록 리팩터링.
- Android 레거시가 필요하면 `FlutterSipEngine`을 조건부로 유지(플랫폼 분기).

### 7.4 SIP 401 인증 루프 진단 순서

1. 자격증명/도메인/realm 일치 확인 (`pjsip show auths`, `sip show domain`).
2. 계정 등록 상태 확인 (`pjsip show contacts`).
3. 네트워크 경로 확인 (`nc -zv <server> 5060`, `nc -zv <server> 8088`).
4. 서버 재로드(`pjsip reload`) 후 클라이언트 재등록.
5. 위 실패 시 WSS 경로로 전환해 비교 검증.

## 13. 결론

- macOS 우선 개발은 **타당**하다. 다만 현재 `macos-client/`는 **빌드 불가 상태의 소스 복사본**이며, 근본 원인은 **SIP 엔진이 Android 전용**이라는 점이다.
- 따라서 본 계획은 **"플랫폼 스캐폴딩 복구 → 코드 정비 → SIP 엔진 교체 → 등록/통화/회의 검증"** 순으로 P0를 재정렬한다.
- macOS에서 확보한 **플랫폼 독립 SIP/미디어 구조**를 iOS/Windows/Android에 그대로 역적용하는 것이 최종 목표다.
