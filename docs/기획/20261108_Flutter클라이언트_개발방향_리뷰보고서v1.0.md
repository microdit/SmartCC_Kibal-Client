## 1. 리뷰 개요

본 문서는 `20261108_Flutter클라이언트_개발방향_v1.0.md`(12,241 bytes)를 대상으로 다음을 검토했다.

1. **문서 내용의 정확성**: WebRTC 웹 클라이언트의 제약과 Flutter 전환의 효과에 대한 기술적 분석
2. **아키텍처 제안의 타당성**: 하이브리드 구조(Web 유지 + Flutter 전용 앱), SFU 기반 다자간 회의, SIP 분리에 대한 판단
3. **개발 로드맵의 적절성**: 4단계 접근 방법의 현실성
4. **현재 구현 상태와의 정합성**: 실제 프로젝트(`SmartCC_Kibal` + `SmartCC_Kibal-Client`)와 비교

### 리뷰 관점

> **"WebRTC 웹 클라이언트와는 별도의 건, Native App(Flutter) 개발 방향으로 진행하는 것이다. iOS 클라이언트는 이미 빌드해서 시뮬레이터로 동작시켰다. 지금은 Android 또는 iOS, Windows, macOS 버전을 만들어서 테스트하려고 한다."**


## 2. 문서 검토 결과 — 2.1 문서 구조 평가

| 섹션 | 평가 | 비고 |
|------|------|------|
| 1. WebRTC 웹 클라이언트 문제 정의 | ✅ 양호 | HTTPS·로컬호스트·MD5 인증 문제를 명확히 구분 |
| 2. Flutter 전환의 기술적 효과 | ✅ 양호 | 브라우저 제약 vs 네이티브 권한 차이를 정확히 설명 |
| 3. 외부망·다자간 회의 해결 방안 | ✅ 양호 | P2P/Mesh/SFU/MCU 비교와 SFU 권장 근거 명확 |
| 4. FTP(_HTPASSWD 등) — 없음 | — | 해당 섹션은 문서에서 발견되지 않음 (원문상 불필요) |
| 5. 권장 기술 구성 | ✅ 양호 | flutter_webrtc, dart-sip-ua, LiveKit, coturn 매핑 명확 |
| 6. 기존 SmartCC Kibal 변경 방안 | ✅ 양호 | 폐기 vs 하이브리드 선택 제안 상세 |
| 7. 개발 순서(단계별 로드맵) | ✅ 양호 | 4단계 접근, 우선순위 명확 |
| 8. 최종 판단 | ✅ 양호 | Flutter 전용 + LiveKit + Asterisk + Backend + Web 유지 |

**총평**: 문서의 기술적 분석과 아키텍처 제안은 대체로 정확하고, WebRTC 웹 클라이언트와 Flutter 네이티브 앱의 역할을 구분하는 접근이 합리적이다. 다만, **현재 실제 구현 상태**를 반영한 "현재 진행 중/미착수" 구분이 문서에 명시되어 있지 않아, 독자가 실제 프로젝트 상태와 문서의 권고를 바로 대조하기 어렵다.

### 2.2 기술적 분석 평가

| 평가 항목 | 문서 주장 | 검토 의견 |
|-----------|-----------|-----------|
| HTTPS 인증서 없이 카메라·마이크 사용 | Flutter 네이티브 앱은 브라우저 Secure Context 제약에서 벗어남 → 해결 가능 | ✅ 정확. 단, 앱-서버 API 통신은 HTTPS 권장 |
| HTTP에서 localhost만 허용되는 문제 | 네이티브 앱은 브라우저 Secure Context 제약에서 벗어남 | ✅ 정확. 외부망에서도 동작 가능 |
| 외부 IP 간 연결 | STUN/TURN 및 미디어 서버 구성으로 해결, 별도 네트워크 구성 필요 | ✅ 정확. Flutter로 해결되는 것이 아님 |
| 여러 사용자 화상회의 | SFU 기반 다자간 처리 가능 | ✅ 정확. P2P는 2~3명, 확장 시 SFU 권장 |
| SIP MD5 인증 오류 | Flutter로 바꿔도 자동 해결 안 됨 | ✅ 정확. SIP 계정 인증은 별도 해결 필요 |
| WebRTC 미디어 암호화 | DTLS-SRTP 유지 권장 | ✅ 정확. TLS만 제거되고 미디어 암호화는 유지 |
| Windows/macOS 지원 | flutter_webrtc 지원. Intel Mac은 x64 지원 축소 고려 | ✅ 정확. Intel Mac은 별도 검증 항목 필요 |

**총평**: 기술적 분석의 정확도는 높다. 다만 문서의 추천 기술 조합(`dart-sip-ua`)은 `SmartCC_Kibal-Client` 프로젝트에서 실제 채택한 `flutter_sip` + `flutter_webrtc`와 다르다. 현재 구현된 Mobile Client(`mobile/`)는 `flutter_sip` 기반이므로, 문서와 실제 구현 사이에 기술 선택지가 존재한다는 점을 독자에게 알려야 한다.



### 3.1 지금 실제로 구현된 것

| 영역 | 구현 상태 | 근거 |
|------|-----------|------|
| **Server (Asterisk)** | ✅ 완료 | Asterisk 22 LTS, PJSIP, ConfBridge SFU, DEV/PRD 운영 중 |
| **Web 클라이언트 (React + SIP.js + WebRTC)** | ✅ 완료 | CT01/CT02/CT05 DEV/PRD PASS, npm run build PASS |
| **Mobile 클라이언트 (Flutter)** | ✅ 구현 완료 | `SmartCC_Kibal-Client/mobile/` — 14개 Dart 파일, 4,500+ 라인 |
| **iOS 시뮬레이터 테스트** | ✅ 완료 (사용자 확인) | iOS 클라이언트 빌드 완료, 시뮬레이터 동작 확인 |
| **Android 빌드/테스트** | ⏳ 미진행 | `mobile/android/` 존재, 빌드·실행 미확인 |
| **Windows/macOS 네이티브 빌드** | ⏳ 미진행 | `SmartCC_Kibal-Client`에서 Flutter 기반 Windows/macOS 프로젝트 미생성 |
| **SFU (LiveKit)** | ⏳ 미구성 | 문서상 권장 사항이나 미확정 |
| **TURN (coturn)** | ⏳ 미구성 | CT06 외부망 테스트 대비 필요 |
| **WSS/TURN 인프라** | ⏳ 미구성 | CT06 BLOCKED 상태 |
