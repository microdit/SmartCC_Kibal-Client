# 작업계획서 — 음성 전용 참가자(카메라 없음) 영상 수신 지원

**날짜**: 2026-11-12
**버전**: v1.0
**대상 버전**: macOS Client v0.0.17
**관련**: ADR-006(`wiki/05_Decisions/ADR-006-카메라없는단말_영상수신전용.md`), 작업로그 `wiki/07_Logs/작업로그_20261112.md`

---

## 1. 배경

2026-11-12 서버 유선(192.168.0.3) 전환 후 6000 회의실 3자 통화 성공. 그러나 **카메라가 없는 1101(MacPro)** 화면에서는 다른 참가자 영상이 보이지 않는다.

### 1.1 관찰 (1101 로그, 01:11~01:28)

| 시각 | 로그 | 의미 |
|------|------|------|
| 01:11:56 | `SIP call -> 6000 voiceOnly=true` | 카메라 없음 → 음성 전용 발신 |
| 01:11:59 | `re-INVITE 수신 hasAudio=true hasVideo=true -> 자동 수락` | ConfBridge(SFU)가 영상 스트림 추가 제안 |
| 01:11:59 | `remote video tile 등록(전용)` ×2 | 참가자 2명 영상 트랙/타일 생성 |
| 01:12~01:28 | `videoBytes=0`, `video summary in=-@-fps decodedFrames+0` | **영상 데이터 0** — 타일은 있으나 화면 검정 |
| 동일 | `audioLost=0`, 30초당 ~186KB | 음성 정상 |

### 1.2 원인 가설

| ID | 가설 | 근거 | 검증 방법 |
|----|------|------|----------|
| V1 | `voiceOnly=true` 옵션이 `OfferToReceiveVideo=false`로 전달 → 최초 offer에 video m-line 없음 / re-INVITE answer에서 video를 `inactive` 또는 `port 0`으로 응답 | `sip_ua_helper.dart _options()`에서 voiceOnly가 수신 constraint까지 끔 | re-INVITE answer SDP의 `m=video`/`a=` 방향 확인 |
| V2 | re-INVITE 자동 수락(`onNewReinvite`) 시 `voiceOnly` 옵션으로 answer → 영상 수신 거절 | H5 수정 시 기존 call 옵션 재사용 | `sip_client.dart` 수락 옵션 추적 |
| V3 | 서버(ConfBridge)가 sendonly 참가자에게 영상을 보내지 않음(`video_mode`) | `confbridge.conf` 설정 | `confbridge show profile bridge`, `rtp set debug` |
| V4 | 트랙은 받았으나 `transceiver.direction=inactive` | WebRTC unified-plan | `getTransceivers()` 로그 |

> 핵심 원칙: **"카메라 없음 = 송신 없음"이지 "수신 없음"이 아니다.** 음성 전용 단말도 영상은 `recvonly`로 받아야 한다.

## 2. 목표 / 완료 기준

| 구분 | 기준 |
|------|------|
| 기능 | 1101(카메라 없음)이 6000 회의 참여 시 다른 참가자 영상 타일이 실제로 재생 |
| 지표 | 1101 `SIP media summary` `videoKB>0`, `video summary decodedFrames>0`, `in=WxH@fps` |
| 1:1 | 1101 ↔ 1102 1:1 영상통화에서 1101이 상대 영상 수신(단방향) |
| 회귀 | 카메라 있는 단말(1102/1103) 송수신 영향 없음, 음성 `audioLost` 증가 없음, ICE 실패 0 |
| 서버 | 서버 로그 `DTLS ... ICE not completed yet` 반복 원인 확인(부가) |

## 3. 작업 범위

### 3.1 클라이언트 (macos-client)

| # | 작업 | 파일 |
|---|------|------|
| T1 | `voiceOnly`를 **송신 여부**(`sendVideo`)와 **수신 여부**(`receiveVideo`)로 분리 | `packages/sip_ua/lib/src/sip_ua_helper.dart` `_options()` |
| T2 | 카메라 없음 시 `mediaConstraints.video=false` 유지, `OfferToReceiveVideo=true` | 동일 |
| T3 | 발신 offer에 video transceiver `recvonly` 추가 | `packages/sip_ua/lib/src/rtc_session.dart` (connect 경로) |
| T4 | 수신(accept) / re-INVITE 자동 수락 시 상대가 영상을 제안하면 `recvonly`로 응답 | `lib/src/sip/sip_client.dart` accept, `onNewReinvite` |
| T5 | 진단 로그: transceiver별 `mid/kind/direction/currentDirection`, answer SDP `m=video` 요약 1줄 | `sip_client.dart` |
| T6 | UI: 수신 영상만 있는 경우 로컬 미리보기 영역 "카메라 없음" 표시, 원격 타일 정상 표시 | `ui/conference/conference_screen.dart`, `ui/call/call_screen.dart` |
| T7 | 단위 테스트: 옵션 생성(sendVideo/receiveVideo 조합) | `test/` |

### 3.2 서버 (SmartCC_Kibal) — 확인 위주

| # | 작업 |
|---|------|
| S1 | `confbridge.conf` bridge profile `video_mode`(sfu) 확인, recvonly 참가자에게 스트림 전달 여부 |
| S2 | 테스트 중 `rtp set debug on` 1분 캡처 → 1101 방향 video RTP 송신 확인 |
| S3 | `DTLS packet ... ICE not completed yet` 반복(60초 주기) 채널 추적 |

## 6. 위험 / 대응

| 위험 | 영향 | 대응 |
|------|------|------|
| recvonly offer를 Asterisk가 거부/`inactive` 응답 | 영상 여전히 0 | 서버 `pjsip` endpoint 설정 확인(S1), 필요 시 최초 offer는 audio만, re-INVITE에서 recvonly |
| sip_ua 포크 변경 범위 확대 | 업스트림과 차이 증가 | ADR-005/006에 변경점 기록, 포크 diff 최소화 |
| 1101 CPU/대역 증가(영상 디코딩 2개) | MacPro 부하 | 최신 3타일 제한 유지 |
| 기존 voiceOnly 의미 변경 | 다른 호출부 회귀 | `voiceOnly` 기본 동작 유지 + 새 파라미터 추가 방식 |
