# 작업계획서 — 회의 참가자 카드(영상 없는 참가자 표시·내선 라벨)

**날짜**: 2026-11-12
**버전**: v1.0
**대상**: macOS Client v0.0.18, 서버 OPS API
**관련 설계**: `wiki/02_Design/회의참가자_아키텍처_20261112.md`, `wiki/02_Design/회의화면_화면설계서_20261112.md`
**선행**: ADR-006(v0.0.17) — 실기 확인: 1101 `videoKB=15384 videoTracks=2/2 ice=Completed`

---

## 1. 배경 / 문제

6000 회의 3자(1101 카메라 없음, 1102 MacBook, iMac) 진행 중:
- 1102·iMac 화면에 **1101 카드가 없다.** 1101은 영상을 보내지 않아 원격 영상 트랙이 없고, 현재 카드는 "원격 영상 트랙" 기준으로만 만들어진다.
- 카드 라벨이 `원격 1/2`라서 누가 누구인지 모른다.
- 음성은 정상(서버 channelstats opus 손실 0~29)이므로 **참가자로서 표시되어야 한다.**

서버에서 확인한 사실(`core show channel`):
- 각 채널 토폴로지에 `softbridge_dest_PJSIP/<ext>-<id>_1` 스트림 = 다른 참가자의 영상 슬롯(순서 = SDP m-line 순서)
- 참가자 자신의 `video-1` 상태: 1101은 `sendonly`(서버→단말, 즉 단말은 송신 안 함) → **영상 없음 판정 근거**

## 2. 목표 / 완료 기준

| # | 기준 |
|---|------|
| A1 | 회의 화면 참가자 카드 = **서버 ConfBridge 참가자 전원**(본인 제외 + 내 카드) |
| A2 | 영상 없는 참가자(1101) 카드: "영상 없음" + 마이크 아이콘, 내선 라벨 |
| A3 | 영상 있는 참가자 카드: 내선 라벨(`1102`), 실시간 썸네일 |
| A4 | 입장/퇴장 5초 이내 반영 |
| A5 | 같은 내선 중복 접속 시 `1102 (2)`처럼 구분 |
| A6 | 서버 API 실패 시 기존 동작(트랙 기준 카드) 유지 — 회귀 없음 |

## 3. 작업 범위

### 서버 (SmartCC_Kibal, OPS)
| # | 작업 |
|---|------|
| S1 | `GET /api/conference/<room>/participants?extension=<ext>` (X-Client-Key) |
| S2 | `confbridge list <room>` 파싱 → 채널·내선·CallerID |
| S3 | 채널별 `core show channel` 스트림 파싱 → `has_video`(자기 `video-*` 상태가 sendrecv/recvonly), 요청자 채널의 `softbridge_dest_*` 순서 → `video_order` |
| S4 | 채널명 정규식 검증(명령 주입 방지), 단위 테스트 |

### 클라이언트 (macos-client)
| # | 작업 |
|---|------|
| C1 | `ConferenceParticipantService`: OPS API 5초 폴링(회의 중에만) |
| C2 | 카드 모델: 참가자 목록 + 원격 영상 스트림 매핑(영상 있는 참가자를 `video_order` 순서로 원격 스트림에 대응) |
| C3 | 회의 화면: 영상 없음 카드, 내선 라벨, 참가자 수 표시 |
| C4 | 로그: `CONFERENCE participants n=.. video=..` 변경 시 1줄 |
