# git-pull.sh 발행 정보 연동 / 빌드 선택 작업계획서 v1.0

- 문서 ID: PLAN-20261127-GITPULL-RELEASE-INFO
- 작성일: 2026-11-27 KST
- 상태: 구현 완료 → TEST 검증 중
- 선행 체크리스트: 지시서/영속규약/상태/원격버전 확인 완료

## 1. 배경/문제

- `./scripts/git-pull.sh --auto --interactive`로 브랜치를 받아도 **어느 원격·어느 버전·어느 커밋을 받았는지** 선택 전에 보이지 않는다.
- 다른 작업자가 feature(v0.0.65)와 test(v0.0.66) 중 엉뚱한 브랜치를 받아 기능 누락/혼란이 생긴다.
- pull 후 빌드까지 이어지지 않아 "최신 정보를 같이 보면서 선택 → 같은 버전으로 빌드"가 불가능하다.

## 2. 목표

1. 브랜치 선택 목록에 **원격/버전/커밋/기능 요약**을 표시한다.
2. pull 완료 후 **발행 보고 7항목**을 자동 출력한다(보고 규칙 §1 준수).
3. `--build` 옵션으로 선택한 브랜치에서 **analyze/test/release_macos.sh/DMG SHA256**까지 한 번에 실행한다.
4. 발행 규칙 문서와 `git-pull.sh`가 같은 정보를 쓰도록 맞춘다(단일 소스).

## 3. 범위

| 포함 | 제외 |
|------|------|
| `scripts/git-pull.sh` 개선 | 다른 저장소(Server)의 git-pull.sh |
| `scripts/pick_branch.py --info` 확장 | 자동 승격/PR 생성 |
| `wiki/03_Guides/...발행_원격브랜치_보고_규칙_v1.0.md` 갱신 | force push 자동화 |
| wiki 로그/양쪽 교차 기록 | NAS dev/prd 자동 push |

## 4. 설계

### 4.1 브랜치 정보 표시 (선택 전)

```
Available branches:
  1) feature/external-network-access  [origin] 0.0.65+66  0fafeed4  DEV 안정화/외부망 라인
  2) test/client-v0.0.64-recovery     [origin] 0.0.66+67  c3997b89  TEST 검수(로그 1~60분/이중저장)
```

- 원격 판별: 브랜치명에 `/` 포함 + remote 존재 → 해당 remote, 아니면 `origin`
- 버전: `<remote>/<branch>:macos-client/pubspec.yaml`의 `version:` (없으면 `-`)
- 커밋: `<remote>/<branch>` 짧은 해시
- 기능 요약: 브랜치별 매핑 테이블(문서/스크립트 공통 상수)

### 4.2 pull 후 자동 보고

```
[발행 보고]
- 저장소: <ROOT_DIR>
- 원격: origin (https://...)
- 브랜치: <TARGET>
- 푸시 원격 브랜치: <PULL_REMOTE>/<TARGET>
- 커밋: <hash>
- 버전: <version>
- DMG: <경로/없음>
- 승격 상태: TEST 검수 중 / DEV 안정화
- NAS dev/prd: SKIP(SSH 4949 timeout) / 반영
- pull 안내: git checkout -b <TARGET> <PULL_REMOTE>/<TARGET>
```

### 4.3 `--build` 옵션

```bash
./scripts/git-pull.sh --interactive --build
./scripts/git-pull.sh --interactive --dry-run
```

- pull 성공 후 자동:
  - `cd macos-client && flutter analyze && flutter test`
  - `./scripts/release_macos.sh --no-bump`
  - `codesign --verify --deep --strict build/.../macos_client.app`
  - `shasum -a 256 ...dmg`
- 빌드 결과를 발행 보고에 덧붙여 출력

### 4.4 로그 동기화/가시성 (중요)

- 문제: wiki 로그가 로컬 커밋에만 있으면 다른 작업자는 못 본다.
- 해결: `git-pull.sh`가 fetch 후 **원격 브랜치의 최신 교차 로그/작업로그를 자동 표시**한다.
  - `git ls-tree`로 원격 브랜치의 로그 파일 최신 3개를 찾고 각각 말미 8줄을 표시한다.
  - `git log -3 --format='%h %ad %s' --date=short <remote>/<target> -- wiki/07_Logs docs/_작업이력`으로 로그 커밋 이력을 표시한다.
  - `--dry-run`에서도 checkout/pull/stash/build 없이 동일한 원격 로그를 확인할 수 있다.
- 다른 작업자가 남긴 로그를 pull 후 즉시 볼 수 있게 하고, 내가 남긴 로그도 커밋/푸시되어 전파되게 한다.
- 보고 7항목에 "최근 원격 로그 커밋"을 추가한다.

### 4.5 단일 소스 원칙

- 브랜치별 원격/버전/커밋/기능 요약은 `scripts/pick_branch.py --info`가 생성한다.
- `git-pull.sh`는 그 출력을 선택 목록과 발행 보고에 재사용하고, 문서에는 "자동 생성 기준은 git-pull.sh 출력"이라고 명시한다.
- DMG는 최신 파일 글롭이 아니라 **현재 checkout한 pubspec 버전과 일치하는 파일명**만 보고한다.

## 6. 안전/정책 준수

- 버전 상승 없음(도구 개선이므로 release_macos.sh 가드 무력화 불필요)
- `git add -A` 금지, 명시 파일만 stage
- force push 금지
- 검수 전 산출물은 TEST 브랜치 먼저, feature 승격은 PASS·승인 후
- 자동 stash는 추적 파일만 보존하고 untracked 파일은 이동하지 않음
- active call 중 파괴적 서버 작업 없음(Client 도구 작업만)

## 7. 완료 기준

- `./scripts/git-pull.sh --interactive`에서 브랜치별 원격/버전/커밋/기능이 보임
- pull 후 7항목 자동 보고와 원격 로그 최신 3개/로그 커밋 이력 표시
- `--dry-run`은 checkout/pull/stash/build 없이 원격 정보만 표시
- `--build`로 analyze/test/DMG/SHA까지 성공하고 버전 불일치 시 중단
- 보고 규칙 문서와 스크립트 출력이 일치
