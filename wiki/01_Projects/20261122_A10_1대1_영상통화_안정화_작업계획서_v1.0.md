# A10↔macOS 클라이언트 1:1 영상통화 안정화 작업계획서

| 항목 | 내용 |
|---|---|
| 문서 ID | PLAN-20261122-A10-1TO1-STABILIZE-001 |
| 버전/작성일 | v1.0, 2026-11-22 |
| 상태 | 승인 대기 → 진행 |
| 대상 | SmartCC_Kibal-Client (macOS v0.0.56+), SmartCC_Kibal (Asterisk/ops), Yealink A10 `192.168.11.65` |
| 관련 | RPT-20261122-A10-1201-1TO1-001, ADR-009, 설계서/테스트/검증 문서 |

## 1. 배경
- A10 SIP Server Host를 구 IP `192.168.0.3` → `192.168.11.5`로 변경 후 **등록 성공**, A10→1101 1:1 통화는 연결 성공.
- 그러나 **A10→1102(카메라 보유) 1:1은 수락 1.8초 뒤 A10이 BYE**하여 끊김. 6100 회의실은 30분 이상 정상 유지.
- 로그 교차 분석 결과 3개 원인 중첩 확인 → 본 계획으로 순차 조치.

## 2. 목표
| ID | 목표 | 완료 기준 |
|---|---|---|
| O1 | 1:1 수락 후 즉시 끊김 해소 | A10↔1102 통화 60초 이상 유지, video track live |
| O2 | LAN 내부 TURN 인증 오류 제거 | Asterisk 로그 `370401 Unauthorized` 없음 |
| O3 | 1201 상태 표시 안정 | `pjsip show contacts` 1201 Avail 유지 (qualify 무응답으로 Unavail 안 됨) |

## 3. 작업 항목 (우선순위 순)
| 순서 | 작업 | 대상 | 변경 요지 |
|---|---|---|---|
| 1 | 1:1 수신 fps 60→30 제한 | Client `sip_client.dart`, `video_quality_settings.dart` | SIP 단말(A10 최대 30fps)과 1:1 시 fps 상한 30 적용 |
| 2 | LAN 내부 TURN 비활성화 | Client `sip_client.dart` `_buildIceServers`, OPS `/api/client/config` | onLan이면 TURN URL 제외, STUN/host만 사용 |
| 3 | 1201 AOR qualify 비활성화 | Server `pjsip.conf.template` `[1201]` aor | `qualify_frequency` 제거/0 → Unavail 방지 |

## 4. 절차
1. 본 계획서 + 설계/테스트/검증/승인 문서 작성
2. wiki 로그 기록 → git 커밋/푸시 3-way 동기화
3. 1→2→3 순서 코드/설정 수정
4. A10→1102 1:1 재시도, 60초 유지·영상 수신 확인
5. 검증 결과를 검증보고서에 반영, 필요 시 커밋

## 5. 리스크/제약
- Asterisk 재생성은 활성 통화(6100 등)에 영향 → qualify 변경은 런타임 반영 우선, 재생성은 창구 필요
- Client 변경 시 앱 재설치/재기동 필요
- A10 관리 비밀번호는 기록하지 않음(웹 세션은 사용자 로그인 유지)

## 6. 완료 기준
- A10↔1102 1:1 영상통화 60초 이상 유지 + 양쪽 video track live
- TURN 370401 경고 제거, 1201 Avail 유지
