# 작업 로그 2026-11-21

## 주소록 버전관리 시나리오 재검증/설계 문서화

- 사용자 요구사항 정리
  1. 최초 인증 후 전체 주소록 1회 가져오기
  2. 인증 후 기존 주소록 유지, 네트워크 불안정/단절과 무관하게 유지
  3. 서버 주소록 변경 시 사용자에게 갱신 안내, 갱신은 사용자 수행
  4. 강제 갱신은 서버 전면 개편 시 OPS 콘솔 전체 갱신 기능으로만 수행
- 현행 기준선(코드 관찰)
  - `OpsDirectory.fetch()` 실패 시 빈 `OpsDirectory()` 반환
  - `AddressBookScreen._refresh()`가 실패/미인증 시 빈 디렉터리로 상태 덮어쓰기 가능
  - 앱 시작/재개/설정 복귀/수동 새로고침에서 전체 fetch 호출
  - `ServerConfigService.refresh()`는 200 config를 맥락 검증 없이 적용/저장
  - 서버 `/api/client/config`는 `config_version`/manifest를 이미 제공

## 주소록 버전관리 클라이언트 구현 (DEV)

- `OpsDirectory.fetch()`를 `OpsDirectoryFetch(ok/error)`로 변경: 실패 시 빈 디렉터리 반환 금지.
- `address_book_cache.dart` 추가: `address-book-cache.json` 캐시(버전/forceVersion/fetchedAt) 저장, SIP 비밀번호는 캐시 미저장.
- `AddressBookScreen`: 캐시 우선 표시, 최초/캐시없음만 전체 fetch, 캐시 있으면 버전 메타 비교만 수행. 버전 변경 시 사용자 업데이트 배너, 실패 시 기존 캐시 유지.
- `ServerConfigService`: 외부망(`skipInternal`)에서 내부 RFC1918/localhost/.local config 응답 거부 가드 추가.
- dialer/login/settings 호출부: fetch 실패 시 기존 데이터 유지/안전 처리.
- 검증: `dart analyze` 대상 파일 No issues found.
- 후속: OPS 콘솔 강제 갱신 발행(force_version/audit), 실기 T1~T11 검증, macOS 빌드/테스트.
