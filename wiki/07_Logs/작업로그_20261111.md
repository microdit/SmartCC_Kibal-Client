## 시간순 기록

2. **v0.0.5 빌드/검증** — DMG `macos_client_v0.0.5.dmg`(sha256 `ee73f2…`). H1 복구(`recovered=true kind=audio`) 확인했으나 `audioBytes=0`, 서버 RTP 0/0 → H4(미디어 경로)로 전환
3. **증거 수집 도구** — `scripts/capture_remote_audio.sh` 추가: pjsip logger/rtp debug ON → 10초 스냅샷(confbridge/channelstats) → OFF + docker logs 수집. `kill -9`로만 종료됨(트랩 이슈)
4. **서버 미디어 주소 보정** — `pjsip.conf.template`에 `media_address=${MEDIA_ADDRESS}`, `[transport-ws]`에 `external_media_address`/`external_signaling_address`, `local_net` 10/8만 유지. `entrypoint.sh` envsubst, `deploy/dev/compose.yaml` bind mount, `.env`/`init-env.sh`(dev/prd) 반영. 런타임 확인: `c=IN IP4 192.168.11.39`로 변경, **ICE 후보는 172.19.0.2 유지**
5. **ICE 끄기 시도** — `ice_support=no` → 클라이언트 `488 Bad Media Description`. 원복
6. **엔타이틀먼트 결함 규명** — Release에 `com.apple.security.network.server` 누락으로 UDP 후보 미생성(TCP port 9만). 추가 후 v0.0.6에서 UDP 후보(`192.168.11.22`, srflx `211.253.173.236`) 확인
7. **DTLS 실패 규명·수정** — `dtls_verify=yes` → `certificate verify failed`로 즉시 BYE. `dtls_verify=fingerprint`로 수정, `webrtc=yes`를 개별 옵션으로 분해(`media_encryption=dtls`, `ice_support=yes`, `use_avpf=yes`, `rtcp_mux=yes`)
8. **ICE 자체 종료 규명** — 서버 channelstats `rx/tx` 정상(1101 3728/3788), RTP 로그 양방향(`192.168.11.22:51938`). 실패 원인은 클라이언트가 시그널링 후보 `172.19.0.2`로의 check/consent 실패 후 `ICE Connection Failed`로 BYE하는 것
9. **sip_ua 로컬 포크** — `macos-client/packages/sip_ua` 생성, `_rewriteUnreachableIceCandidates`로 원격 SDP의 172.16/12 후보를 `c=` 주소로 보정. `pubspec.yaml`에 `dependency_overrides` 추가. `flutter analyze` 0건, 테스트 통과
10. **v0.0.7 빌드/실기** — `macos_client_v0.0.7.dmg`(sha256 `0f2f46…`). 1101 오디오 단독 통화 **118초 유지**(12:43:55~12:45:54, `audioBytes` 36,000→911,840). 다자간/영상은 17~35초 `ICE Connection Failed` 잔여

13. **H5 규명/v0.0.8** — `docs/테스트/오늘테스트로그_v1.4.md`와 `evidence/20261111-124756-remote-audio/` 분석 결과, 영상/다자간 실패의 직접 원인은 **서버 re-INVITE에 200 OK 미응답**이었다
    - 서버 re-INVITE(`CSeq: 14230/18793 INVITE`)에 클라이언트는 `100 Trying`만 보내고 200 OK 없음
    - `sip_client.dart`의 `onNewReinvite`가 빈 구현 → `event.accept()` 미호출 → 새 ICE 세대 미완료 → 15~17초 후 `408 ICE Connection Failed`
    - 서버 SDP: 오디오/영상 모두 `c=IN IP4 192.168.11.39` + `a=candidate ... 172.19.0.2 ...` (후보 보정은 정상 적용됨)
    - 서버는 클라이언트 영상 RTP를 수신(`Got RTP type 100`)하지만 re-INVITE 미응답 상태에서 영상 송신 0건
    - 수정: `onNewReinvite` 자동 수락, 포크에서 re-INVITE마다 중복 video track 추가 방지
    - v0.0.8+8 빌드: `analyze` 0건 / `test` 통과, DMG `sha256 5cede9e0…`, `CFBundleVersion` 동기화 스크립트 보정

## 핵심 성과

- 원격 오디오 누락의 직접 원인(H1)과 미디어 경로 문제(H4-1~4), 재협상 실패(H5)를 **증거 기반으로 분리 규명**
- 오디오 단독 통화를 **118초 안정 유지**시켜 원래 버그 해소 확인
- 서버/인프라 변경 없이 Docker NAT 환경을 견디는 **클라이언트 SDP 후보 보정** 확보
- re-INVITE 미응답(H5)을 찾아 v0.0.8에서 수정 → 영상/다자간 ICE 실패의 직접 원인 제거

## 잔여

- v0.0.8 실기 재검증: 영상/3자 5분 이상, `videoBytes` 증가, `ICE Connection Failed` 0건
- re-INVITE 응답 후 서버가 영상 RTP를 실제 송신하는지 확인(`Sent RTP type 100`)
- 3자 입장 시 1명 튕김 — H5 수정으로 해소되는지 확인
- v0.0.7 기준 1:1 영상/3자 영상 5분 이상 장시간 회귀 미실시
- 1101이 DMG 볼륨에서 직접 실행 중 → `/Applications` 설치 권장
- `dtls_verify=fingerprint`는 DEV 한정, PRD 인증서 정책 재검토
- `capture_remote_audio.sh`의 `asterisk -rx`를 컨테이너와 동일한 `-C /run/asterisk/asterisk.conf`로 보정(경고 제거). 스냅샷 공백은 테스트 종료 시점 때문
- **MediaManager 다중 영상 결함**: `addRemoteStream` dedup + 세션당 1 영상 타일 → **v0.0.9에서 수정**(전체 트랙 dedup + 트랙별 렌더 스트림), 실기 검증 대기
- 1:1 영상통화는 H5와 별개로 실측 증거 필요
- v0.0.9 네이티브 `addTrack(addToNative:true)` 원격 트랙 추가가 macOS에서 안전한지 실기 확인 필요
- 양쪽 리포 변경 미커밋, `dev`/`prd` NAS remote 경로 문제 지속
