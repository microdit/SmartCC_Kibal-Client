## 슬립/재개 후 6700 회의실 복구

- **증상**: 서버(Mac Pro)와 클라이언트가 sleep 모드에 들어갔다 재개된 뒤 6700 회의실 정상 동작 불가.
- **점검**:
  - `update-server-ip.sh --check`: `MEDIA_ADDRESS=192.168.11.5` 변경 없음.
  - `fix-dev-ops.sh`: OPS health 200, DEV 3 컨테이너 정상.
  - `verify.sh`: Asterisk 22.8.1, PJSIP endpoint 정상, RTP 10000-10200, ICE/STUN 활성(`74.125.250.129:19302`).
  - `verify-sip-auth.py`: 12개 SIP auth 일치, `/ws` 활성. 1201 32자리 hex 경고는 기존 사항.
- **원인**: sleep/재개 이전의 진단봇 데몬 프로세스 2개(PID 3772, 74460)와 7001 ConfBridge 채널 2개가 잔류. 재개 후 새 세션이 추가되며 6700에 중복 봇/고참 채널이 섞여 영상 소스가 꼬임.
- **조치**:
  - 봇 데몬 프로세스 2개 강제 종료, 포트 4188 정리, 7001/1102/1106 잔류 채널 전부 hangup.
  - 진단봇 데몬 **단일 인스턴스** 재기동(PID 4131) → `diag-bot 7001 in 6700: video=1920x1080` 확인.
  - `conference_probe`(1103, room 6700): CONFERENCE_OK, `videoBytes` 895KB→2.1MB 증가, 오디오 수신 정상. 최종 6700은 7001만 상주.
- **교훈**: sleep/wake 후에는 반드시 `pgrep -fl diag-room-bot-daemon`으로 단일 프로세스 여부와 `confbridge list 6700`의 중복 채널을 확인할 것. 필요 시 `./scripts/restart-diag-bot.sh` 같은 단일 인스턴스 보장 스크립트화가 후속 과제.
- **단일 인스턴스 스크립트화 완료(서버 리포)**: `SmartCC_Kibal/scripts/restart-diag-bot.sh` 추가(`ensure|restart|status|stop`). 데몬에 `/tmp/kibal-diag-bot.lock` PID lock과 세션 재연결 시 `PJSIP/7001-*` 잔류 채널 hangup 로직 추가. launchd watchdog은 macOS TCC로 `~/Downloads` 접근이 차단되어 설치 후 제거하고, 데몬 자체 복구 + 수동/스크립트 ensure 방식으로 확정. 검증: 이중 실행 차단(`diag-bot already running`), `ensure` 정상 시 no-op, 강제 restart 후 단일 프로세스·단일 7001 채널 확인.
