## 1. 진단 대상 계층

```
[단말 A10 1201] ──SIP/UDP──┐
[1101/1103 WebRTC] ──WS────┼──> [Asterisk 22] ──> [ConfBridge 6000/6100]
[1102 macOS App]  ──WS─────┘                          │
                                                       ▼
                                            [OPS client-logs/*.log]
                                            [/var/log/asterisk/{messages,security,full}]
```

| 계층 | 관찰 지점 | 지표 | 소스 |
|------|-----------|------|------|
| L1 SIP 시그널링 | Asterisk | 404, REGISTER, INVITE, re-INVITE | `messages`, `security`, `pjsip set logger` |
| L2 등록 상태 | AOR/Contact | `Avail`, `remove_existing`, expiration | `pjsip show aor/contacts` |
| L3 브리지 | ConfBridge | `video_mode`, follow_talker Flags, 스트림 수 | `confbridge list/show profile` |
| L4 채널 | PJSIP channel | `NativeFormats`, stream `State/Formats`, 트랜스코딩 | `core show channel` |
| L5 WebRTC | 클라이언트 getStats | inbound/outbound-rtp, `freeze`, `pli`, `nack`, `framesPerSecond` | `sip_client.dart:829-930` |
| L6 애플리케이션 | MediaManager | `_remoteSessions`, 타일, `videoTracks` | `media_manager.dart`, `media_provider.dart` |
| L7 로그 파이프라인 | OPS | 필터 모드, rotation, 마스킹 | `remote_log_filter.dart`, `client_logs.py` |

## 2. 항목별 계층 매핑 (C→A→D→B)

| 항목 | 주 계층 | 보조 계층 | 진단 질문 |
|------|---------|-----------|-----------|

## 3. 데이터 흐름 — C (A10 원격 영상)

```
1103 (WebRTC, h264/vp8) ──> PJSIP/1103-0000000f ─┐
                                                  ├─ ConfBridge 6100 (kibal_bridge_ft, follow_talker)
1201 (A10, h264, max_video_streams=1) ───────────┘
        ▲
        └── video-1 State: sendrecv / Formats: (h264)  ← SDP 협상은 정상
        └── 관찰: 1103.log 는 in=1920x1080@30fps 정상 수신
        └── 미해결: 1201 이 "발화자 영상"을 실제로 수신하는가
```

**설계상 후보 3개**
1. `follow_talker`가 발화자 영상을 A10 leg로 전달하지 않음 (L3)
2. A10이 자기 자신의 영상만 루프백 수신 (L3/L4)
3. `max_video_streams=1`로 단일 스트림만 허용되어 선택 로직이 잘못됨 (L2/L4)

> `core show channel PJSIP/1201-*`에서 `video-1 sendrecv/h264`가 확인되므로 **SDP direction(`recvonly`/`inactive`) 문제는 배제**된다.

## 4. 데이터 흐름 — A (404)

```
1102 INVITE (01:05:02 KST)
  → security: SuccessfulAuth AccountID=1102, SessionID=tbfvf26b36uh2r533965
  → extensions.conf:18  Dial(PJSIP/1103,60,tT)
  → AOR 1103 : contact 없음
  → res_pjsip.c: Could not create dialog to invalid URI '1103'
  → chan_pjsip.c: Failed to create outgoing session
  → 1102 수신: Code [404] Not Found
```

**설계 파라미터** (`server/asterisk/config/pjsip.conf.template`)

| 파라미터 | 값 | 영향 |
|----------|-----|------|
| `max_contacts` | 3 | 다중 contact 허용 |
| `remove_existing` | `yes` | **새 REGISTER 시 기존 contact 전부 삭제 → 순간 공백** |
| `default_expiration` | 3600 | 만료 시 contact 소멸 |
| `qualify_frequency` | 30 | OPTIONS qualify |
| `remove_unavailable` | `false` | qualify 실패 시에도 contact 유지(Unavail) |
| `rewrite_contact` | `yes` | WS contact가 `x-ast-orig-host=…invalid:0`로 광고 |

**정정 포인트**: `01:05:30`의 착신은 1103이 아니라 `1102.log:269`의 `callPressed target=1102` self-call이다.

## 5. 데이터 흐름 — D (코드 결함)

### D1 재협상 옵션 누락
```
발신  : _helper.call(customOptions: voiceOnly ? _receiveVideoOptions() : null)   ← sip_client.dart:307
착신  : MapHelper.merge(answerOptions, _receiveVideoOptions())                    ← sip_client.dart:356
재협상: onNewReinvite → _acceptReinvite → accept(<String, dynamic>{})             ← sip_client.dart:631  ✗
                                                    ▲
                                        ADR-006 옵션이 전달되지 않음
```
→ 초기 협상은 `recvonly`, re-INVITE 후에는 기본 옵션으로 되돌아갈 위험.

### D2 누적 스트림
```
addRemoteStream()                     media_manager.dart:377-395
  └─ _remoteSessions[sessionId].add(stream)   (existsById 중복만 방지)
  └─ _sessionTrackCounts()                    :401-410  → 모든 과거 스트림 합산
  └─ session(video=1 → 3 → 6)                 로그에 누적으로 표시

removeRemoteStream(sessionId)         :575-590  ← 통화 종료 시에만 호출
  └─ 통화 중 re-INVITE로 추가된 이전 스트림은 정리되지 않음

remoteStreams getter                  :72-88   ← 최신 3타일만 노출
retainRemoteVideoTracks()             :497-518 ← active=1 / inactive=2
_renderers                            :117-121 ← 4개 상시 생성
```
→ `session(video=6)`은 "실시간 트랙 6개"가 아니라 **누적 스트림 합계**. 실질적 리소스 누수이며 B의 out-fps 붕괴 가중 요인.

## 6. 데이터 흐름 — B (품질)

`getStats()` 5초 폴링 → 30초 요약(`:793-794` `_summaryEveryTicks=6`)

| 필드 | 성격 | 해석 |
|------|------|------|
| `decodedFrames+N` | **30초 델타** | 정상이면 +900 (30fps) |
| `freeze`, `pli`, `nack`, `vLost`, `keyframes` | **누적 카운터** | 값 고정 = 이후 이벤트 0건 |
| `audioLost` | 누적 카운터 | `01:54:33` 이후 29 고정 = 무손실 |
| `in=WxH@fps` | 순간값 | `1280x720@30fps` 유지 |
| `out=WxH@fps`, `target`, `limit` | 순간값 | `02:44–02:46`에 fps만 붕괴 |
| `videoTracks=A/B` | A=최근 15초 증가 트랙, B=`trackIdentifier` 보유 트랙 | `1/1` = 실제 RTP 수신 1개 |

**3현상 분리**
| 시각 | 현상 | 계층 | 근거 |
|------|------|------|------|
| `01:11:03~01:11:28` | 첫 키프레임 대기 ~50초 | L3/L5 | `videoKB=97 → 3181 → 9176`, `pli=1` |
| `01:37:33`, `01:54:33` | 이산 손실 버스트 2회 | 네트워크 | `audioLost 0→15→29`, `vLost 0→42→134`, `decodedFrames+720/+811` |
| `02:44–02:46` | out fps `14→12` 붕괴 | **L5 로컬 인코더** | in 정상, `decodedFrames+900`, `videoKB≈9185`, `limit=none`, `target=1700kbps` |

## 7. 로그 파이프라인 설계 (진단 신뢰성)

| 단계 | 동작 | 주의 |
|------|------|------|
| 앱 | `AppLogger._pushInternal` → `toIso8601String()` | µs가 1000 배수면 **3자리**로 출력(정상) |
| 필터 | `RemoteLogFilter.shouldSend` | `mode=INFO + 이벤트`는 DEBUG 제외 |
| 전송 | `POST /api/client-logs` (session/offset 멱등) | `routes.py:464-498` |
| 저장 | `ClientLogStore.append` | `mask_secrets`, `MAX_LINE_BYTES=4096`, `keep_lines=2000` |
| 로테이션 | 앱 `maxFileBytes=2MB` → 마지막 400행 | 제공 로그 말미 개행 없음 = 캡처 절단 |

> **결론**: 제공된 로그는 OPS 수집본(`1102.log`)이며 현재 로컬 `app.log`는 21:17 세션(`mwdij3x9-12xi1m4`)으로 **다른 세션**이다. 코드 1:1 대조 시 빌드 버전을 확인해야 한다(`SIP accept video=...` 부재).
