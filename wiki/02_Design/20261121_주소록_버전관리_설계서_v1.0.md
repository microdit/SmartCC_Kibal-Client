## 1. 문제 정의

현재 주소록은 "서버에서 다시 가져오면 항상 최신" 모델이 아니라, 실제로는 **가져오기 실패 시 빈 결과로 화면/상태를 덮어쓰는** 동작이 섞여 있다. 네트워크 변경, 일시 단절, OPS 일시 장애, 잘못된 config 적용 시 주소록이 사라졌다가 다시 나타나는 혼란이 발생한다.

### 1.1 코드 기반 관찰

| 관찰 | 근거(코드) | 영향 |
|------|------------|------|
| 주소록 fetch 실패 시 빈 디렉터리 반환 | `macos-client/lib/src/utils/ops_directory.dart`: `fetch()` 예외/비정상 시 `return const OpsDirectory()` | 실패가 "데이터 없음"으로 변환됨 |
| 실패/미인증 시 빈 목록을 상태에 반영 | `macos-client/lib/src/ui/home/address_book_screen.dart`: `_refresh()`에서 빈 dir 또는 미인증 시 `_directory = const OpsDirectory()` | 기존 유효 주소록 소실 |
| fetch는 앱 시작, 앱 재개, 설정 복귀, 수동 새로고침, 실패 배너의 다시 시도에서 호출 | `address_book_screen.dart`: `_bootstrap`, `didChangeAppLifecycleState(resumed)`, `_goSettings().then(_refresh)`, 수동 버튼, RefreshIndicator | 네트워크 변동/앱 전환 시 반복 요청 |
| config는 200 응답이면 맥락 검증 없이 적용/저장 | `macos-client/lib/src/utils/server_config.dart`: `refresh()` 성공 시 `_current=cfg; cfg.save()` | 외부망에서 내부 주소가 적용되면 주소록 endpoint도 내부로 바뀌어 연쇄 실패 가능 |
| 서버는 이미 config_version을 제공 | `server/ops/api/app/routes.py`: `/api/client/config` → `config_version=f"c{contacts_ver}|r{conf_ver}"`, manifest 포함 | 버전 비교 기반 갱신 판단 가능 |

## 2. 목표

1. **최초 1회 전체 수신**: 인증 완료 후 주소록이 없을 때만 전체 가져오기.
2. **로컬 캐시 우선**: 인증 후 주소록이 있으면 네트워크 상태와 무관하게 기존 주소록을 유지한다.
3. **서버 변경 감지, 사용자 갱신**: 서버 주소록 버전이 바뀌면 사용자에게 갱신 가능 표시. 갱신은 사용자가 실행.
4. **강제 갱신은 OPS 전면 개편 시만**: 콘솔 OPS의 명시적 전체 갱신 기능으로만 강제 갱신.

## 3. 비목표

- 주소록 항목의 실시간 push 동기화(WebSocket/SSE) 도입은 이번 범위가 아님.
- 인증/키 정책 자체 변경은 별도 ADR(ADR-006) 범위.
- 외부망 config 내부주소 반환 문제의 서버 수정은 병행 P0이나, 본 문서는 주소록 캐시/버전 정책을 정의한다.

## 4. 설계 원칙

- **Cache-first, user-controlled**: 로컬 유효 캐시가 있으면 네트워크 실패로 지우지 않는다.
- **Version-gated refresh**: 서버 `config_version`/directory version이 바뀐 경우에만 갱신 후보로 본다.
- **Explicit force only**: 강제 갱신은 서버가 명시한 force 토큰/버전일 때만 자동 반영한다.
- **No silent destructive sync**: 실패를 빈 데이터로 변환해 UI를 파괴하지 않는다.

## 5. 데이터 모델

### 5.1 클라이언트 로컬 캐시

파일: `<logs>/address-book-cache.json` (평문 주소록 데이터, 민감정보 최소화; SIP 비밀번호 저장 정책은 보안 정책에 따름)

```json
{
  "schema": 1,
  "profile": "external|dev|prd",
  "fetched_at": "2026-11-21T12:00:00+09:00",
  "directory_version": "c12|r3",
  "force_version": "",
  "contacts": [{"extension":"1101","display_name":"...","sort_order":1}],
  "rooms": [{"room":"6700","name":"...","mode":"sfu","sort_order":1}],
  "source": "ops"
}
```

| 필드 | 설명 |
|------|------|
| `directory_version` | 서버 `/api/client/config`의 `config_version` 또는 전용 주소록 버전 |
| `force_version` | OPS가 발행한 강제 갱신 토큰. 클라이언트가 이 값을 아직 반영하지 않았으면 강제 갱신 대상 |
| `contacts/rooms` | 마지막으로 사용자에게 적용된 유효 주소록 |

### 5.2 서버 응답 확장(제안)

`/api/client/config` manifest 또는 `/api/client/directory-meta`:

| 필드 | 타입 | 설명 |
|------|------|------|
| `config_version` | string | 기존 값(`c{contacts}|r{conferences}`) 유지 |
| `directory_version` | string | 주소록 전용 버전. 초기에는 `config_version`과 동일 가능 |
| `force_update` | bool | 강제 갱신 필요 여부 |
| `force_version` | string | 강제 갱신 식별자(OPS 전체 갱신 실행 시 증가) |
| `force_reason` | string | 사용자 안내 문구(전면 개편/내선 체계 변경 등) |

## 6. 동작 시나리오

### 6.1 최초 인증 후
1. 인증 성공.
2. 로컬 캐시에 유효 주소록 없음 → 전체 fetch.
3. 성공 시 캐시 저장 + 화면 표시.
4. 실패 시 **빈 목록을 만들지 않고** "가져오기 실패" 안내 + 재시도 버튼. 기존 캐시가 있으면 기존 캐시 유지.

### 6.2 일반 실행/네트워크 변동
1. 앱 시작/재개/네트워크 변경 시 전체 주소록 fetch를 하지 않는다.
2. 캐시가 있으면 즉시 표시.
3. 백그라운드로 `config` 또는 `directory-meta`만 가볍게 조회해 버전 비교.
4. 버전 동일 → 아무 UI 변경 없음.
5. 버전 다름 → "주소록 업데이트 가능" 배너/배지 표시.

### 6.3 사용자 갱신
1. 사용자가 "업데이트" 클릭.
2. fetch 성공 → 캐시 교체, `directory_version` 갱신, 배너 제거.
3. fetch 실패 → 기존 캐시 유지, 실패 안내. 캐시를 비우지 않음.

### 6.4 강제 갱신
1. OPS 운영자가 콘솔에서 "주소록 전체 강제 갱신" 실행.
2. 서버가 `force_update=true`, 새 `force_version` 발행.
3. 클라이언트가 meta 확인 시 로컬 `force_version`과 다르면 자동으로 fetch 시도.
4. 성공 시 즉시 반영. 실패 시 기존 캐시 유지하되 "서버 주소록이 전면 개편되어 갱신 필요" 강한 안내 표시.

## 7. UI 정책

| 상태 | 표시 |
|------|------|
| 캐시 있음, 버전 동일 | 기존 주소록 표시, 동기화 오류로 비우지 않음 |
| 캐시 있음, 버전 다름 | "서버 주소록이 변경되었습니다. 업데이트하시겠습니까?" 배너 |
| 캐시 있음, 강제 갱신 필요 | "서버 주소록 전면 개편: 업데이트가 필요합니다." 강한 배너, 자동 재시도 |
| 캐시 없음, fetch 실패 | 빈 화면 + 오류 안내 + 재시도(기존처럼 빈 데이터가 정상 상태처럼 보이지 않게) |
| 미인증 | 주소록 미노출 또는 마지막 인증 캐시 노출 여부는 보안 정책 결정 필요(기본: 미노출) |

## 8. OPS 콘솔 요구사항

- 연락처/회의실 관리 화면에 **"주소록 강제 갱신 발행"** 버튼 추가.
- 버튼은 일반 CRUD 저장과 분리. 전면 개편 시에만 사용.
- 실행 시 `force_version` 증가, 감사 로그 기록(`addressbook_force_publish`, actor, reason, version).
- 일반 연락처 추가/수정/삭제는 `config_version/directory_version`만 증가시키고 사용자 선택 갱신으로 안내.

## 9. 보안/운영 고려

- 주소록 캐시에 SIP 비밀번호를 저장할지 여부는 별도 결정. 기본 제안: **표시용 주소록 캐시는 비밀번호 제외**, 빠른 연결 비밀번호는 인증된 세션/API에서 필요 시 별도 획득.
- 외부망에서 내부 IP config를 받으면 주소록 endpoint도 오염됨. 따라서 `ServerConfigService.refresh()`에 외부망 내부주소 거부 가드가 선행되어야 함.
- 버전 메타 조회 실패는 치명 오류가 아님. 기존 캐시 유지.

## 10. 수용 기준

- 네트워크 끊김/OPS timeout 후에도 기존 주소록이 화면에서 사라지지 않는다.
- 앱 재개/네트워크 전환만으로 전체 주소록 fetch가 반복되지 않는다.
- 서버 버전 변경 시 사용자에게만 갱신 안내가 뜬다.
- 사용자가 갱신하기 전까지 로컬 주소록은 유지된다.
- OPS 강제 갱신 발행 시 클라이언트가 안내/자동 반영한다(정책 선택).
- fetch 실패 시 `contacts=0 rooms=0`으로 정상 캐시를 덮어쓰지 않는다.
