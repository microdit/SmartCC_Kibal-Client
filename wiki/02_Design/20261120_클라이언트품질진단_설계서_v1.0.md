## 1. 전체 구조

```
[설정 화면]
 ├─ 로그보내기 ── RemoteLogForwarder.setAutoSend() / sendNow()
 ├─ 품질 지표 ── QualityReportService ── OPS /api/client-logs ── 표+CustomPaint 그래프
 └─ 영상 품질 ── VideoQualitySettings ── getUserMedia(ideal) + RTCRtpSender.setParameters()

[전체화면]
 └─ 전송속도 진단 버튼 ── LiveQualityService ── RTCPeerConnection.getStats() (1초)
                          └─ LiveQualityOverlay (실시간 + 60초 평균)
```

## 3. 데이터 흐름

### 3.1 품질 지표 (과거/요약)
1. OPS `/api/client-logs?extension=...&q=video summary` 조회.
2. 누적 카운터(first→last delta), 평균 fps/videoKB 산출.
3. 임계치로 양호/주의/위험 판정.
4. 표 + 그래프로 표시.

### 3.2 실시간 진단
1. `LiveQualityService`가 1초마다 `getStats()`.
2. bytes delta로 video/audio bitrate 계산.
3. codec/candidate-pair/freeze/pli/jitter/rtt 추출.
4. 60개 스냅샷 롤링 평균 계산 후 `ValueNotifier`로 UI 갱신.

### 3.3 수동 품질
1. 사용자 선택을 `video-quality-settings.json`에 저장.
2. `getUserMedia`를 `ideal` 해상도/프레임으로 재호출.
3. `RTCRtpSender.setParameters()`로 `degradationPreference`/`maxBitrate`/`maxFramerate` 적용.
4. 새 영상 트랙으로 `replaceTrack()`.

## 4. 판정 기준

| 판정 | 조건 |
|------|------|
| 양호 | 손실/프리즈 없음, fps 안정, ICE Completed |
| 주의 | vLost>0·freeze>10·pli>10 또는 평균 fps<25 |
| 위험 | 영상 트랙 0, ICE Checking/Failed, vLost>100·freeze>50·pli>50 |

---

## 5. 멀티플랫폼 설계

- 신규 의존성 없음: 차트는 Flutter SDK `CustomPaint`, 통계는 `flutter_webrtc` 기존 API.
- 플랫폼별 차이는 `ideal` 제약과 `setParameters` 지원 여부로 흡수.
- 실패 시 예외를 잡아 로그만 남기고 통화를 유지한다.
