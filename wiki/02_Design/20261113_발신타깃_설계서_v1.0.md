## 1. 현재 데이터 흐름 (결함 포함)

```
call(target)
  ├─ _helper.call(target, ...)                    sip_client.dart:303
  │    └─ localSdpTransformer(session,'offer',sdp)   :162-171
  │         └─ target = session.remote_identity?.uri?.user
  │              └─ 발신 offer 시점: null  ✗
  │                   └─ videoPolicyFor(null) = keep   sdp_codec.dart:8-13
  │                        └─ SDP 무변환 → VP8 우선 유지
  └─ _currentSession = SipSession(target)..setRemoteParty(target)   :313
       └─ ❗ offer 이후에 설정되므로 폴백으로도 부적합
```

`sdp_codec.dart` 자체는 정상이다.

| 함수 | 동작 |
|------|------|
| `videoPolicyFor('6100…6199')` | `h264Only` |
| `videoPolicyFor('12xx')` | `h264First` |
| `videoPolicyFor(그 외/null)` | `keep` |
| `applyVideoCodecPolicy()` | `42e01f`·`packetization-mode=1` 우선 정렬, `h264Only`는 H.264+RED/ULPFEC만 유지 |

**결함 위치는 정책 함수가 아니라 타깃 전달 경로다.**

## 2. F1 설계 — `_pendingCallTarget`

| 상태 | 시점 | 값 |
|------|------|-----|
| `_pendingCallTarget = target` | `call()`의 `_helper.call()` **직전** | `'1201'` |
| `localSdpTransformer` | offer 생성 | `remote_identity(null) ?? _pendingCallTarget('1201')` → `h264First` |
| `_pendingCallTarget = null` | `_cleanupSession()` | 통화 종료 시 초기화 |

```dart
String? _pendingCallTarget;
...
// call()
_pendingCallTarget = target;
final ok = await _helper.call(...);
...
// localSdpTransformer
final target = session.remote_identity?.uri?.user ?? _pendingCallTarget;
...
// _cleanupSession()
_pendingCallTarget = null;
```

### 설계 근거

- **왜 `_currentSession`이 아닌가**: `:313`에서 `_helper.call()` **이후** 생성되므로 offer 시점에 null.
- **왜 `remote_identity`만으로 부족한가**: 착신/재협상에서는 설정되지만 발신 초기 offer에서는 미설정. 6100에서만 정책 로그가 찍힌 이유.
- **왜 별도 필드인가**: `localSdpTransformer`는 전역 콜백이라 세션 객체를 인자로 받지만, 발신 타깃은 UA 외부(다이얼러)에만 존재한다.
- **초기화 필수**: 미초기화 시 직전 통화 타깃이 다음 통화에 남아 오적용(예: 1201 종료 후 6000 발신인데 `h264First` 적용). `_cleanupSession()`이 `callTerminated`/`hangup`/`_cleanup()`에서 호출되므로(`:395,418,575,1069`) 이곳이 단일 정리 지점.

### 영향 범위

| 시나리오 |变更前 | 变更后 |
|-----------|--------|--------|
| `1103 → 1201` 1:1 | `keep` → VP8 | `h264First` → A10 수신 가능 |
| `1103 → 6100` 회의 | `h264Only`(기존 동작) | 동일(`remote_identity` 우선) |
| `1103 → 6000` SFU | `keep` → VP8 | 동일(`6000`은 `keep`) |
| `1103 → 1102` | `keep` | 동일 |
| 착신 | `remote_identity` 사용 | 동일 |

→ **12xx 발신만** 바뀐다. 최소 침습.

## 3. F2 설계 — A4 롤백 후 재연결 흐름

```
[변경 전 v0.0.23]
DISCONNECTED → _needsReRegister=true → CONNECTED → unawaited(register())
   → sip_ua 포크가 WS close by local → DISCONNECTED → ... 루프

[변경 후 v0.0.24]
DISCONNECTED → 로그 + _setState(disconnected) + _completeTransport(false)
   → sip_ua 자체 재연결 → CONNECTED → _setState(connected) + _completeTransport(true)
   → REGISTER 는 UA 의 기존 등록 갱신(294초) 흐름에 맡김
```

v0.0.22 `1103`의 실측(`23:52:02 disconnected(1006) → 23:52:11 registered`)이 이 경로의 정상 동작을 증명한다. 서버 A3(`remove_existing=no`/ADR-004 Accepted)가 contact 공백을 이미 제거했으므로 **클라이언트 보강이 불필요**해졌다.

## 4. G2/G3 설계 — ConfBridge 영상 소스·이벤트

### 4.1 확인된 제약

| 항목 | 확인값 |
|------|--------|
| `confbridge show profile bridge` | `Video Mode: follow_talker`, `Enable Events: no`, `REMB Send Interval: 0`, **`Video Source` 항목 없음** |
| `confbridge.conf:36-43` | `video_mode=follow_talker`만, `video_source` 미설정 |
| `ConfbridgeSetSingleVideoSrc` | *"Set a conference user as the single video source distributed to **all other participants**"* → 자기 자신 제외 |
| `CBAnn/6100-*` | 오디오 안내 전용(`conf-onlyperson` 등), 영상 소스 아님 |
| `max_video_streams=1`(1201) | 단일 `video-1 sendrecv/h264` m-line. 소스 없으면 그대로 빔 |

⇒ **Asterisk 22에는 "빈 회의실 기본 화면"을 자동 생성하는 bridge profile 옵션이 없다.** 임의로 `video_source=` 를 넣으면 unknown option 경고만 발생한다.

### 4.2 G3 (이번 적용)

```ini
[kibal_bridge_ft]
type=bridge
...
video_mode=follow_talker
enable_events=yes
```

참가자 입·퇴장 이벤트(AMI/ARI)가 발행되어 카드 UI가 갱신 신호를 받는다. 영상 소스 자체는 만들지 않으므로 **단독 입장 스피너는 남는다**(정상 대기로 문서화).

### 4.3 G2 대안 (이번 제외, 후속 설계)

| 안 | 내용 | 난이도 | 비고 |
|----|------|--------|------|
| G2-A | 2번째 참가자 입장으로 해소 확인 | 낮음 | **G1로 이번 검증**. 정상 동작 확정 |
| G2-B | 더미 영상 참가자 채널을 6100에 상시 입장 + `ConfbridgeSetSingleVideoSrc`로 지정 | 높음 | 정지영상/파일 소스(`Originate` + 영상 재생) 설계 필요. 자기 제외 규칙 때문에 **반드시 별도 채널**이어야 함 |
| G2-C | 단말/앱 UI가 참가자 0명일 때 "대기 중" 화면 렌더 | 중간 | A10 펌웨어 영역, 서버 수정으론 한계 |
| G2-D | `video_mode=sfu`로 변경 | 중간 | 6000 SFU 회귀·A10 `max_video_streams=1` 제약 재검 필요 |

**권장**: G1로 정상 동작을 확정한 뒤, 운영 요구가 있으면 **G2-C**(단말 대기 화면) 또는 **G2-B**(더미 소스)를 별도 과제로 진행. 서버 설정만으로는 단독 입장 화면을 만들 수 없다.

### 4.4 G5 (운영)

`confbridge list 6100`에 동일 `1201` 채널이 2개 남는 현상(동시 2통화)은 테스트 종료 시 채널을 완전히 끊어 정리한다. 앱 단일 통화 구조와 A10 동시 호출이 원인(서버 작업로그 "문제3"과 동일 패턴).
