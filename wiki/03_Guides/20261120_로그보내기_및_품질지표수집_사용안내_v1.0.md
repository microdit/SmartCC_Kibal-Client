## 1. 로그보내기

### 1.1 자동보내기 (5분 주기)

- 스위치를 켜면 **즉시 1회 전송**하고, 이후 **5분마다** 로그를 분할해 자동 전송한다.
- 설정은 `remote-log-settings.json`의 `autoSend`에 저장되어 앱 재시작 후에도 유지된다.
- 전송 모드가 `끄기`이면 수집만 하고 전송하지 않으므로, "전송 설정"에서 모드를 확인한다.

### 1.2 즉시보내기 (1회성)

- 현재까지 쌓인 로그를 **즉시 한 번** 전송한다.
- 자동보내기가 켜져 있어도 대기 시간과 무관하게 바로 전송된다.
- 즉, **자동 + 즉시 동시 사용 가능**하다.

### 1.3 동작 상태 확인

다이얼로그 하단에 마지막 전송 시각/전송 줄 수/미전송 바이트가 표시된다. 서버에서는 다음으로 확인:

```bash
OPS_URL=http://192.168.11.5:8091 ./scripts/ops_client_logs.sh list
OPS_URL=http://192.168.11.5:8091 ./scripts/ops_client_logs.sh grep 1102 '원격 로그 즉시전송 요청' 10
```

## 2. 앱 내 품질 지표 보기 (v0.0.42)

설정 → **테스트 결과 · 품질 지표**에서 OPS에 업로드된 로그를 분석해 다음을 한 화면에 표시한다.

- **표**: 평균 수신 fps, 평균 videoKB/30s, 해상도, ICE 상태, vLost/freeze/pli/audioLost 증가량, keyframe/decoded 증가량.
- **그래프**: 수신 fps(선 그래프), vLost/freeze/pli 구간별 증가(막대 그래프).
- **진단 결과**: 양호/주의/위험 판정과 근거 문구, 조치 의견.

| 판정 | 조건 |
|------|------|
| 위험 | 영상 트랙 0 또는 ICE Checking/Failed, `vLost>100`·`freeze>50`·`pli>50` |
| 주의 | `vLost>0`·`freeze>10`·`pli>10` 또는 평균 fps < 25 |
| 양호 | 위 조건 미해당 |

> 그래프는 Flutter SDK의 `CustomPaint`로 직접 렌더링한다. 차트 패키지 등 외부 의존성을 추가하지 않았으므로 **1 source multi OS** 배포 원칙을 유지한다.

## 3. 영상 품질 수동 설정 (v0.0.43)

설정 → **영상 품질 (수동 테스트)**에서 해상도와 프레임률을 조합해 적용할 수 있다.

| 해상도 모드 | 캡처 기준 | 최대 비트레이트 |
|------------|-----------|----------------|
| 자동 | WebRTC가 선택 | WebRTC가 선택 |
| 320p | 568x320 | 0.4Mbps |
| 640p | 640x360 | 0.8Mbps |
| 720p | 1280x720 | 2.5Mbps |
| 1080p | 1920x1080 | 5Mbps |
| 4K | 3840x2160 | 12Mbps |

프레임률: 15 / 24 / 30 / 60fps 조합 가능.

- `자동`은 `degradationPreference=BALANCED`로 WebRTC에 위임.
- 수동은 `MAINTAIN_FRAMERATE_AND_RESOLUTION` + `maxBitrate`/`maxFramerate`를 `RTCRtpSender.setParameters()`로 적용하고, 카메라를 다시 열어 actor 트랙을 교체한다.
- 카메라/인코더가 요청 해상도를 지원하지 않으면 `ideal` 제약으로 인해 가까운 값으로 내려가므로, 4K가 항상 3840x2160로 나오는 것은 아니다.
- 통화 중 적용하면 카메라가 잠시 재시작될 수 있다.

설정은 `video-quality-settings.json`에 저장되어 재시작 후에도 유지된다.

## 4. 전체화면 실시간 전송속도 진단 (v0.0.44)

1:1 통화 또는 회의실에서 전체화면 진입 후 하단 컨트롤의 **전송속도 진단** 버튼(속도계 아이콘)을 누르면 우측 상단에 실시간 패널이 표시된다.

| 구분 | 표시 항목 |
|------|-----------|
| 영상 | 해상도, 코덱, 현재/평균 fps, 현재/평균 bitrate, 패킷 손실, freeze, PLI, NACK |
| 음성 | 코덱, 현재/평균 bitrate, jitter, 패킷 손실 |
| 네트워크 | 현재/평균 RTT, 가용 송신량, ICE candidate 상태 |
| 판정 | 양호 / 프레임 저하 / 품질 저하 / ICE 점검 중 |

1초 간격으로 WebRTC `getStats()`를 폴링하며, 평균은 최근 60초 롤링 윈도우다. 버튼을 다시 누르면 진단이 종료된다. 외부 차트/통계 패키지 없이 구현되어 멀티플랫폼 배포 원칙을 유지한다.

## 5. 품질지표 수집 스크립트

네트워크 전환 테스트 때 아래 스크립트로 `video summary`/`media summary`를 wiki에 자동 기록한다.

```bash
cd ~/Downloads/dev/SmartCC_Kibal-Client

# 현재 상태 기준 수집
./scripts/collect-test-metrics.sh 1102 current 10

# 무선으로 바꾼 뒤
./scripts/collect-test-metrics.sh 1102 wireless 10

# 다시 유선으로 바꾼 뒤
./scripts/collect-test-metrics.sh 1102 wired 10
```

- `OPS_URL` 기본값은 `http://192.168.11.5:8091`이며 환경변수로 변경 가능.
- 결과 파일: `wiki/08_Experiments/YYYYMMDD_네트워크전환_품질검증_v1.0.md`
- 단계별(phase) 구분으로 `current` / `wireless` / `wired` 비교가 가능하다.

## 6. 테스트 의견

수집 스크립트화는 **권장**한다. 이유:

1. 무선↔유선 전환은 IP가 바뀌고(`192.168.11.59` ↔ `192.168.11.54`) 로그에 타임스탬프가 남아야 인과관계가 명확하다.
2. `vLost`/`freeze`/`pli`는 누적 값이므로 **증가률**을 단계별로 비교해야 한다.
3. `ice=RTCIceConnectionStateChecking`이 섞이면 단순 손실이 아닌 재협상 실패이므로 `media summary`를 함께 봐야 한다.

판정 기준:

| 지표 | 정상 | 이상 |
|------|------|------|
| `in fps` | 29~30 | 5~18 또는 `-` |
| `vLost` | 증가 없음 | 계속 누적 |
| `freeze` / `pli` | 0~3 유지 | 수십~수백 누적 |
| `videoTracks` | 1/1 | 0/0 |
| `ice` | Completed | Checking |
