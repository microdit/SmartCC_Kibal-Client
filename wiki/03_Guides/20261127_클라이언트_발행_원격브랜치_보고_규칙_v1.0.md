## 3. 다른 작업자용 git pull 안내 (정확히 이대로)

```bash
# TEST 산출물(v0.0.66, 로그 주기/이중저장 기능 포함)을 받을 경우
git clone https://github.com/microdit/SmartCC_Kibal-Client.git
cd SmartCC_Kibal-Client
git fetch origin
git checkout -b test/client-v0.0.64-recovery \
  origin/test/client-v0.0.64-recovery
grep '^version:' macos-client/pubspec.yaml   # 0.0.66+67 확인
git log --oneline -1                          # fd441853 확인

# DEV 성격 기준선(v0.0.65, 안정화 라인)을 받을 경우
git checkout -b feature/external-network-access \
  origin/feature/external-network-access
grep '^version:' macos-client/pubspec.yaml   # 0.0.65+66 확인
git log --oneline -1                          # 42f74fdf 확인
```

> **주의**: 두 브랜치는 버전·커밋이 다르다. v0.0.66 기능을 쓰려면 반드시 `test/client-v0.0.64-recovery`를 받는다. feature를 받으면 v0.0.65라 로그 주기 설정(1~60분)과 이중저장 반영이 없다.

## 4. 금지/주의

- 보고에 "커밋했습니다"만 쓰고 브랜치/원격/버전 누락 금지
- 어떤 작업자가 어느 브랜치를 쓰는지 모호하게 쓰지 말 것
- NAS `dev/prd` 미도달 시 "SKIP(SSH 4949 timeout)" 명시, 성공한 것처럼 보고 금지
- `git add -A` 금지, 명시 파일만 stage
- 승인 없는 force push 금지 (이미 발생한 사고 재발 방지)

## 5. 다른 작업자용 전체 명령 시퀀스 (복사해서 그대로 사용)

### A. 처음 clone 없이 기존 로컬 저장소가 있는 경우

```bash
# 1) 작업 디렉터리로 이동
cd /Users/microdit/Downloads/dev/SmartCC_Kibal-Client

# 2) 원격 확인/추가 (이미 있으면 생략)
git remote -v
git remote add origin https://github.com/microdit/SmartCC_Kibal-Client.git 2>/dev/null || true
# NAS 4환경이 필요하면 (SSH 4949 접속 가능한 터미널에서만)
git remote add dev-gh https://github.com/microdit/Smart_Kibal-Client-DEV.git 2>/dev/null || true
git remote add test-gh https://github.com/microdit/Smart_Kibal-Client-TEST.git 2>/dev/null || true

# 3) 최신 반영 + 대상 브랜치 체크아웃
git fetch --all --prune

# v0.0.66 기능(로그 1~60분/이중저장)이 필요하면 TEST 브랜치
git checkout -b test/client-v0.0.64-recovery origin/test/client-v0.0.64-recovery 2>/dev/null \
  || git checkout test/client-v0.0.64-recovery
git reset --hard origin/test/client-v0.0.64-recovery

# 또는 v0.0.65 안정화 라인이 필요하면
# git checkout -b feature/external-network-access origin/feature/external-network-access 2>/dev/null \
#   || git checkout feature/external-network-access
# git reset --hard origin/feature/external-network-access

# 4) 버전/커밋 확인 (기대값과 일치해야 함)
grep '^version:' macos-client/pubspec.yaml      # TEST: 0.0.66+67 / feature: 0.0.65+66
git log --oneline -1                             # TEST: 79bd50f1 / feature: 74aaab7e
git status --short --branch

# 5) 검증
cd macos-client
flutter analyze
flutter test

# 6) 빌드 (현재 버전 그대로, 다른 Mac에서 재현할 때)
./scripts/release_macos.sh --no-bump
#   -> build/macos/Build/Products/Release/macos_client_v<버전>.dmg

# 7) 산출물 확인
shasum -a 256 build/macos/Build/Products/Release/macos_client_v*.dmg | tail -1
```

### B. 완전히 새로 clone 하는 경우

```bash
git clone https://github.com/microdit/SmartCC_Kibal-Client.git
cd SmartCC_Kibal-Client
git fetch --all --prune
git checkout -b test/client-v0.0.64-recovery origin/test/client-v0.0.64-recovery
grep '^version:' macos-client/pubspec.yaml   # 0.0.66+67 확인
cd macos-client && flutter pub get && flutter analyze && flutter test
./scripts/release_macos.sh --no-bump
```

### C. 버전을 올려 새 발행할 때 (정책 준수)

```bash
cd /Users/microdit/Downloads/dev/SmartCC_Kibal-Client/macos-client
# 반드시 TEST 브랜치에서만. release_macos.sh가 원격 최신 대비 역행을 차단함.
git branch --show-current   # test/... 이어야 함
flutter analyze && flutter test
./scripts/release_macos.sh --no-bump   # 또는 patch/minor/major로 자동 상향
codesign --verify --deep --strict build/macos/Build/Products/Release/macos_client.app
shasum -a 256 build/macos/Build/Products/Release/macos_client_v*.dmg
git add <명시 파일들>        # git add -A 금지
git commit -m "feat(client): vX.Y.Z ..."
git push origin <브랜치>
```

### 주의

- `git reset --hard`는 로컬 변경을 버린다. 로컬 수정이 있으면 먼저 `git stash` 또는 커밋할 것.
- **feature 브랜치를 받으면 v0.0.65**라 v0.0.66 기능(로그 주기 설정, NAS 이중저장 UI)이 없다.
- NAS `dev/prd` remote는 SSH 4949가 에이전트 셸에서 timeout 가능 → 접속되는 터미널에서만 push, 미도달 시 SKIP 기록.
- 빌드 가드(`release_macos.sh`)를 무력화하지 말 것.
