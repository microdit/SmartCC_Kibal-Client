## 1. 사용자 동작

### 1.1 최초 사용
1. 설정에서 인증 내선/클라이언트 키를 검증한다.
2. 인증이 완료되면 주소록을 서버에서 1회 가져온다.
3. 가져온 주소록은 기기에 저장되어 다음 실행부터 바로 표시된다.

### 1.2 평상시
- 주소록은 기기에 저장된 내용을 우선 표시한다.
- 네트워크가 잠깐 끊기거나 불안정해도 기존 주소록은 유지된다.
- 앱을 다시 열거나 네트워크가 바뀌어도 전체 주소록을 무조건 다시 받지 않는다.

### 1.3 서버 주소록 변경 시
- 서버 주소록 버전이 바뀌면 화면에 "주소록 업데이트 가능" 안내가 표시된다.
- 사용자가 **업데이트**를 누르면 최신 주소록을 받아 적용한다.
- 사용자가 업데이트하지 않아도 기존 주소록은 유지된다.
- 갱신 실패 시 기존 주소록은 유지되고, 나중에 다시 시도할 수 있다.

### 1.4 강제 갱신
- 서버 전면 개편 등 OPS 운영자가 강제 갱신을 발행한 경우, 클라이언트는 강한 안내를 표시하거나 자동 반영한다.
- 강제 갱신은 일반 주소록 변경과 다르며, OPS 콘솔의 전체 갱신 기능으로만 발행된다.

## 2. 운영자(OPS 콘솔) 동작

### 2.1 일반 변경
- 연락처/회의실 추가·수정·삭제: 서버 버전이 증가한다.
- 클라이언트는 이를 "업데이트 가능"으로 감지하고, 사용자가 갱신한다.

### 2.2 전면 개편 강제 갱신
- 사용 조건: 내선 체계 전면 변경, 대규모 주소록 교체, 호환성 깨지는 변경.
- OPS 콘솔에서 "주소록 전체 강제 갱신 발행" 실행.
- 입력: 사유(감사 로그), 대상 범위(전체/프로필).
- 결과: `force_version` 증가, 클라이언트에 강제 갱신 신호 전달.

## 3. 문제 발생 시 안내

| 상황 | 사용자 메시지 | 동작 |
|------|---------------|------|
| 최초 동기화 실패 | "주소록을 가져오지 못했습니다. 네트워크 확인 후 다시 시도하세요." | 재시도 버튼, 빈 캐시 생성 안 함 |
| 기존 캐시 있음 + 갱신 실패 | "업데이트에 실패했습니다. 기존 주소록을 유지합니다." | 기존 캐시 유지 |
| 서버 버전 변경 감지 | "서버 주소록이 변경되었습니다." | 사용자 업데이트 버튼 |
| 강제 갱신 필요 | "서버 주소록이 전면 개편되었습니다. 업데이트가 필요합니다." | 자동/수동 갱신 안내 |
| 인증 만료/미인증 | "인증 후 주소록을 사용할 수 있습니다." | 설정 이동 |

## 4. 개발/검증 체크리스트

- [ ] `OpsDirectory.fetch()` 실패 시 빈 결과를 반환하지 않고 오류를 구분한다.
- [ ] `_refresh()`는 실패 시 기존 `_directory`를 유지한다.
- [ ] 앱 재개/네트워크 변경 시 전체 fetch 대신 버전 메타 확인만 수행한다.
- [ ] `config_version`/`directory_version` 비교로 업데이트 배지를 표시한다.
- [ ] 강제 갱신은 `force_version` 변경 시에만 수행한다.
- [ ] OPS 콘솔 강제 갱신 액션은 감사 로그를 남긴다.
