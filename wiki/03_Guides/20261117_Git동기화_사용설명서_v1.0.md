## 3. `git-pull.sh` — 소스 가져오기

```bash
./scripts/git-pull.sh                    # 대화형 (기본)
./scripts/git-pull.sh --interactive      # 동일
./scripts/git-pull.sh --auto             # 현재 브랜치에서 자동 pull
./scripts/git-pull.sh --interactive -v   # 상세 출력
./scripts/git-pull.sh --help
```

### 동작 순서
1. **Fetch**: `git fetch --all --prune` (github/dev/prd 전체)
2. **브랜치 목록**: `scripts/pick_branch.py --list` 결과로 로컬 + remote-tracking 브랜치 표시
3. **현재 상태**: `git status --short` 출력
4. **브랜치 전환 + pull**:
   - 작업트리가 더티하면 자동 `stash` 후 checkout (아래 5장 참조)
   - `github/feature/X` 선택 시 `PULL_REMOTE=github`, 로컬 타깃 `feature/X`로 매핑 → detached HEAD 방지
   - `git pull <해당 remote> <로컬 브랜치>`
5. **상태 리포트**: HEAD, 최근 커밋 5개, 설정된 모든 remote의 behind/ahead

## 4. `git-push.sh` — 소스 올리기

```bash
./scripts/git-push.sh                          # 대화형 (기본)
./scripts/git-push.sh --interactive            # 동일
./scripts/git-push.sh --auto                   # 현재 브랜치 → 모든 remote
./scripts/git-push.sh --dry-run                # 실제 push 없이 탐지/선택만 확인
./scripts/git-push.sh --help
```

### 동작 순서
1. **Fetch**: `git fetch --all --prune`
2. **전체 브랜치 최신 커밋 탐지**: `refs/heads` + `refs/remotes`를 `committerdate` 내림차순 정렬
   - 최신 커밋 해시/일시/제목과 **동일 커밋을 가리키는 모든 ref**를 출력
   - 예: `dfe4ec40 (2026-11-17 17:03)` — `feature/addressbook-auth-secure-dev`, `dev/...`, `github/...`, `prd/...`
3. **브랜치 선택**: 번호 입력. 각 항목에 날짜·해시와 `(current)`, `(LATEST)` 표시. Enter = 현재 브랜치.
4. **자동 stash**: 작업트리 변경 감지 시 보존 (5장 참조)
5. **remote 선택**: `a) all` 또는 번호로 특정 remote. 대상은 해당 브랜치를 가진 remote만 후보로 표시.
6. **Push**: 각 remote에 `GIT_SSH_COMMAND="ssh -o ConnectTimeout=5 -o BatchMode=yes"` 적용, NAS 미도달 시 `SKIP`
7. **상태 리포트**: HEAD, remote별 behind/ahead, stash 복구 안내

### `--dry-run`
브랜치/remote 선택과 stash까지 수행하지만 실제 `git push`는 생략합니다. 탐지 결과와 선택 흐름을 안전하게 확인할 때 사용합니다.

## 5. 자동 stash (트래쉬) 동작과 복구

두 스크립트 모두 checkout 전에 `git status --porcelain`로 변경을 감지하면 다음을 수행합니다.

```bash
git stash push -u -m "git-pull.sh auto-stash YYYYMMDD_HHMMSS"
# 또는 "git-push.sh auto-stash ..."
```

- `-u` 옵션으로 **미추적 파일까지** stash합니다.
- push 스크립트의 경우 "stash된 변경은 push에 포함되지 않습니다" 경고가 함께 출력됩니다. 커밋한 뒤 재실행해야 반영됩니다.
- 완료 시 `STASH: 로컬 변경 보존됨 → 복구: git stash pop` 안내가 표시됩니다.

### 복구
```bash
git stash list                 # stash 이름/순서 확인
git stash pop                  # 최신 stash 복구 (stash 항목은 삭제됨)
git stash apply stash@{0}      # 항목을 남겨둔 채 적용
```

> **주의**: 스크립트는 **모든** 로컬 변경을 stash합니다. 스크립트 자체를 수정한 직후 실행하면 그 수정도 stash되므로, 실행 전에 커밋하거나 실행 후 `git stash pop`으로 복구하세요.

## 6. `git-sync.sh` — 커밋 + 3-way 동기화

```bash
./scripts/git-sync.sh "fix: 버그 수정" --no-deploy
./scripts/git-sync.sh --auto --no-deploy
./scripts/git-sync.sh --interactive --auto --no-deploy
./scripts/git-sync.sh --status
```

- `git add -A`로 전체 스테이징 → 커밋 → github/dev/prd 순차 push → `scripts/log.py` 기록.
- `--no-deploy`: PRD 배포 생략 (현재 PRD 배포 파이프라인 없음).
- 실행 전 `git status --short`로 포함될 파일을 반드시 확인하세요.

## 9. 문제 해결

| 증상 | 원인 | 조치 |
|------|------|------|
| `origin/... not found` | 클라이언트에 `origin` 없음 | `github/...`로 교체 |
| `checkout failed (local changes?)` (구 버전) | 더티 워크트리 | 최신 스크립트는 자동 stash 처리 |
| `push`가 `SKIP`됨 | NAS 대역 미도달 | GitHub만 동기화, 네트워크 복구 후 재실행 |
| `detached HEAD` | remote-tracking ref 직접 checkout | 최신 스크립트는 로컬 브랜치로 자동 매핑 |
| stash 복구 충돌 | pull 후 같은 파일 변경 | `git stash pop` 후 충돌 해결 |
