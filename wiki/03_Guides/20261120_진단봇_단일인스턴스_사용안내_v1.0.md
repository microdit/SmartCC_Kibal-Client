# 6700 진단봇 단일 인스턴스 사용 안내

| 항목 | 내용 |
|------|------|
| **작성일** | 2026-11-20 |
| **버전** | v1.0 |
| **대상** | SmartCC_Kibal 서버(DEV `192.168.11.5`) / 6700 테스트 회의실 진단봇(7001) |
| **관련 스크립트** | `SmartCC_Kibal/scripts/restart-diag-bot.sh`, `SmartCC_Kibal/tests/diagnostic-bot/diag-room-bot-daemon.mjs` |

---

## 1. 목적

슬립/웨이크 또는 세션 끊김 이후에도 **6700 회의실에 AI봇(7001)이 정확히 하나만 상주**하도록 보장한다. 기존에는 진단봇 프로세스가 중복되거나 오래된 ConfBridge 채널이 남아 영상 소스가 꼬이고, 사용자가 "원격 영상이 없다"고 체감하는 문제가 반복됐다.

---

## 2. 구성

| 요소 | 경로 | 역할 |
|------|------|------|
| 관리 스크립트 | `scripts/restart-diag-bot.sh` | 프로세스/채널 상태 확인, 정리, 단일 재기동 |
| 데몬 | `tests/diagnostic-bot/diag-room-bot-daemon.mjs` | 7001 계정으로 6700 입장 후 1920x1080 테스트 영상 송출 |
| PID lock | `/tmp/kibal-diag-bot.lock` | 중복 실행 차단 |
| 로그 | `/tmp/kibal-diag-bot.log` | 등록/입장/송출 및 재연결 이력 |

데몬은 재연결 직전 `PJSIP/7001-*` 잔류 채널을 자동 hangup한다. 즉 슬립/웨이크 후 이전 세션이 남아 있어도 새 세션이 정리하고 입장한다.

---

## 3. 사용법

서버 리포지토리 최상위에서 실행한다.

```bash
cd ~/Downloads/dev/SmartCC_Kibal

./scripts/restart-diag-bot.sh status    # 상태만 확인
./scripts/restart-diag-bot.sh ensure    # 비정상이면 자동 재기동 (기본값)
./scripts/restart-diag-bot.sh restart   # 강제로 정리 후 단일 인스턴스 재기동
./scripts/restart-diag-bot.sh stop      # 봇 프로세스와 7001 채널만 정리
```

인자를 생략하면 `ensure`로 동작한다.

```bash
./scripts/restart-diag-bot.sh
```

### 3.1 정상 출력 예

```
>>> mode=status pids=[8396 ] count=1
>>> channels=[PJSIP/7001-00000024 ]
Channel                        Flags  User Profile ...
PJSIP/7001-00000024                   kibal_user   kibal_bridge ...
>>> HEALTHY
```

`HEALTHY`는 **프로세스 1개 + 6700에 7001 채널 1개**를 의미한다.

---

## 4. 슬립/웨이크 대응 절차

1. 서버/클라이언트가 슬립 후 재개되면 먼저 상태 확인:
   ```bash
   ./scripts/restart-diag-bot.sh status
   ```
2. `HEALTHY`가 아니면:
   ```bash
   ./scripts/restart-diag-bot.sh restart
   ```
3. 데몬 로그에서 재연결 확인:
   ```bash
   tail -20 /tmp/kibal-diag-bot.log
   ```
   정상 문구: `diag-bot 7001 in 6700: video=[[...{"kind":"video","state":"live","w":1920,"h":1080}]]`
4. 클라이언트 앱에서 6700을 나갔다 다시 입장한다.

> 정상 세션 중에는 `ensure`를 주기적으로 호출해도 아무 동작을 하지 않는다. 통화가 끊기지 않으므로 watchdog/cron에서 사용해도 안전하다.

## 5. 문제 해결

| 증상 | 확인 | 조치 |
|------|------|------|
| 6700에 AI봇이 안 보임 | `status`가 `UNHEALTHY` | `restart` 후 앱에서 6700 재입장 |
| 봇 프로세스가 2개 이상 | `pids=[...] count=2` | `restart` — PID lock과 함께 정리됨 |
| 7001 채널이 2개 이상 | `channels=[PJSIP/7001-..., PJSIP/7001-...]` | `restart` — 잔류 채널 hangup 후 재등록 |
| 로그에 `already running` | 다른 데몬이 이미 살아 있음 | 정상. 중복 실행이 차단된 것 |
| 로그에 `browser.newContext ... closed` | Chromium 종료 후 재시도 중 | 데몬이 브라우저를 재실행함. 회복 안 되면 `restart` |
| `Operation not permitted` | `~/Downloads` 접근이 차단된 launchd 등에서 실행 | 사람이 터미널에서 실행할 것. launchd watchdog은 TCC 문제로 사용하지 않음 |

## 6. 검증 명령

```bash
pgrep -fl diag-room-bot-daemon
docker exec kibal-dev-asterisk asterisk -rx 'confbridge list 6700'
docker exec kibal-dev-asterisk asterisk -rx 'core show channels concise' | grep PJSIP/7001
tail -20 /tmp/kibal-diag-bot.log
```

기대값: `node diag-room-bot-daemon.mjs` 프로세스 1개, 7001 채널 1개, 로그에 1920x1080 송출 기록.

## 7. 주의사항

- OPS 8091은 외부에 개방하지 않는다. 봇은 내부망 `http://192.168.11.5:8091`만 사용한다.
- 미디어 원본(`media/diag_hwasa_04_full.mp4`, 362MB)은 git 제외이며 서버 로컬에 유지된다. 삭제하면 봇이 기동하지 않는다.
- 수동 종료는 `pkill -f diag-room-bot-daemon.mjs`로 해도 되며, 시그널 핸들러가 lock 파일을 정리한다.
- launchd watchdog은 macOS TCC가 `~/Downloads`를 차단해 제거됐다. 자동화가 필요하면 Full Disk Access를 부여한 별도 실행 경로를 검토한다.
