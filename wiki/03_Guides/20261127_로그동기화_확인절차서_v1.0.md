## 1. 목적과 확인 대상

로그 동기화는 아래 두 축을 분리해 확인한다.

| 구분 | 저장 위치 | 판정 기준 |
|---|---|---|
| 커밋 로그 | Git의 `wiki/07_Logs`, `docs/_작업이력` | 로컬 HEAD와 원격 브랜치가 같고, 원격에 최신 로그 내용이 존재 |
| 런타임 클라이언트 로그 | OPS `<ext>.log` + `<ext>.meta.json`, NAS `<ext>_YYYYMMDD.txt` | OPS `mirror_ok=true`, OPS/NAS 최신 로그 시각 일치, NAS 파일 갱신 |

AI 작업자의 커밋 로그는 Git 로그 축에 해당한다. AI봇 확장자 `7001`의 런타임 로그는 별도 축이며, 클라이언트 로그 파이프라인에 파일이 없다고 해서 커밋 로그 동기화 실패로 판정하지 않는다.

- NAS SMB 경로: `/Volumes/NetBackup/보관함/개발/Live_Log`
- OPS 컨테이너: `kibal-dev-ops`
- 모든 확인은 read-only로 수행한다. 서비스 재시작·채널 정리·파일 삭제는 포함하지 않는다.


정상 기준: OPS `status=ok`, NAS SMB 마운트 확인.

## 4. 런타임 클라이언트 로그 동기화 확인

### 4.1 OPS 미러 상태

```bash
curl -fsS --max-time 10 \
  -H "X-Client-Key: $OPS_CLIENT_KEY" \
  "$OPS_URL/api/client-logs/mirror-status"
```

정상 기준:

- `enabled=true`
- `mounted=true`
- `writable=true`
- `last_error=null`
- `path=/var/lib/kibal-ops/live-log-mirror`

`401`이면 키 설정/내선 바인딩을 확인한다. 키를 응답 본문이나 보고서에 붙여넣지 않는다.

### 4.2 OPS 로컬 파일·메타

OPS는 누적 `<ext>.log`와 `<ext>.meta.json`을 저장한다.

```bash
docker exec kibal-dev-ops stat -c '%y %s %n' \
  "/var/lib/kibal-ops/client-logs/$EXT.log" \
  "/var/lib/kibal-ops/client-logs/$EXT.meta.json"

docker exec kibal-dev-ops python3 -c '
import json, pathlib
root = pathlib.Path("/var/lib/kibal-ops/client-logs")
ext = "'"$EXT"'"
meta = json.loads((root / f"{ext}.meta.json").read_text())
keys = ("last_seen", "last_session", "mode", "host", "ip", "app_version", "mirror_ok", "mirror_reason")
print(json.dumps({k: meta.get(k) for k in keys}, ensure_ascii=False))
print("\n".join((root / f"{ext}.log").read_text(errors="replace").splitlines()[-5:]))
'
```

정상 기준:

- `.log`와 `.meta.json`이 존재한다.
- `mirror_ok=true`, `mirror_reason=null`
- `last_seen`이 최근 활동 시각과 일치한다.
- 말미 로그에 해당 내선 `usr=<EXT>`와 최근 이벤트가 보인다.

### 4.3 NAS 일자별 미러

```bash
DAY=$(date +%Y%m%d)
NAS_LOG="/Volumes/NetBackup/보관함/개발/Live_Log/${EXT}_${DAY}.txt"

stat -f '%Sm %z %N' -t '%Y-%m-%d %H:%M:%S' "$NAS_LOG"
tail -n 8 "$NAS_LOG"
```

정상 기준:

- 파일이 존재하고 수정 시각이 최근 OPS 수신 시각 이후의 가까운 시각이다.
- 말미 로그의 timestamp/이벤트가 OPS `.log` 말미와 일치한다.
- OPS `.log`는 누적 파일이고 NAS 파일은 일자별 파일이므로 파일 크기/바이트 수 일치는 판정하지 않는다.

### 4.4 종합 판정

| 조건 | 판정 |
|---|---|
| OPS `mirror_ok=true` + NAS 파일 존재 + 최신 로그 일치 | 동기화 정상 |
| OPS 로그는 있지만 NAS 파일 없음 | 미러 실패/경로 문제 |
| NAS 파일은 있지만 OPS `mirror_ok=false` | 부분 실패, OPS 저장은 유지 |
| OPS/NAS 모두 오래된 timestamp | 클라이언트 종료/전송 지연/네트워크 확인 |
| API `401` | 인증 문제, 로그 유실과 별개 |
| `7001.log`/NAS `7001_YYYYMMDD.txt` 없음 | AI봇 런타임 로그는 별도 경로 확인 필요 |

## 6. 문제별 조치

### `origin/<branch> is not a commit`

```bash
git fetch origin
git branch -r --list "origin/$BRANCH"
git checkout -b "$BRANCH" "origin/$BRANCH"
```

### OPS 미러 상태 API `401`

- `OPS_CLIENT_KEY` 환경변수 설정 확인
- 해당 내선의 client-key 바인딩 확인
- 키 자체는 보고하지 않음

### OPS는 저장되나 NAS 파일이 없음

- `mount | grep -i NetBackup`
- `/api/client-logs/mirror-status`의 `mounted/writable/last_error`
- OPS 컨테이너의 `/var/lib/kibal-ops/live-log-mirror` 마운트 확인
- 서비스 재시작 없이 먼저 원인 기록

### 클라이언트 로그가 오래됨

- 앱 실행 여부, 로그 전송 모드/주기(1~60분), 네트워크/OPS URL 확인
- 최근 로그의 `usr=`와 `app_version` 확인
- 통화/통화 품질 이슈는 별도 보고서로 분리

## 8. 안전 규칙

- read-only 확인만 수행한다.
- 토큰·client key·전체 webhook URL을 문서/커밋/보고에 포함하지 않는다.
- `git add -A`, 승인 없는 force push, 버전 임의 상향을 금지한다.
- 검수 전 문서는 TEST 브랜치에만 커밋/푸시한다.
- raw 로그 전체를 wiki에 붙여넣지 않고 최소 timestamp/상태/경로만 기록한다.
