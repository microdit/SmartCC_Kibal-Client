## 1. C — A10(1201) 원격 영상 수신

| ID | 시나리오 | 절차 | 기대 결과 | 확인 로그/명령 |
|----|---------|------|----------|----------------|
| TC-C1 | 채널 스냅샷 | 6100 통화 중 `core show channels` | `PJSIP/1103-*`, `PJSIP/1201-*` 2채널 Up | `2 active calls` |
| TC-C2 | SDP/스트림 | `core show channel PJSIP/1201-<id>` | `video-1 State: sendrecv`, `Formats: (h264)`, `max_video_streams=1` | `NativeFormats: (g722\|h264)` |
| TC-C3 | 코덱·트랜스코딩 | 동일 명령 | 오디오 `g722↔slin48` 트랜스코딩, 영상 h264 passthrough | `WriteTranscode`, `ReadTranscode` |
| TC-C4 | 발화자 전환 | 1103이 발화 → 정지 → A10이 발화 | A10 화면에 1103 영상이 표시되는 구간 특정 | `confbridge list 6100` Flags 열 |
| TC-C5 | 수신 바이트 | A10 수신 RTP 계측 | 30초간 inbound video `bytesReceived` 단조 증가 | `pjsip show channel`, `rtp set debug` |
| TC-C6 | 방향 대조 | 1103 OPS 로그 확인 | `in=1920x1080@30fps`, `videoKB≈183`, `ice=Completed` → 1103 수신은 정상 | `1103.log` tail |
| TC-C7 | 제약 확인 | `pjsip show endpoint 1201` | `max_video_streams=1`, `max_audio_streams=1` | 템플릿 `:143-146` |

**C 합격**: A10 화면에 원격(1103/발화자) 영상 표시 + `bytesReceived` 증가.
**C 판정 (23:15 실기 갱신)**: 발언자 **1201 자동설정** + 1103에 발언자 영상 표시 + 음성 수신 확인 → `follow_talker` **정상**, 후보 ①(발화자 영상 미전달) **기각**. `confbridge list`의 빈 `Flags`는 talker 미선정이 아님(Flags는 사용자 플래그만 표시). `Enable Events: no`도 영상 전달과 무관 → **브리지 설정 변경 불필요**.
**C 잔여**: TC-C4를 아래 2건으로 대체한다.
- TC-C8: **A10(1201) 실제 화면 캡처** → 스피너/자기 영상/1103 영상 판별
- TC-C9: **발화자 전환**(1201 음소거 또는 1103 발화) 후 A10에 1103 영상 표시 여부 → 표시되면 `max_video_streams=1` + `follow_talker`의 설계상 정상으로 확정

> 상세: [[wiki/08_Experiments/20261112_C_발화자영상_검증_v1.0]]. 지금까지 증거는 **A10→1103 방향**이며 최초 증상은 **1103→A10 방향**임에 유의.

## 2. A — `1102 → 1103` 404

| ID | 시나리오 | 절차 | 기대 결과 |
|----|---------|------|----------|
| TC-A1 | 근거 대조 | `messages:1261-1265`의 `16:05:02/19 UTC` ↔ `1102.log` `01:05:02/19 KST` | 9시간 차이로 정확히 일치 |
| TC-A2 | 인증 대조 | `security:2200-2203` | `AccountID=1102`, `SessionID=tbfvf26b36uh2r533965` / `tbfvf7ln6ut8zb0ed70v` = 호 ID 앞 20자 |
| TC-A3 | 실패 메시지 | 동일 시각 | `Could not create dialog to invalid URI '1103'. Is endpoint registered and reachable?` + `Failed to create outgoing session` |
| TC-A4 | 미등록 확인 | `pjsip show contacts` / `1103.log` | 해당 시각 1103 contact 없음, `security`에 1103 인증 없음 |
| TC-A5 | self-call 배제 | `1102.log:269` | `01:05:29.986868 callPressed target=1102` → 이후 착신은 1103이 아닌 자기 호출 |
| TC-A6 | 재현(갱신 중) | `pjsip set logger on` → 1103 재로그인/로그아웃 반복 → 1102에서 발신 | `remove_existing=yes` contact 공백 구간 실측 |
| TC-A7 | 재현(만료 직후) | 1103 강제 종료 → `default_expiration=3600` 경과 전후 발신 | 404 재발 시점 특정 |
| TC-A8 | 회귀 | 1103 등록 직후 / 갱신 중 / 만료 직후 3시점 발신 | 3시점 모두 200 OK 또는 명시적 실패(404 아님) |

```bash
docker exec kibal-dev-asterisk asterisk -rx 'pjsip set logger on'
docker exec kibal-dev-asterisk sh -c 'grep -n -m 30 -E "Could not create dialog|No contact|404" /var/log/asterisk/messages'
docker exec kibal-dev-asterisk asterisk -rx 'pjsip set logger off'   # 진단 후 필수
docker exec kibal-dev-asterisk sh -c 'grep -n -m 20 "AccountID=\"1103\"" /var/log/asterisk/security'
```

**A 합격**: 3시점 모두 연결 성공. **분기**: contact 공백 재현 → 서버 AOR 정책 변경 / 미재현 → 클라이언트 WS 재연결 시 재REGISTER 보장.

## 4. B — 장시간 통화 품질

| ID | 시나리오 | 절차 | 기대 결과 |
|----|---------|------|----------|
| TC-B1 | 60분 통화 | 1102 → 6000, 60분 유지 | out fps ≥ 25 유지, `session(video)` 누적 없음 |
| TC-B2 | in/out 분리 | 30초 요약 수집 | `in=1280x720@30fps`, `decodedFrames+900`, `videoKB≈9185` 일정 |
| TC-B3 | fps 붕괴 재현 | `02:44–02:46` 상당 구간에서 CPU/인코더 사용률 동시 계측 | `out=12~16fps`일 때 CPU 포화 여부 상관 확인 |
| TC-B4 | 손실 버스트 | 의도적 패킷 손실 또는 Wi-Fi 이동 | `pli`/`keyframes` 회복 로그, `nack` 동작 여부 |
| TC-B5 | 해상도 하향 | ~~`01:15:03` 상당 시점 경로 특정~~ → **완료(B3 코드 추적)** | `videoConstraints`/`lowVideoConstraints` 미사용 확인, `media_manager.dart:203-204` 1280x720 하드코딩 → **WebRTC 인코더 자체 적응**으로 결론. 앱 코드 경로 아님 |
| TC-B6 | 첫 키프레임 | 6000 연결 직후 60초 | `videoKB=97 → 3181 → 9176` 전이, `pli=1` → 첫 키프레임 도착 시점 기록 |

```bash
./scripts/ops_client_logs.sh grep 1102 "SIP video summary" 40
./scripts/ops_client_logs.sh grep 1102 "SIP media summary" 40
```

**B 합격**: 60분 통화 out fps ≥ 25, 손실 버스트 후 `pli` 회복, 누적 카운터 정상 증가.

> **판정 주의**: `freeze`/`vLost`/`pli`/`nack`/`keyframes`는 getStats **누적 카운터**다. 값이 고정이면 "갱신 정지"가 아니라 **해당 이벤트가 0건**이라는 뜻이다. `decodedFrames+N`만 30초 델타다.
