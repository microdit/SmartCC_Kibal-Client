## 1. 목적

Client 저장소도 Server와 동일하게 DEV/TEST/PRD/EXTERNAL 분리 원칙을 따른다. 검수 전 변경은 TEST로 격리하고, 검수 PASS 후 DEV 승격한다.

## 2. 환경 매핑

| 환경 | GitHub repo | remote | 기준 브랜치 | 용도 |
|---|---|---|---|---|
| DEV | `microdit/Smart_Kibal-Client-DEV`(신규 예정) 또는 기존 `SmartCC_Kibal-Client` DEV 기준선 | `dev-gh` | `dev` | 검수 PASS 후 승격 |
| TEST | `microdit/Smart_Kibal-Client-TEST`(신규 예정) | `test-gh` | `test` | 검수 전/검수 중 |
| PRD | `microdit/Smart_Kibal-Client-PRD`(신규 예정) | `prd-gh` | `main` | 승인 후 승격 |
| EXTERNAL | `microdit/Smart_Kibal-Client-EXTERNAL`(신규 예정) | `external-gh` | `external` | 외부망 검증 |
| 레거시 | `microdit/SmartCC_Kibal-Client` | `origin` | 기존 | 전환 기간 참조/미러, 기준선 직접 오염 금지 |
| 레거시 NAS | NAS SSH | `dev`, `prd` | 기존 | 대역 미도달 시 SKIP |

> 2026-11-26 기준 Client용 4환경 GitHub repo는 아직 미생성일 수 있음. 생성 전에는 `origin`의 `test/<topic>` 브랜치로 격리하고, DEV/PRD 승격 금지.

## 3. 승격 흐름

```text
test/<topic> (검수 전)
  -> analyze/test/build/DMG/SHA256/실기 증거
  -> TEST PASS
  -> DEV 승격
  -> 안정화
  -> PRD/EXTERNAL 승인 후 승격
```

## 4. 버전/릴리스 사고 방지

- 버전 상향 전 `git fetch --all --prune`, 태그/remote 최신 커밋 확인.
- NAS `dev/prd` 또는 기준선이 선행하면 **선행 커밋 보존 + 기능 누락 확인 + 버전 상향**. 단순 역행 덮어쓰기 금지.
- DMG/앱 산출물 변경 시 버전/빌드번호 상향, `release_macos.sh` 산출물, SHA256, codesign 검증, wiki 로그 필수.
- 검수 전 빌드는 TEST 브랜치 산출물로만 취급. 검수 PASS 전 DEV/PRD/NAS 배포 금지.

## 5. 로컬 규약

- `git status --short` 먼저 확인. `git add -A` 금지.
- 무관 수정/untracked는 분리: commit / stash(WIP) / 폐기 / 로컬전용.
- 대용량 raw 로그/개인 캡처는 기본 커밋 제외, 요약 보고서만 wiki 커밋.
- active call 또는 실기 검증 중이면 파괴적 정리/재시작 금지.
