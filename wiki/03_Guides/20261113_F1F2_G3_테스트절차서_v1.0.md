

## 1. F1 — 발신 타깃 코덱 정책

| ID | 시나리오 | 절차 | 합격 기준 |
|----|---------|------|-----------|
| T-F1-1 | 정적 검증 | `cd macos-client && flutter analyze && flutter test` | analyze 0건, 테스트 전 통과 |
| T-F1-2 | 정책 로그 | v0.0.24로 `1103 → 1201` 1:1 발신 | OPS `1103` 로그에 **`SIP codec policy target=1201 type=offer video=h264First`** |
| T-F1-3 | 서버 코덱 정합 | 통화 중 `core show channel PJSIP/1103-*` / `PJSIP/1201-*` | 양 leg `video-1 State: sendrecv`, **`Formats: (h264)`** 동일. `NativeFormats`에 `vp8` 없음 |
| T-F1-4 | 오류 소멸 | `messages` 최근 타임스탬프 확인 | 신규 `Don't know how to send format vp8/h264 packets with RTP` **0건**(마지막은 `15:41:51 UTC` = `00:41:51 KST`) |
| T-F1-5 | 실기 화면 | 1:1 통화 중 A10 확인 | **원격 영상 표시** + 셀프 영상 정상 + 음성 정상 |
| T-F1-6 | 회귀(6100) | `1103 → 6100` 발신 | `SIP codec policy target=6100 ... video=h264Only` 유지, 발언자 화면 정상 |
| T-F1-7 | 회귀(6000) | `1103 → 6000` 발신 | 정책 `keep`(VP8 우선) 유지, 3자 회의 정상 |
| T-F1-8 | 타깃 초기화 | 1201 통화 종료 → 6000 발신 | 6000에 `h264First`가 잘못 적용되지 않음(`_cleanupSession` 검증) |

## 2. F2 — A4 롤백

| ID | 시나리오 | 절차 | 합격 기준 |
|----|---------|------|-----------|
| T-F2-1 | 로그 소멸 | 1101 재로그인 / WS 재연결 유도 | **`SIP transport reconnected -> re-REGISTER` 로그 없음** |
| T-F2-2 | 루프 제거 | 1101 로그인 후 2분 관찰 | `close by local disconnected` ↔ `SIP 등록 시간 초과 또는 실패` 반복 **0회** |
| T-F2-3 | 등록 유지 | OPS `1101.meta.json` / `pjsip show contacts` | `registered` 1회, `Avail` 유지 |
| T-F2-4 | 실기 회의 | 1101로 6000 또는 6100 입장, **5분 유지** | 튕겨 나가지 않음, 참가자 카드 유지 |
| T-F2-5 | disconnect 진단 보존 | 강제 WS 끊김 | `SIP transport disconnected (cause: …)` 로그는 **남아 있음**(제거 대상 아님) |
| T-F2-6 | A5 회귀 | `pjsip show aor 1103` | `remove_existing=false` / `remove_unavailable=true` / `qualify_frequency=15` 유지(ADR-004) |

> 대조 기준: v0.0.23 `1101_MacPro로그.txt`의 00:53:24~00:54:22 루프(15회+). 이 패턴이 재현되지 않아야 한다.
