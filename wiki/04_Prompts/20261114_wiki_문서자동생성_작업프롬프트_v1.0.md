## 1. 배경 (현재 자동화 범위와 한계)

`./scripts/git-sync.sh --auto`는 다음을 수행한다.
- `git add -A` → `scripts/generate-commit-msg.py`로 커밋 메시지 생성/커밋 → 등록된 모든 remote push(접속 불가 SSH skip).
- `generate-commit-msg.py`: staged diff 분석, `docs/_작업이력/{YYYY-MM-DD}.md`에 **Auto Commit** 섹션 append+stage(동일 hash 중복 방지). 존재 시 `scripts/wiki_agent.py --auto --skip-push` 호출 시도 후 재분석.

**한계(본 프롬프트가 보완)**
- `scripts/wiki_agent.py` **부재** → Wiki 레이어별 문서(설계서/테스트/보고/실험/결정/지식) 자동 생성 미동작.
- `wiki/07_Logs/작업로그_YYYYMMDD.md` 갱신·`docs/AGENTS.md` 현재 진행 갱신은 자동화되지 않음.
- ChromaDB 벡터 인덱싱(`scripts/index_wiki.py`/`agent_wiki_vector.py`)은 git-sync에 포함되지 않아 수동 실행 필요.

> 본 프롬프트로 생성/갱신한 문서는 **추후 검토 대상**이다. 불확실한 내용은 추측하지 말고 “미확인/추정/실기 필요”로 명시한다.

## 2. 사용 방법

아래 **[실행 프롬프트]** 섹션 전체를 AI 코딩 에이전트에 전달한다. 작업 범위를 좁히려면 “이번 작업 요약/대상 커밋/변경 파일/요구 산출물”을 추가로 명시한다.

- 입력: 이번 세션 작업 내용, 관련 커밋/이슈, 변경 파일 목록, 테스트/빌드 결과, 실기 제약.
- 출력: Wiki 문서 생성·갱신 + `docs/AGENTS.md`/`docs/_작업이력`/`wiki/07_Logs` 반영 + (지시 시) git 커밋·push 동기화.

| 04 | `wiki/04_Prompts/` | 후속작업/자동화 프롬프트 | 반복 수행할 에이전트 작업 지시 |

**배치 판단 팁**
- “어떻게 테스트/수행하는가(절차)” → 03_Guides, “무엇을 관측/검증했고 결과가 무엇인가(증거·판정)” → 08_Experiments 또는 06_Reports.
- 미해결/실기 대기는 08_Experiments(현황) 또는 계획서에 상태로 남기고, 확정 결론은 06_Reports/05_Decisions로 승격.

## 4. 파일명·메타 규칙

- **기본 형식**: `YYYYMMDD_주제_vX.Y.md` (한글 주제 허용, 공백 대신 `_` 권장). 기존 관례 파일(예: `작업로그_YYYYMMDD.md`, ADR 파일명)은 해당 관례 유지.
- **문서 상단 메타 표(권장)**:

| 항목 | 내용 |
|------|------|
| **문서 ID** | `<TYPE>-YYYYMMDD-<KEY>-NNN` |
| **작성일** | YYYY-MM-DD (필요 시 HH:MM KST) |
| **상태** | 초안/진행/완료/보류(사유)/실기대기 |
| **관련** | `[[wiki/...]]`, 커밋/태그, 이슈, DMG/해시 등 |

- **상호 참조**: `[[wiki/레이어/파일명]]` 형태 사용. 서버(`SmartCC_Kibal`) 산출물은 경로/리포를 명시해 구분.

## 5. 문서 유형별 최소 템플릿

### 5.1 계획서 (01_Projects)
- 배경/목표, 범위(In/Out), 순번·WBS(담당/의존/상태), 산출물, 리스크·전제(승인/실기/NAS/통화창구), 일정·마일스톤.

### 5.2 설계서 (02_Design)
- 문제/요구, 현행 구조, 제안 설계(흐름·인터페이스·데이터·상태), 호환/마이그레이션, 영향 범위, 검증 포인트, 미결 사항.

### 5.3 테스트 절차서/가이드 (03_Guides)
- 전제(버전/빌드 해시/환경/계정), 사전 준비, 단계별 절차(입력·기대·관측 포인트), 로그 수집 위치(KST/UTC 병기 등), 판정 기준(Pass/Fail), 롤백/주의.

### 5.4 ADR (05_Decisions)
- 상태(Proposed/Accepted/Deprecated), 맥락, 결정, 대안, 근거/트레이드오프, 결과·후속.

### 5.5 보고서 (06_Reports)
- 요약, 범위/환경, 수행 내용, 결과·증거(로그/해시/스크린샷 참조), 원인 분석, 결론, 잔여/후속.

### 5.6 작업로그 (07_Logs, `작업로그_YYYYMMDD.md`)
- 일자/대상, 절 단위(번호·시각 선택)로 **지시/원인/조치/검증(테스트·빌드·해시)/발행(DMG·태그·커밋)/제약·후속** 기록. append 방식, 기존 내용 보존.

### 5.7 실험/현황 (08_Experiments)
- 목적·가설/검증 항목, 환경·빌드 식별, 절차/관측, 결과(정량/정성), 판정, 차단·다음 액션.

### 5.8 지식 (09_Knowledge)
- 정의/증상/원인/해결/재현 조건/참조 링크(간결·재사용 중심).

## 6. [실행 프롬프트] — 에이전트에게 전달

```text
당신은 SmartCC_Kibal-Client 리포지토리의 문서화 에이전트다. wiki_agent.py가 없으므로 아래 규칙에 따라 Wiki 문서를 생성·갱신한다.

[컨텍스트 수집]
1) `git status --short`, `git log --oneline -10`, (필요 시) `git diff`로 변경 범위 파악.
2) `docs/AGENTS.md`, 오늘 `docs/_작업이력/YYYY-MM-DD.md`, `wiki/07_Logs/작업로그_YYYYMMDD.md` 최신 내용 확인.
3) 관련 기존 문서(`wiki/01~09`, `wiki/03_Guides`, `docs/보고서` 등) 검색해 중복 생성 방지·갱신 우선.

[분류·생성]
4) 변경/작업을 분류해 필요한 문서만 생성/갱신: 계획(01), 설계(02), 절차·테스트가이드(03), 프롬프트(04), ADR(05), 보고(06), 로그(07), 실험·현황(08), 지식(09).
5) 파일명 `YYYYMMDD_주제_vX.Y.md` 및 메타 표(문서ID/작성일/상태/관련) 사용. 기존 관례 파일명은 유지.
6) 사실/측정(테스트 수, 빌드, SHA256, 커밋/태그, 서버 관측 시각 KST/UTC) 기반 기록. 미실행·미검증·추정은 “미확인/실기 필요/추정”으로 명시.

[필수 동반 갱신]
7) `wiki/07_Logs/작업로그_YYYYMMDD.md`에 오늘 절 append(지시·원인·조치·검증·산출물·커밋/태그·제약·후속).
8) `docs/_작업이력/YYYY-MM-DD.md`에 작업 요약 append(자동 Auto Commit 로그와 별개로 사람이 읽을 요약 유지).
9) 진행/차단/다음 단계가 바뀌면 `docs/AGENTS.md`의 현재 진행·참조 문서 갱신.

[제약]
10) 사용자가 지정하지 않은 기존 미커밋/무관 파일은 수정·스테이징하지 않는다.
11) NAS(dev/prd) 미접속/미지시 시 origin 기준 동기화. 커밋/푸시는 명시적 요청이 있을 때만 수행(요청 시 포함 파일 확인 후 `git add <명시 파일>` 권장; `--auto`는 `git add -A`이므로 주의).
12) 비밀키/토큰/개인정보를 문서에 기록하지 않는다.

[커밋·동기화(요청 시)]
13) 문서/코드 변경을 논리 단위로 커밋(`docs:`/`feat:`/`fix:`/`release:` 등)하고 `git push origin <branch>`(+필요 시 태그). `./scripts/git-sync.sh --auto --no-deploy` 사용 시 스테이징 범위를 사전 확인.

[선택]
14) 문서 갱신 후 의미검색 최신화가 필요하면 `python scripts/index_wiki.py --reindex` 실행 가능 여부(venv/의존성)를 확인 후 수행.

[출력]
- 생성/갱신한 파일 목록, 각 문서 배치 사유(레이어), 검증 결과, 커밋/푸시 결과, 미확인·후속 항목을 요약 보고한다.
```
