## 3. 1차 검증 절차 (그대로 실행)

### 3.1 서버 상태/캡처

```bash
cd /Users/microdit/Downloads/dev/SmartCC_Kibal-Client

# pjsip logger + rtp debug + 10초 스냅샷 + docker logs 수집
./scripts/capture_remote_audio.sh 600 6000

# 별도 터미널: 채널/참가자 실시간 확인
docker exec kibal-dev-asterisk asterisk -rx "confbridge list 6000"
docker exec kibal-dev-asterisk asterisk -rx "pjsip show channelstats"
```

### 3.2 테스트 시나리오

- **A**: 1101(음성) + 1102(영상) 2자, 6000 입장 → 60초 유지
- **B**: 1101 + 1102 + 1103 3자 → 60초 유지
- 각 단말 로그: `~/Library/Containers/com.microdit.macosClient/Data/Library/Application Support/com.microdit.macosClient/logs/app.log`
- 사용자는 테스트 로그를 `docs/테스트/`에 새 버전으로 저장해 전달

### 3.3 추출할 증거 (서버)

```bash
docker logs kibal-dev-asterisk --since <시작시각> 2>&1 \
  | grep -E "c=IN IP4|a=candidate|m=audio|m=video|a=setup|a=fingerprint|Got  RTP|Sent RTP"
```

확인 포인트 (H5 수정 검증):

| 질문 | 판정 |
|------|------|
| re-INVITE(`CSeq ... INVITE`)에 클라이언트가 **200 OK(SDP)** 를 보냈는가? | v0.0.8 로그에 `SIP re-INVITE 수신 ... -> 자동 수락`, `응답 전송 accepted=true` 확인 |
| 서버가 영상 RTP를 **송신**하는가? | `Sent RTP packet to ... (type 100,` 존재해야 함 |
| 클라이언트 `videoBytes`가 증가하는가? | 0이면 서버 SFU 영상 송신 문제 |
| `ICE Connection Failed`가 사라졌는가? | 0건이어야 함 |
| 3자에서 1명이 튕기는가? | `confbridge list`/`channelstats`로 교차 확인 |

## 4. 가설과 분기 (H5 이후)

| 관찰 | 원인 후보 | 조치 |
|------|----------|------|
| 200 OK는 보내지만 여전히 ICE 실패 | 후보 보정/DTLS 재협상 | 재-INVITE answer의 `c=`/후보/`fingerprint` 확인 |
| 200 OK 후 `videoBytes=0` 지속 | ConfBridge SFU 영상 송신 문제 | `Sent RTP type 100` 확인, `video_mode`/비디오 소스 점검 |
| 3자에서만 1명 튕김 | ConfBridge SFU/포트 충돌 | 서버 채널별 RTP/참가자 로그 |
| 오디오 단독 회귀 | 변경 부작용 | 1101 단독 60초 즉시 재확인 |
| re-INVITE 응답 지연 | `accept` 콜백 예외 | 앱 로그 `re-INVITE 수락 실패` 확인 |

## 5. 구현 가이드 (적용 완료)

- `macos-client/lib/src/sip/sip_client.dart`: `onNewReinvite` → `event.accept({})` 자동 호출
- `macos-client/packages/sip_ua/lib/src/rtc_session.dart`: `upgradeToVideo` 중복 video track 방지
- 빌드: `cd macos-client && ./scripts/build_macos.sh release` → v0.0.8
- 후보 보정 일반화(`candidateRewriteAddress`)는 **H5와 무관**하므로 보류. 서버가 도달 가능한 후보를 광고하게 되면 재검토.

## 6. 금지/주의

- `webrtc=yes`로 되돌리지 말 것 (`ice_support`를 덮어씀)
- `ice_support=no`로 끄지 말 것 (클라이언트 488)
- PRD에 `dtls_verify=fingerprint`를 그대로 적용하지 말 것 (인증서 정책 재검토)
- 오디오 단독 정상 케이스를 회귀시키지 말 것 — 매 변경 후 1101 단독 60초 테스트
- `onNewReinvite`에서 예외가 나도 이전 통화를 깨지 않도록 `accept` 실패는 로그만 남길 것
- NAS `dev`/`prd` remote 경로 문제는 이번 범위 밖
