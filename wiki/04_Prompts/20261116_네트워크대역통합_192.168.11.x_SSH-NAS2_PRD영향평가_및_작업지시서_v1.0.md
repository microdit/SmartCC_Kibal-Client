## 1. 배경 및 목표
- **현상**: 이중 NAT(Double NAT) 환경에서 PRD/NAS2(`192.168.11.2`)에 대한 SSH 접근 불가(개발 장비가 `192.168.0.x` 대역에 위치한 상태로 추정).
- **근거 문서 요지(v1.2)**:
  - IPTime2를 허브/AP 모드로 전환: WAN→LAN 포트 연결, IPTime2 DHCP 서버 중지, IPTime2 관리 IP를 `192.168.11.254` 등(`192.168.11.1`과 충돌 회피)으로 변경.
  - IPTime1(`192.168.11.1`, DHCP 활성)이 전 기기에 `192.168.11.x`를 할당. NAS2는 `192.168.11.2` 유지.
  - Mac Pro(DEV/Asterisk Docker)는 IPTime1 DHCP 예약(MAC 바인딩)으로 **고정 IP** 사용.
  - Docker 브릿지(`172.x.x.x`)는 영향 없으나, Asterisk/서비스 설정에 `192.168.0.3` 등 구 IP 하드코딩 시 신규 IP로 수정 필요.
- **확정 사항(2026-11-16, 실측 반영)**: DEV 서버(Mac Pro, KIBAL) 확정 IP **`<NEW_IP> = 192.168.11.5`**, 인터페이스 **`en1` / MAC `E4:50:EB:BA:2E:70`** (“Mac Pro 고정 Kibal”, 유선 LAN1 수동할당), `inet 192.168.11.5/24` 활성 확인. (참고: Mac Pro에 2개 랜카드 장착 — `.6`은 다른 NIC `A4:83:E7:BA:1F:D1`로 등록됨, DEV는 `.5`/E4:50:EB:BA:2E:70 기준)
