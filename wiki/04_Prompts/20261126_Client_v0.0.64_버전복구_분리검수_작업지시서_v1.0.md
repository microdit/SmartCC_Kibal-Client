## 1. 배경

Client 작업 에이전트 보고에 따르면, 로컬 Client 브랜치 버전이 NAS 원격보다 역행된 상태에서 빌드가 진행되었다.

| 항목 | 값 |
|---|---|
| Client repo | `/Users/microdit/Downloads/dev/SmartCC_Kibal-Client` |
| 로컬 브랜치 | `feature/external-network-access @ aac71569` |
| origin | `aac71569` (v0.0.58 보고) |
| dev/prd NAS | `df9432cc` (v0.0.63+64 보고) |
| 문제 | dev/prd가 로컬보다 5커밋 선행, 로컬 버전 역행 |

동시에 Server repo는 2026-11-26에 4환경 GitHub repo 분리를 확정했다. 따라서 Client도 **버전 복구**와 **환경 분리/검수 승격**을 분리해서 다뤄야 한다.

## 2. Server 측 현재 확정 사항 (반드시 인지)

| 환경 | Server GitHub repo | 기준 브랜치 | 규칙 |
|---|---|---|---|
| DEV | `microdit/Smart_Kibal-DEV` | `dev` | 검수 PASS 후 승격 |
| TEST | `microdit/Smart_Kibal-TEST` | `test` / `test-pending-verification` | 검수 전 작업 |
| PRD | `microdit/Smart_Kibal-PRD` | `main` | 승인 후 승격 |
| EXTERNAL | `microdit/Smart_Kibal-EXTERNAL` | `external` | 외부망 검증 후 승격 |

- 규약: `wiki/03_Guides/20261126_4환경_Git_운영규약_v1.0.md`
- Server 검수 전 커밋은 TEST에 반영함. DEV 기준선 직접 덮어쓰기 금지.
- active call > 0이면 파괴적 점검/정리/재시작 BLOCKED.

## 3. 목표

1. Client 버전을 실제 최신 기준으로 복구한다.
2. 6700 재입장 원격 트랙 누적 근본 수정이 포함된 빌드를 검증한다.
3. 검수 전 산출물을 TEST 성격 브랜치/검증 기록으로 분리한다.
4. 검수 PASS 후에만 DEV/NAS dev/prd 승격한다.

## 4. 권고 작업 순서

### Phase A - 사실 확인 (read-only)

```bash
cd /Users/microdit/Downloads/dev/SmartCC_Kibal-Client
git fetch --all --prune
git status --short --branch
git log --oneline --decorate -5
git log --oneline --decorate -5 dev/feature/external-network-access || true
git log --oneline --decorate -5 prd/feature/external-network-access || true
git describe --tags --always
```

확인 항목:

- `df9432cc`가 실제 dev/prd 최신인지.
- `v0.0.63+64` 태그/릴리스/DMG/SHA256가 있는지.
- 로컬 `aac71569` 대비 dev/prd 선행 커밋에 버전 외 기능 변경이 포함되는지.
- NAS remote 접근 가능 여부. 미도달이면 push SKIP 기록.

### Phase B - 분리 작업 브랜치 생성

검수 전 산출물은 현재 feature 브랜치에 직접 누적하지 말고 분리한다.

권고:

```bash
git switch -c test/client-v0.0.64-recovery
```

또는 Client repo에 4환경 remote가 아직 없으면, 기존 origin에 `test/*` 브랜치로 먼저 분리하고 이후 Server와 동일한 `*-DEV/TEST/PRD/EXTERNAL` repo 체계로 맞춘다.

### Phase C - 버전/코드 복구

1. `pubspec.yaml`: dev/prd 최신 확인 후 `0.0.64+65` 또는 확인된 다음 버전으로 설정.
2. `macos/Runner/Info.plist`: `CFBundleShortVersionString`, `CFBundleVersion` 동기화.
3. `release_macos.sh`가 pubspec 기준이면 중복 수동 변경 최소화.
4. 코드 변경은 버그 수정만 포함:
   - `media_manager.dart`: `clearRemoteSessions()` + 원격 트랙 상한 3개
   - `sip_provider.dart`: `onCallEnded` 콜백
   - `app.dart`: 연결
5. dev/prd 선행 커밋에 누락된 기능이 있으면 cherry-pick/merge로 반영 후 버전만 상향. 버전 역행으로 기능 유실 금지.

### Phase D - 빌드/검증

```bash
flutter analyze
flutter test
./scripts/release_macos.sh --no-bump
codesign --verify --deep --strict <app>
shasum -a 256 <dmg>
```

검수 기록 필수:

- 앱 버전, 빌드번호, DMG 파일명, SHA256
- 6700 재입장 시나리오: 재입장 전/후 원격 트랙 수, 영상 수신, 좀비 트랙 여부
- 필요 시 1101/1102/1103 실기 또는 probe 증거
- PJSIP/OPS/client 로그 위치

### Phase E - 문서/로그/색인

Client repo 기준:

- `wiki/07_Logs/YYYYMMDD.md` 또는 기존 로그 규약에 버전 복구/검수 기록
- 필요 시 `wiki/08_Experiments/`에 재입장 검증 기록
- `scripts/index_wiki.py --reindex`

Server 연동 영향이 있으면 Server repo에도 교차 참조 보고서 남김.

### Phase F - 커밋/푸시/승격

검수 전:

- 명시 파일만 stage (`git add -A` 금지)
- 커밋 메시지에 버전/원인/검증 포함
- TEST 성격 브랜치 또는 test remote에 push

검수 PASS 후:

- DEV 승격: origin/dev 또는 `Smart_Kibal-DEV` 대응 브랜치
- PRD/NAS prd 승격: 승인 후만
- NAS 미도달 시 SKIP 사유 기록

## 5. 금지 사항

- 검수 전 dev/prd 기준선을 덮어쓰는 push 금지.
- 버전만 올리고 dev/prd 선행 기능 누락 여부 미확인 금지.
- DMG 생성 후 SHA256/버전/로그 누락 금지.
- `git add -A` 금지.
- active call 중 서버 파괴적 조치 금지.

## 7. Server 에이전트 의견

- 이번 건은 “버전 사고 복구”와 “4환경 분리 정착”이 겹친다. **복구 빌드라도 TEST 검수 후 DEV 승격**이 맞다.
- Client도 Server와 같은 쌍 규약을 적용해야 한다. 최소한 브랜치명/릴리스 매니페스트/검수 증거를 맞춘다.
