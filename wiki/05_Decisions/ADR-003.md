## 1. 배경 (Context)

Web Client (Mobile Safari PWA)로 시작하나, iOS에서의 **백그라운드 전화 수신**은 다음과 같은 Apple의 제약으로 인해 불가능합니다.

| 제약 | 설명 |
|------|------|
| **5초 제한** | 백그라운드에서의 WebSocket/실시간 처리 최대 5~30초 |
| **WebRTC 제한** | Safari 백그라운드에서 WebRTC 세션 유지 불가 |
| **PWA 제한** | 설치된 PWA도 네이티브 Background Mode 지원 불가 |

고객사(특히 금융/증권)의 경우 **상시 전화 수신**이 필수적일 수 있습니다.

## 2. 결정 (Decision)

### 2.1 단계적 접근

| 단계 | 대상 | 설명 |
|------|------|------|
| **Phase 1** | Web Client | MVP — Mobile Safari에서 1:1 및 회의 지원 |
| **Phase 2** | Flutter Mobile | 푸시 알림 (FCM)으로 대체 수신 |
| **Phase 3** | Native iOS | VoIP (PushKit) Background Mode |

### 2.2 iOS Native 필요 조건

- 고객사가 **상시 전화 수신**을 요구하는 경우
- **App Store 배포**가 필요한 경우
- **Apple 심사**에서 VoIP 기능 검증 필요 (실제 전화 기능 제공 증명)

### 2.3 기술 선택

| 계층 | 기술 |
|------|------|
| 언어 | Swift 5.9+ |
| SIP Engine | PJSIP (iOS XCFramework) |
| Media | AVFoundation |
| 백그라운드 | PushKit (VoIP) |
| 배포 | App Store |

## 3. 영향 (Consequences)

### 긍정적 영향
- iOS 백그라운드에서의 상시 전화 수신 가능
- App Store를 통한 브랜드 가시성
- 시스템 레벨의 전화 처리 (침묵/거절 UI)

### 부정적 영향
- 별도 iOS 개발/유지보수 비용
- Apple 심사 복잡성
- PJSIP iOS 빌드 검증 필요
