# ADR-009: WS 재연결 시 재REGISTER 보장(A4)을 롤백한다

**날짜**: 2026-11-13
**상태**: **수용(Accepted)** — v0.0.24에서 롤백 예정(문서 선행 후 구현)
**관련**: [[wiki/05_Decisions/ADR-008-re-INVITE_recvonly_유지]], 서버 리포 `ADR-004_WebRTC_AOR_등록유지정책_20261112`
**상위**: [[docs/보고서/20261113_F1F2_G3_작업계획서_v1.0]] §4, [[wiki/06_Reports/20261113_1201_1대1_영상미수신_교차분석보고서_v1.0]] 6장

---

## 배경

A 항목(404 재발 방지)에서 `transportStateChanged(DISCONNECTED)` 시 `_needsReRegister=true`, `CONNECTED` 복귀 시 `unawaited(register())` 를 추가했다(v0.0.23, A4). 당시 가설은 "WS 재연결 후 재REGISTER 경로가 없다"는 것이었다.

`1101_MacPro로그.txt`(v0.0.23 실기)에서 **회귀가 확인**됐다:

```
00:53:24  SIP transport reconnected -> re-REGISTER
00:53:26  SIP transport disconnected (cause: Code: [0], ... close by local)
00:53:33  re-REGISTER → registered
00:53:35  disconnected (close by local)
00:53:39  ERROR SIP 등록 시간 초과 또는 실패
00:53:43  re-REGISTER → unregistered → ERROR → registered
...       2~7초 주기 15회 이상 반복 (~00:54:22)
```

사용자 메모: *"1101은 다자간 통화중 자꾸 튕겨져 나간다. 반복 재현됨."* 로그에 `callPressed`/`callInitiation`/`6000`/`6100`/`CONFERENCE` 가 0건 → **회의 진입 전 등록 단계**에서 불안정.

### 반증

| 대조 | 결과 |
|------|------|
| v0.0.22 `1103` | A4 **없이** `23:52:02 disconnected(1006) → 23:52:11 registered` 로 sip_ua 자체 재연결만 복구 |
| A5 회귀 | 서버 A3(`remove_existing=no` / `remove_unavailable=yes` / `qualify_frequency=15`) **만으로** 294초 갱신 구간 contact 해시 유지·신규 404 0건 → ADR-004 Accepted |

즉 **클라이언트 보강은 불필요**했고, `_helper.register()` 호출이 sip_ua 포크의 기존 WS를 `close by local` 로 닫아 재연결 → 재REGISTER 루프를 만든다.

---

## 결정

1. A4를 **전부 제거**한다.

| 제거 | 위치 |
|------|------|
| `bool _needsReRegister = false;` | 필드 영역 |
| `if (_needsReRegister) { ... AppLogger.instance.i('SIP transport reconnected -> re-REGISTER'); unawaited(register()); }` | `transportStateChanged` `CONNECTED` |
| `_needsReRegister = true;` | `transportStateChanged` `DISCONNECTED` |

2. `DISCONNECTED`의 **`SIP transport disconnected (cause: …)` 로그·`_setState(disconnected)`·`_completeTransport(false)`는 유지**한다(진단 가시성 보존).
3. **유지**: A3(서버 ADR-004), `_receiveOnlyVideo`/`_acceptReinvite` 옵션 병합(D1·ADR-008), D2 스트림 정리, `_pendingCallTarget`(F1·ADR-008 후속).
4. 재연결 후 REGISTER는 **sip_ua 자체 등록 갱신 흐름(294초)에 맡긴다.**

---

## 대안

| 대안 | 기각 이유 |
|------|-----------|
| `register()` 대신 지연/디바운스 추가 | 근본 원인(`register()`가 WS를 닫음) unresolved, 복잡도만 증가 |
| `CONNECTED` 1회만 재REGISTER | 최초 로그인 `CONNECTED`와 재연결 구분 필요 → 상태 추가, 여전히 WS close 유발 |
| sip_ua 포크에서 재연결 시 자동 REGISTER | 포크 변경 범위 과다, v0.0.22에서 이미 동작 확인됨 |

---

## 결과

- **장점**: 등록 루프·다자간 튕김 제거, 코드 단순화, v0.0.22의 검증된 동작으로 복귀.
- **단점**: 재연결 직후 즉시 REGISTER를 강제하지 않음 → 단, UA가 294초 주기로 갱신하고 서버 A3가 contact 공백을 제거했으므로 실영향 없음.
- **검증**: T-F2-1 `re-REGISTER` 로그 소멸 / T-F2-2 등록 타임아웃 반복 0회 / T-F2-4 1101 회의 5분 유지 / T-F2-6 ADR-004 설정 유지.
- **영향 파일**: `macos-client/lib/src/sip/sip_client.dart` 1개(3개소 제거).

---

## 롤백(이 결정 자체의)

재도입이 필요하면 이 ADR을 `Superseded`로 하고 A4 커밋(`133c7ae`)을 참조하되, 반드시 1101 등록 루프 실기 검증을 선행한다.
