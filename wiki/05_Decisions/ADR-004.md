# ADR-004: SIP 엔진을 flutter_sip에서 dart-sip-ua(sip_ua)로 교체

| 항목 | 값 |
|------|---|
| **결정 일자** | 2026-11-09 |
| **결정자** | Kibal Team |
| **상태** | 결정됨 (Accepted) |
| **버전** | v1.0 |
| **적용 대상** | `macos-client` (이후 iOS/Windows/Android에도 동일 적용) |

## 1. 배경

기존 Flutter 클라이언트는 `flutter_sip 0.0.8`을 사용했다. 그러나 이 플러그인은 **Android 플랫폼만 선언**되어 있어 iOS/macOS에서는 플러그인이 등록되지 않는다.

실제 iOS 빌드 로그에서 확인된 오류:

```
MissingPluginException(No implementation found for method init on channel flutter_sip)
MissingPluginException(... channel login_status_stream)
```

즉, 과거 iOS에서 "동작 확인"된 것은 UI뿐이며 SIP는 실제로 동작하지 않았다.

## 2. 결정

- SIP 스택을 **`sip_ua`(dart-sip-ua, ^1.1.0)** 로 교체한다.
- `flutter_webrtc`를 `0.11.7` → **`^1.6.3`** 으로 승격한다 (sip_ua 1.1.0이 `flutter_webrtc ^1.2.0` 요구).
- `KibalSipClient`의 공개 API(`init/register/unregister/disconnect/call/accept/reject/hangup`, `SipEvent`)는 유지해 UI/Provider 변경을 최소화한다.

## 3. 근거

| 항목 | flutter_sip 0.0.8 | sip_ua 1.1.0 |
|------|-------------------|--------------|
| 플랫폼 | Android만 | iOS/Android/macOS/Windows/Linux/Web |
| 구현 | 네이티브 채널 | 순수 Dart (JsSIP 포팅) |
| 미디어 연동 | 제한적 | flutter_webrtc 네이티브 연동 |
| 수신 통화/종료 | API 미비 | Call.answer/hangup 등 완비 |
| 유지보수 | 저조 | flutter-webrtc.org 공식 |

## 4. 제약 및 영향

- **전송은 WS/WSS·TCP만 지원(UDP SIP 미지원)** → macOS 클라이언트는 WebSocket(`ws://…:8088/ws`)을 사용한다. UDP 5060 네이티브 SIP가 필요해지면 별도 스택(PJSIP 등) 검토가 필요하다.
- DEV Asterisk WebRTC 내선(1101~1104)과 동일한 DTLS-SRTP 미디어를 사용하므로 서버 설정 변경이 없다.
- 브라우저가 아니므로 **HTTPS/WSS 인증서는 여전히 불필요**하다(네이티브 전환 목적과 무충돌).

## 5. 검증

- REGISTER: `401(정상 챌린지) → 200 OK`
- 1:1 통화: 1102↔1103 수립·양방향 원격 스트림·종료 성공
- 3자 회의: ConfBridge 6000 `Users: 3` 확인
