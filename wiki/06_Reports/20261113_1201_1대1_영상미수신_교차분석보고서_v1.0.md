## 1. 요약

**`1201`(A10)이 1:1 영상통화에서 원격 영상을 못 보는 원인은 코덱 불일치다.**

- `1103`(macOS 클라이언트)이 **`1201`로 발신할 때 H.264 코덱 정책이 적용되지 않아** offer가 WebRTC 기본 우선순위인 **VP8**로 나갔다.
- `1201` endpoint는 **`allow=(g722|ulaw|alaw|h264)`로 H.264만** 지원한다.
- Asterisk는 **영상 코덱을 트랜스코딩하지 못한다**(오디오만 트랜스코딩). 그 결과 `Don't know how to send format vp8/h264 packets with RTP` 경고가 발생하고 **1103 → 1201 방향 영상 RTP가 전달되지 않는다**.
- 반대 방향(A10 → 1103)은 A10이 보내는 H.264를 1103이 `vp8|h264` 양쪽 지원으로 받아 **정상**(`in=1920x1080@30fps`). 셀프 영상은 A10 자기 카메라 로컬 프리뷰라 정상, 음성은 opus↔ulaw/g722 트랜스코딩이 되어 정상이다. ⇒ **단방향만 끊긴다.**

별건으로 **v0.0.23의 A4(WS 재연결 시 재REGISTER)가 등록 루프를 유발**해 `1101`이 다자간 통화에서 튕겨 나가는 회귀가 확인됐다.

> **이전 C 결론 정정**: 6100 `follow_talker`는 정상이었고(발언자 1201 자동설정), "원격 영상 미표시는 1103→A10 방향 미검증"으로 남겨뒀는데, 이번 1:1 실기로 그 방향이 **코덱 불일치로 실패**함이 확정됐다. 브리지 문제가 아니다.

## 3. 실시간 채널 스냅샷 (분석 시점, 1:1 통화 22분째 유지)

```
PJSIP/1103-00000002   1201@from-internal:2   Up  Dial(PJSIP/1201,60,tT)
PJSIP/1201-00000003   (None)                 Up  AppDial((Outgoing Line))
5 active channels / 2 active calls
```

| leg | `core show channel` | 의미 |
|-----|---------------------|------|
| `PJSIP/1103-00000002` | `NativeFormats: (opus\|vp8)`, `video-1 State: sendrecv Formats: (vp8\|h264)`, `WriteTranscode: ulaw→slin48→opus`(오디오만) | **실제 전송 코덱 VP8** |
| `PJSIP/1201-00000003` | `NativeFormats: (h264\|ulaw)`, `video-1 State: sendrecv Formats: (h264)`, `WriteFormat slin48 / ReadFormat ulaw`, `BRIDGEPEER=PJSIP/1103-00000002` | **H.264만 허용** |

`pjsip show endpoint 1201`: `allow=(g722|ulaw|alaw|h264)`, `max_video_streams=1`, `media_encryption=no`, `webrtc=no`.

> **SDP direction(`sendrecv`)은 양쪽 모두 정상**이다. 불일치는 `direction`이 아니라 **payload/코덱**이다. 이것이 이전에 "SDP 정상 → 브리지 문제"로 좁혔던 판단이 틀린 지점이다.

## 4. 원인 사슬

```
[1103] call(target=1201)
  └─ localSdpTransformer(session, 'offer', sdp)            sip_client.dart:162-171
       └─ target = session.remote_identity?.uri?.user      ← 발신 offer 시점에 null
            └─ videoPolicyFor(null) = VideoCodecPolicy.keep   sdp_codec.dart:8-13
                 └─ SDP 무변환 → WebRTC 기본 우선순위 VP8이 첫 payload
                      └─ Asterisk 1103 leg: NativeFormats (opus|vp8)
                           └─ 1201 leg은 h264 only → 영상 트랜스코딩 불가
                                └─ Don't know how to send format vp8/h264 packets with RTP
                                     └─ A10 원격 영상 RTP 없음 → 검은 화면/스피너
```

`sdp_codec.dart:11`은 `RegExp(r'^12\d\d$')` → `1201`을 `h264First`로 매핑하도록 **이미 구현돼 있다**. 문제는 정책 함수가 아니라 **타깃 전달 경로**다. 6100 회의에서 `target=6100 type=offer video=h264Only`가 찍힌 것은, 회의 진입 시 `remote_identity`가 설정된 이후의 offer/재협상이기 때문으로 보인다. ⇒ **발신 초기 offer에만 구멍**이 있다.

`SipSession`(`sip_session.dart:32,105-111`)에 `remoteParty`가 있고 `call()`(`sip_client.dart:313-315`)에서 `SipSession(target)..setRemoteParty(target)`로 설정되므로, **`_currentSession?.remoteParty`를 폴백으로 쓰면 발신 시점에도 타깃을 얻을 수 있다.**

## 6. 별건 — v0.0.23 A4 회귀 (1101 튕김)

`1101_MacPro로그.txt` 사용자 메모: *"1101은 다자간 통화중 자꾸 튕겨져 나간다. 반복 재현됨."*

```
00:53:24  SIP transport reconnected -> re-REGISTER     ← v0.0.23 A4 신규 로그
00:53:26  SIP transport disconnected (close by local)
00:53:33  re-REGISTER → registered
00:53:35  disconnected (close by local)
00:53:39  ERROR SIP 등록 시간 초과 또는 실패
00:53:43  re-REGISTER → unregistered → ERROR → registered
00:53:45  disconnected
... 2~7초 주기로 15회 이상 반복 (~00:54:22)
```

- 로그에 `callPressed` / `callInitiation` / `6000` / `6100` / `CONFERENCE` 가 **0건** → 튕김은 **회의 진입 전 등록 단계**에서 발생한다(체감상 회의에서 나가는 것).
- **A4가 `CONNECTED`에서 `unawaited(register())`를 호출**(`sip_client.dart` D1 작업에서 추가한 `_needsReRegister` 경로) → `_helper.register()`가 sip_ua 포크의 기존 WS를 `close by local`로 닫고 재연결 → 다시 `CONNECTED` → 재REGISTER → 등록 완료 대기(15초)와 겹쳐 타임아웃 → 루프.
- **대조**: v0.0.22의 `1103`은 A4 없이도 재생성 후 `23:52:02 disconnected → 23:52:11 registered`로 **sip_ua 자체 재연결만으로 깔끔하게 복구**됐다(선행 실험 기록). A5 회귀 합격도 **서버 A3(`remove_existing=no`)만으로** 달성됐다.
- ⇒ **A4는 불필요했고 오히려 회귀를 만들었다. 롤백이 정답**이다.

## 10. 후속 질문 — 6100 단독 입장 시 빈 회의실 화면·카드 없음 + 스피너 (2026-11-13 01:10)

> 질문: *"1201을 6100 회의실에 제일 먼저 입장시키면 셀프영상은 나오고 빈회의실 화면이 보여야 하는데 그게 없고 참석 카드도 안보인다. 중앙에 원격지 영상이 계속 동그란 인디게이터로 회전한다. 왜 회의실 화면이 전달이 안되는가?"*

**결론: 코덱/전달 실패가 아니라 "전달할 원격 영상 소스가 존재하지 않는다"는 설계 동작이다.**

### 근거

| 항목 | 확인값 |
|------|--------|
| `kibal_bridge_ft` | `Video Mode: follow_talker`, `Video Update Discard: 2000`, `REMB Send Interval: 0`, **`Enable Events: no`**, **`video_source` 항목 없음** |
| `confbridge.conf:36-43` | `video_mode=follow_talker`만 지정. 빈 회의실용 정지영상/기본 화면 소스 **미설정** |
| `manager show command ConfbridgeSetSingleVideoSrc` | Synopsis: *"Set a conference user as the single video source distributed to **all other participants**"* → **자기 자신 제외** |
| 단독 입장 채널 `PJSIP/1201-0000000e` | `video-1 State: sendrecv / Formats: (h264)`, `NativeFormats (g722\|h264)` — **협상 정상**, 그러나 분배 대상 0명 |
| `CBAnn/6100-*` | 오디오 안내 전용(`conf-onlyperson` 등), 영상 소스 아님 |
| `confbridge list 6100` | **`PJSIP/1201-0000000b` + `PJSIP/1201-0000000e` — 1201 채널 2개 동시 존재**(이전 테스트 잔여, 발화자 판정·카드 수 꼬임 가중) |
| `messages` 코덱 경고 | 마지막 `15:41:51 UTC`(00:41:51 KST, 1:1 통화). **이후 신규 0건** → 단독 입장 스피너는 코덱 불일치 아님 |

### 인과

```
1201 단독 입장 (참가자 1명)
  └─ follow_talker / ConfbridgeSetSingleVideoSrc 는 "다른 참가자"에게만 영상 분배
       └─ other participants = 0  →  분배할 원격 스트림 없음
            └─ 1201 leg 는 video-1 sendrecv 로 협상 → 원격 프레임 기대
                 └─ RTP 프레임 0  →  A10 이 스피너 무한 회전
            └─ video_source 미설정  →  "빈 회의실 화면" 자동 생성 안 됨(Asterisk 기본 기능 아님)
            └─ Enable Events: no + 원격 트랙 0  →  참석 카드 구성 불가
  └─ 셀프 영상은 A10 로컬 프리뷰라 정상, 음성은 g722↔slin 트랜스코딩으로 정상
```

즉 **셀프 영상·음성이 정상인 것과 원격 영상이 없는 것은 모순이 아니다.** 1201이 **유일한 참가자**일 때 서버가 1201에게 되돌려 보낼 영상은 설계상 존재하지 않는다(자기 영상 루프백 방지). 2번째 참가자가 들어오면 발화자 영상이 1201로 전달된다(선행 실기에서 1103이 A10 영상을 `in=1920x1080`으로 수신한 것의 역방향).
