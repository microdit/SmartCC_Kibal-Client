## 1. 목표

Web 클라이언트를 SIP 영상회의의 기준 클라이언트로 완성한다.

- SIP over WebSocket 등록·해제·재연결
- WebRTC 1:1 영상통화와 6000 회의실 SFU
- 마이크·카메라 on/off와 세션 종료 정리
- SIP 비밀번호를 브라우저 번들에 포함하지 않음
- `ws://`/`wss://` 및 HTTPS mixed content 사전 검증

## 2. MD5 이슈 대응

### 2.1 결론

SIP Digest는 인증 시점에 challenge-response로 MD5를 계산한다. 서버와 클라이언트는 **동일한 plaintext 비밀번호**를 사용해야 하며, 사전 계산된 MD5 digest를 비밀번호로 넣으면 안 된다.

DEV 장애의 실제 원인은 stale Docker 컨테이너의 32자리 hex 런타임 값과 `.env`/클라이언트 입력 값의 불일치였다. `deploy/dev/.env`는 이미 plaintext였고, 서버 컨테이너를 재생성해 일치시켰다.

### 2.2 클라이언트 원칙

| 원칙 | 구현 |
|------|------|
| 비밀번호 번들 금지 | `VITE_SIP_PASSWORD` 제거, UI 입력만 사용 |
| 비밀번호 저장 금지 | `localStorage`에는 password를 빈 값으로 저장 |
| 서버와 동일한 값 사용 | 등록 실패 시 서버 `.env`/runtime 일치 확인 |
| 32자리 hex 경고 | 서버 entrypoint·검증 스크립트에서 경고 |
| template hardcode 금지 | `${SIP_PASSWORD_*}` placeholder 유지 |
