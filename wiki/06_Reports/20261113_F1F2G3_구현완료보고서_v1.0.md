## 2. 구현 내역

### F1 — `macos-client/lib/src/sip/sip_client.dart`

| # | 변경 | 위치 |
|---|------|------|
| 1 | `String? _pendingCallTarget;` 추가 | 필드 영역(`:86`) |
| 2 | `final target = session.remote_identity?.uri?.user ?? _pendingCallTarget;` | `localSdpTransformer`(`:167-168`) |
| 3 | `_pendingCallTarget = target;` | `call()`의 `_helper.call()` 직전(`:306`) |
| 4 | `_pendingCallTarget = null;` | `_cleanupSession()`(`:1054`) |

`sdp_codec.dart`는 **무변경**(`12xx → h264First` 이미 구현). 6100/6000/착신 경로도 무변경.

> **정정 반영**: 선행 분석보고서 v1.0의 `_currentSession?.remoteParty` 폴백은 `:313`(offer 이후 생성)이라 부정확 → `_pendingCallTarget`로 확정(분석보고서 v1.2, 설계서 2장, 지식 K17).

### F2 — 동일 파일

| 제거 | 위치 |
|------|------|
| `bool _needsReRegister = false;` | 필드 |
| `if (_needsReRegister) { … 'SIP transport reconnected -> re-REGISTER' … unawaited(register()); }` | `transportStateChanged` `CONNECTED` |
| `_needsReRegister = true;` | `transportStateChanged` `DISCONNECTED` |

`SIP transport disconnected (cause: …)` 로그·`_setState(disconnected)`·`_completeTransport(false)` 는 **유지**. `grep` 결과 `_needsReRegister`/`re-REGISTER` 잔여 **0건**. 근거 [[wiki/05_Decisions/ADR-009-A4_재등록_롤백]].

### G3 — `server/asterisk/config/confbridge.conf`

```ini
[kibal_bridge_ft]
...
language=en
enable_events=yes      # 신규
```

`6000`(`kibal_bridge`) 무변경, `video_source` 미추가(옵션 부재). 근거 서버 리포 `ADR-005_ConfBridge_참가자이벤트_20261113`.

| ID | 절차 | 합격 기준 |
|----|------|-----------|
| **T-F1-2/4/5** | v0.0.24 `1103 → 1201` 1:1 발신 | OPS 로그 `SIP codec policy target=1201 type=offer video=h264First`, 양 leg `video-1 (h264)`, 신규 `Don't know how to send format` 0건, **A10 원격 영상 표시** |
| **T-F1-6/7/8** | 6100 / 6000 발신, 1201 종료 후 6000 재발신 | `h264Only` / `keep` 유지, 타깃 초기화로 오적용 없음 |
| **T-F2-1~4** | 1101 재로그인 + 6000/6100 5분 | `re-REGISTER` 로그 0, 등록 타임아웃 반복 0, **튕김 없음** |

## 5. 보류·주의

- **G2(단독 입장 상시 영상 소스)**: `confbridge show profile`에 Video Source 항목 없음, `ConfbridgeSetSingleVideoSrc`는 "all other participants"(자기 제외) → 더미 영상 채널 설계가 별도 과제. 단독 입장 스피너는 **정상 대기**로 문서화(설계서 4.3, 지식 K16).
- **1201 1:1 코덱 불일치**는 F1로 해소되나, **6100 단독 입장 스피너와는 별개 원인**임을 혼동하지 말 것.
- 컨테이너 재생성은 진행 통화를 종료시킨다. 이후 실기 테스트 재개 시 등록 상태를 먼저 확인.
- 실기 로그 제공 시 T-F1/T-F2/T-G3/T-G1 판정과 ADR-009·ADR-005 상태를 `Accepted(검증됨)`으로 갱신한다.
