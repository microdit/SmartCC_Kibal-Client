## 1. 목적

외부망 사용 시 보고된 아래 장애에 대해, 클라이언트 측 로그/코드 교차검증 결과를 공유하고 **서버(OPS/Asterisk/coturn) 측 원인 확인 및 수정 범위**를 Mac Pro 담당 에이전트와 합의하기 위한 의견을 정리한다.

- 주소록이 계속 다시 가져와짐
- 주소록이 사라졌다가 다시 나타남(깜빡임/빈 목록)
- 미디어 재생 안 됨
- 영상 화면 안 나옴

## 2. 관측 증상 및 확인된 근거 (클라이언트/OPS 수집 로그)

### 2.1 서버 로그 수집 상태
- OPS 클라이언트 로그 수집은 정상 동작 확인: `OPS_URL=http://appletreeda.synology.me:8091 ./scripts/ops_client_logs.sh list|tail|server`
- 1104(v0.0.55), 1102(v0.0.55) 세션 로그 교차검증 가능

### 2.2 주소록 반복 갱신/소실 — 확인된 사실
| 사실 | 근거 |
|------|------|
| 외부망 단말이 OPS config를 200으로 받았으나 내부망 주소가 적용됨 | 1104 v0.0.55: `onLan=false, currentProfile=appletreeda.synology.me` 상태에서 `GET /api/client/config` 200 → `domain=192.168.11.5 ws=ws://192.168.11.5:8088/ws changed=true`, `client_log_url=http://192.168.11.5:8091/api/client-logs` |
| 내부 주소 적용 후 디렉터리 조회가 실패해 주소록이 0건으로 동기화됨 | 1102 v0.0.55: `http://192.168.11.5:8091/api/client/contacts|conferences` Timeout(4s) → `AddressBook synced contacts=0 rooms=0` |
| 클라이언트가 외부 프로필로 자동 복구하나 다시 내부값이 재적용되어 진동 | 1102 v0.0.55: `외부망 감지 → 외부 프로필로 자동 전환` 후 `contacts=7 rooms=3` 복구, 이후 config 200으로 다시 내부값 적용 → `7/3 ↔ 0/0` 반복 |
| config 401과 directory 200이 공존하는 세션 존재 | 1104 v0.0.53: 30초 주기 `config 401 AUTH_REQUIRED` 반복, `contacts/conferences 200` 및 `contacts=7 rooms=3` 유지 |

**클라이언트 동작 요인(증폭 요인):**
- 주소록 화면 30초 주기 `refreshSmart + fetch` 및 앱 재개 시 재동기화
- 디렉터리 fetch 실패/타임아웃 시 빈 결과(`OpsDirectory()`) 반환 및 UI 즉시 덮어쓰기
- `ServerConfigService.refresh()`가 성공 응답(200)을 네트워크 맥락 검증 없이 적용/저장

### 2.3 미디어 재생 불가/영상 미표시 — 확인된 사실
| 사실 | 근거 |
|------|------|
| 시그널링/통화 성립 및 원격 스트림 객체 생성은 발생 | 1102 v0.0.55 6700 회의: `registered`, `callEstablished/Confirmed`, `remoteStreamAdded`, 원격 비디오 타일 등록, re-INVITE 자동 수락 |
| 실제 인바운드 RTP가 수신되지 않음 | `SIP stats inbound audioBytes=0 audioPackets=0 videoBytes=0` 반복 |
| ICE 실패로 통화 종료 | `RTP Timeout, ICE Connection Failed (408)` |
| 서버 측 ICE 오류 다수 관측 | OPS 서버 이벤트 로그: `PJ ICE Rx error status code: 370401 'Unauthorized'`, `ICE not completed yet`, DTLS drop 경고 |
| 일부 시그널링 연결 타임아웃도 관측 | 1104 세션: `SIP 전송 연결 시간 초과` (`wss://appletreeda.synology.me:8089/ws`) |

## 3. 원인에 대한 의견 (확인됨 / 확인 필요)

### 3.1 확인됨 (높은 신뢰도)
1. **OPS `/api/client/config` 응답 정합성 문제(외부망 내부값 반환)가 주소록 소실 진동의 직접 트리거**
   - 외부 도달 경로(`http://appletreeda.synology.me:8091`)로 200을 받더라도 payload에 내부 `sipDomain/ws/opsBaseUrl/client_log_url`이 포함되면 클라이언트 설정이 오염됨.
2. **클라이언트 방어 부족으로 장애가 증폭**
   - 외부망 컨텍스트에서 내부 RFC1918/내부 전용 주소를 거부/정규화하지 않고 저장.
   - 디렉터리 실패 시 이전 유효 데이터를 유지하지 않아 즉시 빈 화면으로 전환.
3. **미디어 경로(ICE/RTP) 실패가 "재생 안 됨/영상 없음"의 직접 원인**
   - 단순 UI 문제보다 네트워크 미디어 전달 실패 근거가 우세.

### 3.2 확인 필요 (Mac Pro/서버 측 협의 필요)
1. **OPS config 생성/분기 로직**
   - 요청 Origin/Host/프록시 헤더/접속 경로(외부 DDNS vs 내부)에 따라 어떤 값(`sip_domain`, `ws_server`, `ops_base_url`, `client_log_url`, `turn`, `bound_extension`, `auth_mode`)을 내려주는지?
   - 외부 요청에 내부 IP를 반환하는 조건(기본값 fallback, 환경변수, DB 설정, reverse proxy/NAT hairpin 인식 오류 등)은 무엇인지?
2. **config 401(AUTH_REQUIRED) vs directory 200 불일치**
   - 동일 단말/세션에서 config는 401, contacts/conferences는 200인 정책이 의도된 동작인지?
   - 클라이언트가 보내는 `X-Client-Key`/`X-Client-Extension` 처리 차이 및 필요 헤더/인증 흐름 정리 필요.
3. **ICE 370401 Unauthorized / RTP Timeout 원인**
   - Asterisk ICE/STUN/TURN 설정, coturn 자격증명(realm/user/secret, ttl), 외부 포트 개방(UDP/TCP/TLS), advertised address, 인증서/WSS 연계 상태 점검.
   - OPS가 내려주는 `turn` 정보의 외부망 유효성(호스트, 포트, credential type, 만료) 확인.
4. **로그 업로드 경로**
   - 외부망 단말이 접근 가능한 `client_log_url`(공인/외부 도메인) 표준값 확정 필요.

## 4. 제안 사항

### 4.1 서버/OPS (P0)
- [ ] `/api/client/config` 외부 응답에서 **외부 도달 가능한 값만** 반환하도록 분기/정규화
  - `sipDomain`, `wsServer`(wss), `opsBaseUrl`, `client_log_url`에 내부 IP(`192.168.x.x` 등) 노출 금지(외부 컨텍스트 기준)
- [ ] 외부 응답용 `client_log_url`을 공인/외부 도메인 기준으로 고정
- [ ] config/directory 인증 정책 정합성 점검(401 vs 200 불일치 원인 문서화 또는 수정)
- [ ] 필요 시 응답에 `profile_scope`/`network_scope`(internal/external) 메타를 추가해 클라이언트 오적용 방지(선택)

### 4.2 미디어 인프라 (P0/P1)
- [ ] coturn/TURN 외부 경로 점검: 공개 주소, 포트포워딩/방화벽, credentials, TLS/UDP 지원 범위
- [ ] Asterisk ICE/미디어 설정 점검: 외부 candidate, NAT 설정, `PJ ICE Rx error status code: 370401` 재현 로그와 매핑
- [ ] OPS config `turn` 필드가 실제 운영 TURN과 일치하는지 검증 (`tool/turn_probe.dart` 또는 동등 절차)

### 4.3 클라이언트 (P0/P1, 후속 구현 제안)
- [ ] `refresh()`/`_fetch()` 적용 전 가드: 외부망(`!onLan` 또는 external 컨텍스트)에서 내부 주소 payload 수신 시 **채택 거부 또는 외부 프로필 값으로 정규화**, 저장 방지
- [ ] `probeProfile(external)`의 외부 보호 로직을 일반 refresh 경로와 일관화
- [ ] 디렉터리 조회 실패 시 직전 유효 캐시 유지(빈 목록 즉시 덮어쓰기 금지), 재시도/백오프/후보 fallback
- [ ] 설정 오염 감지/거부 사유 및 `7/3 → 0/0` 급변 시 WARN 로그 강화

> 클라이언트 방어는 재발 완화에 필요하나, **근본 해결은 OPS가 올바른 외부 설정을 반환하는 것**이 우선이라는 의견.

### 4.4 운영/관측성 (P2)
- [ ] config 응답 감사 로그(요청 출처, 선택된 프로필, 반환 주요 URL, 마스킹) 추가
- [ ] 외부망 헬스체크 항목에 "config 외부 정합성(내부 IP 미포함)" 자동 점검 추가

## 5. Mac Pro 담당 에이전트에게 요청하는 확인/회신 항목

1. 외부 요청에서 `/api/client/config`가 내부 IP를 반환하게 된 **정확한 조건/코드 위치**(OPS repo 기준)
2. 외부망용 정식 값: `sipDomain`, `wsServer`, `opsBaseUrl`, `client_log_url`, `turn`(서버/포트/credential 방식)
3. 1104 사례 기준 `config 401` + `directory 200`이 의도인지, 아니라면 수정 계획
4. Asterisk ICE 370401 Unauthorized의 현재 서버 설정 원인 및 조치 계획(coturn 포함)
5. 수정 후 합동 검증 시간/방법(외부 단말 1대, 5분 이상 주소록 안정성 + 6700 회의 RTP 수신 확인)

## 6. 합동 검증 기준 (수정 후 완료 조건)

- [ ] 외부망에서 config 응답의 `sipDomain/wsServer/opsBaseUrl/client_log_url`이 외부 도달 값이며 내부 IP 미포함
- [ ] 5분 이상 `AddressBook synced contacts=7 rooms=3` 유지, `contacts=0 rooms=0` 및 `sipDomain` 내부 IP 전환 미발생
- [ ] SIP 등록 안정, 의도치 않은 재등록 루프 없음
- [ ] 6700 회의에서 `inbound audioBytes/videoBytes > 0`, `ICE Connection Failed/RTP Timeout` 미발생, 영상 표시/오디오 재생 확인
- [ ] 동일 단말 세션 로그가 OPS에 지속 수집됨

## 7. 결론 의견

- 본 장애는 단일 요인이 아니라 **(1) OPS 외부 config 응답의 내부 주소 주입**, **(2) 클라이언트의 무방비 적용/빈 결과 덮어쓰기/주기 재동기화**, **(3) 외부망 ICE/RTP 미디어 경로 실패**가 결합된 형태로 판단된다.
- 우선순위는 **서버(OPS) config 정합성 수정 + TURN/ICE 경로 정상화**이며, 클라이언트는 이를 전제로/병행하여 오염값 방어 및 주소록 캐시 보존을 적용하는 것이 안전하다.
- Mac Pro 담당 에이전트의 서버 측 확인(§5)이 확보되면, 클라이언트 수정 범위와 검증 시나리오를 즉시 확정 가능하다.
