## 1. 요약

- A10은 `TEAMS EDITION` / `BYOD` 전용 상태이며, SIP Account UI는 편집 가능하지만 **SIP 설정 저장이 되지 않았다**.
- 저장 실패 원인은 A10이 `talking=true`로 응답해 웹 UI의 `writeData`가 **`isTalking()` 가드에서 중단**되기 때문이다. `POST /api/inner/writeconfig` 요청 자체가 발생하지 않았다.
- USB-C 케이블은 A10 후면 C-type 포트에 연결됐고 A10 화면은 BYOD로 진입했지만, **`No sharing signal`** 이 표시되고 Mac에서 **Yealink Room Camera/Audio가 열거되지 않는다**.
- 따라서 현재 P1(v0.0.21 장치 선택)과 P2(v0.0.22 H.264/6100) 모두 **실기 검증 대기** 상태다.
- SIP 1201은 서버에 설정되어 있으나 A10 등록 전이라 `Unavailable`이다. 6100 `follow_talker`는 서버에 로드되어 있다.

## 3. 원인 분석

### 3.1 T0-C SIP 저장이 안 된 이유

A10 웹 UI의 `writeData`는 설정을 저장하기 전에 `isTalking()`을 호출한다. 이 값이 `true`이면 `writeconfig`를 보내지 않고 조용히 반환한다.

- `GET /api/common/info/status/talking` → `true`
- `/api/diagnosis/talk/statistics` → `Get callid error!`
- `/api/contacts/callingcontacts` → 빈 목록
- 즉 실제 통화 콜ID는 없는데 `talking` 플래그만 `true`로 남아 있는 상태로 보인다. BYOD/USB-C 연결 상태 또는 이전 세션의 잔여 상태가 원인일 수 있다.

또한 자동화 관점에서 A10 웹 UI 입력은 `fill()`만으로 Vue `formData`가 갱신되지 않는다. **입력 후 `Tab`/blur 이벤트가 필요**하다. 이번 재시도에서는 `fill + Tab`으로 모델 갱신을 확인했다.

### 3.2 USB B′ 링크가 성립하지 않는 이유

- A10의 `No sharing signal`은 **USB-C를 통한 DisplayPort 화면 공유 신호가 없다**는 뜻이다. P1의 카메라/오디오 사용과는 별개일 수 있으므로, P1 판정은 **Mac의 USB 장치 열거**를 기준으로 한다.
- 커넥터 LED는 전원 표시일 뿐 데이터 링크를 보장하지 않는다.
- Mac에서 Yealink 카메라/오디오가 전혀 열거되지 않으므로 **USB 데이터 링크 자체가 열리지 않았다**.
- 후보 원인:
  1. 충전 전용 USB-C 케이블
  2. USB-A → USB-C 케이블 또는 허브 경유 (DP Alt Mode 불가)
  3. Mac Pro 7,1의 Thunderbolt 3 포트가 아닌 다른 포트 사용
  4. macOS USB 액세서리 승인 프롬프트 미승인
  5. A10 USB-C 포트 또는 케이블 불량

## 5. 다음 단계

상세 절차·합격 기준은 [[docs/보고서/20261112_A10_T0C_USB_작업계획서_v1.0]]를 따른다.

1. **USB B′ 우선 확인**
   - USB-C → USB-C 케이블(데이터 + DP Alt Mode 지원)로 교체
   - Mac Pro 상단 Thunderbolt 3 포트에 직결, 허브/변환 제거
   - macOS `Privacy & Security > Allow accessories to connect` 확인
   - `System Information > USB`에서 Yealink 장치 확인
   - 가능하면 Windows PC에서 교차 확인
2. **P1 실기**
   - Mac에서 Yealink 카메라/마이크/스피커가 보이면 v0.0.21 장치 선택 저장 → 1:1/6000 검증
3. **SIP T0-C 재시도(선택)**
   - USB-C를 분리해 A10을 idle로 만들고 `talking=false` 확인
   - `fill + Tab`으로 값 입력 → `Confirm` → `writeconfig` 발생 확인
   - A10 `Registered` 및 서버 `1201 Avail` 확인
4. **분기**
   - USB 성공 → P1 완료, P2는 보조 경로
   - USB 실패·SIP 성공 → P2 경로
   - 둘 다 실패 → 케이블/포트/펌웨어 하드웨어 이슈로 에스컬레이션

## 6. 재현·확인 명령

```bash
# A10 상태
A10_PASS='<관리자 비밀번호>' ./scripts/a10_admin.sh summary
A10_PASS='<관리자 비밀번호>' ./scripts/a10_admin.sh get '/api/account/status?type=sip&acc=1'
A10_PASS='<관리자 비밀번호>' ./scripts/a10_admin.sh get '/api/common/info/status/talking'

# 서버 SIP/브리지
docker exec kibal-dev-asterisk asterisk -rx 'pjsip show contacts'
docker exec kibal-dev-asterisk asterisk -rx 'pjsip show endpoint 1201'
docker exec kibal-dev-asterisk asterisk -rx 'confbridge show profile bridge kibal_bridge_ft'

# Mac USB/오디오
ioreg -p IOUSB -l -w 0 | grep -i -E 'yealink|room camera|room audio'
system_profiler SPAudioDataType | grep -i -A6 -E 'yealink|hd20k'
```

> 비밀번호는 문서·로그·커밋에 기록하지 않는다. 명령 실행 시 환경변수로만 전달한다.

## 8. 후속 분석 연계 (2026-11-12 22:50)

본 보고서의 **USB B′ / T0-C 실기 대기 상태는 그대로 유지**된다. 다만 이후 SIP 경로의 로그를 별도 교차검증하면서 본 보고서의 전제 일부가 보강·정정되었다.

| 항목 | 본 보고서(v1.0) | 이후 확인 |
|------|-----------------|-----------|
| `1201` 등록 | `Unavailable` / 미등록 | **등록 성공**(`Avail`). A10 웹 `#/account-sip` 저장으로 1201 등록 확인, `6100` ConfBridge에 `PJSIP/1201-00000010` 참여 중(1h45m) |
| `1103` 상태 | `Avail` | `1102→1103` 발신 `404`는 **해당 시각 1103 AOR contact 부재**(`messages:1261-1265`, 16:05 UTC = 01:05 KST) |
| 원격 영상 | 6000 SFU는 A10 부적합(기존 분석 유지) | `6100`에서 `video-1 sendrecv/h264` **SDP 정상**. 미표시는 브리지 `follow_talker` 영상 전달 지점으로 좁혀짐 |
| USB B′ | 미열거 → 케이블/포트 확인 필요 | **변경 없음**(별건 추적 유지) |
