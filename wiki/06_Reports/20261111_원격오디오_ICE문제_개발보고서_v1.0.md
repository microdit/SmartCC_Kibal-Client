## 1. 요약 (Executive Summary)

- ConfBridge 6000 원격 오디오 누락의 **직접 원인(H1)** 을 수정했다. `sip_ua`가 `event.streams`가 비어 있는 원격 오디오 트랙을 폐기하던 문제로, 클라이언트에서 복구 로직을 추가해 `recovered=true kind=audio`를 확인했다.
- H1 수정 후 드러난 **미디어 경로 문제 4건**을 순차 규명·수정했다.
  - H4-1: Release 엔타이틀먼트에 `com.apple.security.network.server` 누락 → UDP ICE 불가
  - H4-2: Docker 컨테이너가 ICE 후보로 `172.19.0.2`를 광고, `media_address`는 `c=`만 보정
  - H4-3: `dtls_verify=yes`로 WebRTC 자체서명 인증서 검증 실패 → Asterisk 즉시 BYE
  - H4-4: 클라이언트 ICE가 도달 불가능한 시그널링 후보를 계속 검사하다 `ICE Connection Failed`로 자체 종료
- **v0.0.7에서 1101 오디오 단독 통화가 118초간 유지**되어 원래 목표(원격 오디오)는 달성했다.
- **H5(추가 규명·수정)**: 영상/다자간 재협상 실패의 직접 원인은 **클라이언트가 서버 re-INVITE에 200 OK를 보내지 않은 것**이었다. `sip_client.dart`의 `onNewReinvite`가 빈 구현이라 새 ICE 세대가 완료되지 못하고 15~17초 후 `ICE Connection Failed` → BYE. v0.0.8에서 자동 수락 구현.
- **잔여 문제**: v0.0.8 실기 재검증(영상/3자 5분 이상), 서버가 re-INVITE 응답 후 실제 영상 RTP를 송신하는지 확인.

## 3. 원인 체인

### H1. 원격 오디오 트랙 폐기 (수정 완료)

- 위치: `sip_ua 1.1.0` `lib/src/rtc_session.dart:1749` 부근
- `event.streams.isNotEmpty`일 때만 `EventStream`을 emit → msid 없는 ConfBridge 원격 오디오가 UI에 전달되지 않음
- 클라이언트 `macos-client/lib/src/sip/sip_client.dart`에 수신 트랙 복구 로직 추가
- 검증: v0.0.5 로그 `SIP remote-track recovery armed`, `recovered=true kind=audio`, `remoteStreamAdded audio=1`

> 주의: 트랙 존재만으로 수신 증거가 아니다. `SIP stats inbound audioBytes`와 서버 `pjsip show channelstats`의 RTP 카운트로 판정해야 한다.

### H4-1. Release 엔타이틀먼트 누락 (수정 완료)

- `macos-client/macos/Runner/Release.entitlements`에 `com.apple.security.network.server`가 없어 Release 빌드에서 UDP 소켓 바인딩이 차단됨
- 증상: 클라이언트 offer에 TCP 후보(port 9)만 존재, UDP 후보 없음
- 수정: `network.server` 추가 → v0.0.6에서 `192.168.11.22`, srflx `211.253.173.236` UDP 후보 생성 확인

### H4-2. Docker 내부 ICE 후보 (부분 완화)

- Asterisk answer SDP 예:
  ```
  c=IN IP4 192.168.11.39
  m=audio 10048 ...
  a=candidate:Hac130002 1 UDP 2130706431 172.19.0.2 10048 typ host
  ```
- `media_address`는 `c=`만 192.168.11.39로 보정하고 **ICE 후보는 172.19.0.2 그대로** 광고
- `external_media_address`도 ICE 후보를 바꾸지 못함
- `ice_support=no`로 끄면 클라이언트가 `488 Bad Media Description`으로 거부
- macOS Docker Desktop은 컨테이너에 LAN IP를 줄 수 없고, `--network host`도 VM IP(`192.168.65.4`)라 해결되지 않음

### H4-3. DTLS 인증서 검증 실패 (수정 완료)

- `webrtc=yes`를 개별 옵션으로 분해하면서 `dtls_verify=yes`가 됨
- 서버 로그:
  ```
  res_rtp_asterisk.c:3348 __rtp_recvfrom: DTLS failure occurred ...
  due to reason 'certificate verify failed', terminating
  RTP Read error: Unspecified. Hanging up.
  ```
- 수정: `dtls_verify=fingerprint` (WebRTC 자체서명 인증서를 SDP fingerprint로 검증)
- `webrtc=yes`는 `ice_support=no`를 덮어쓰므로, 개별 옵션(`media_encryption=dtls`, `ice_support=yes` 등)으로 유지

### H4-4. 클라이언트 ICE 자체 종료 (오디오 단독은 수정 완료)

- 미디어는 peer-reflexive 쌍으로 양방향 정상이었음
  - 서버 로그: `Sent RTP packet to 192.168.11.22:51938 (via ICE)`, `Got RTP packet from 192.168.11.22:51938`
  - 서버 channelstats: 1101 `rx/tx 3728/3788`, 1102 `rx/tx 726/780`
- 그러나 클라이언트는 시그널링된 `172.19.0.2`로의 connectivity check/consent가 실패해 ~85초 후 `RTCIceConnectionStateFailed` → `sip_ua`가 즉시 BYE(`408 ICE Connection Failed`)
- 수정: `macos-client/packages/sip_ua` 로컬 포크에서 **원격 SDP의 172.16/12 후보를 `c=` 주소로 보정**
  - `_rewriteUnreachableIceCandidates`, `_isDockerBridgeAddress`
  - 원격 offer(`_sdpOfferToWebRTC`)와 모든 원격 answer(`setRemoteDescription`)에 적용
- 결과: 1101 오디오 단독 통화 **118초 유지**(2026-11-11 12:43:55~12:45:54), ICE 실패 없음

### H5. 서버 re-INVITE 미응답 (v0.0.8 수정 완료)

**증거 (`docs/테스트/오늘테스트로그_v1.4.md` + `evidence/20261111-124756-remote-audio/`)**

- v1.4의 모든 영상/다자간 통화가 `callEstablished` 후 **17~35초**에 `cause=Code: [408], Cause: RTP Timeout, Reason: ICE Connection Failed`로 종료
- `remoteStreamAdded state=video=2`(서버 re-INVITE로 영상 스트림 추가) 직후 실패
- 서버 pjsip 로그:
  - 서버가 `INVITE`(re-INVITE)를 클라이언트로 전송: `CSeq: 14230 INVITE`, `CSeq: 18793 INVITE`
  - 클라이언트는 `100 Trying`만 보내고 **200 OK 응답이 없음**
  - re-INVITE SDP는 `m=audio` + `m=video`(sendrecv) + `m=video`(sendonly) 3개 m-line, 모두 `c=IN IP4 192.168.11.39` + `a=candidate ... 172.19.0.2 ...`
- 원인: `macos-client/lib/src/sip/sip_client.dart`의 `onNewReinvite(ReInvite event) {}`가 **빈 구현**
  - `sip_ua`는 `EventReInvite`를 앱 리스너에 전달하고, 앱이 `event.accept(...)`를 호출해야 200 OK(SDP answer)를 전송
  - 앱이 응답하지 않아 서버의 새 ICE 세대/DTLS가 완료되지 않고, 클라이언트 ICE도 실패 → BYE
- **오디오 단독 통화가 118초 유지된 이유**: 카메라/추가 참가자가 없어 re-INVITE 자체가 발생하지 않음

**수정 (v0.0.8)**

1. `sip_client.dart`: `onNewReinvite`에서 `event.accept({})` 자동 호출 + 로그(`SIP re-INVITE 수신 ... -> 자동 수락`, `응답 전송 accepted=...`)
2. `packages/sip_ua/.../rtc_session.dart`: `upgradeToVideo`가 re-INVITE마다 새 video track을 추가하던 문제 방지
   - 이미 로컬 video track/sender가 있으면 업그레이드 skip
   - 로그: `re-INVITE video upgrade skipped: local video already present`

**부수 관찰 (서버)**

- 서버는 클라이언트 영상 RTP를 **수신**(`Got RTP ... (type 100 ...)`)하지만, re-INVITE 미응답 상태에서는 **송신 0건**(`Sent RTP ... type 100` 없음)
- `confbridge.conf`의 `kibal_bridge`에 `video_mode=sfu`는 설정되어 있음 → re-INVITE 응답 후 SFU 영상 송신이 시작되는지 v0.0.8에서 확인 필요

## 6. 미진 사항 / 확인 필요

1. **v0.0.8/v0.0.9 실기 재검증 (P0)**
   - v0.0.8: 1101+1102 1:1 영상, 1101+1102+1103 3자 영상 5분 이상 유지(H5 검증)

   - `ICE Connection Failed` 0건, `videoBytes` 증가 확인
   - 서버 `Sent RTP ... (type 100 ...)`(영상 송신) 발생 여부 확인
2. **3자 입장 시 1명 튕김**
   - H5 수정으로 해소되는지 우선 확인. 잔존 시 `confbridge list`, 채널별 `pjsip show channelstats` 교차 확인
3. **영상/오디오 장시간 회귀**
   - v0.0.8 기준 1:1 영상, 3자 영상 5분 이상 유지 테스트 미실시
4. **증거 수집 스크립트 보정 (완료)**

5. **설치 방식**
   - 1101은 DMG 볼륨 직접 실행 중. `/Applications` 복사 설치 권장
6. **보안**
   - DEV 한정 `dtls_verify=fingerprint`. PRD 적용 시 인증서/CA 정책 재검토
7. **커밋/동기화**
