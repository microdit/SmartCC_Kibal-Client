## 1. 요약 (Executive Summary)

두 문서는 같은 사업(스마트경로당 다자간 영상회의)을 **upper-level(전략·역할) 과 RFP(요구사항) 관점**에서 각각 기술한다. 정합성은 대체로 높으나 **동시접속 용량 기준(문서① 50~150개소 vs 문서② 100~200자간)과 레이아웃 요구 구체성**에서 차이가 있어 제안 전 확정이 필요하다.

현재 Kibal 스택(Asterisk ConfBridge SFU, 브리지당 10명, RTP 201포트, endpoint 12개, 코덱 opus/vp8/h264)은 **문서①·②의 100~200자간 동시접속·4K·FEC 30%·MCU 믹싱·H.323/H.460·국정원/AES-256 요구를 직접 충족할 수 없다.** 따라서 제안 전략은 **"기존 Kibal을 소규모 파일럿/제어 평면으로 활용 + 전용 MCU(또는 YMS 연동) 게이트웨이 병행"** 의 하이브리드 구조가 현실적이다.

## 2. 문서 ① 분석 — MCU 핵심 역할 및 과업지시

### 2.1 인프라 핵심 개요
- 지자체 스튜디오 ↔ 다수 경로당 초연결 허브, **1:N & N:N**, 수십~수백 개소 동시 양방향
- 서비스: 노래교실·체조·건강상담·행정공지

### 2.2 MCU 4대 핵심 역할
| # | 역할 | 세부 |
|---|---|---|
| 01 | 대규모 미디어 믹싱/트랜스코딩 | 30~200개소 실시간 합성, 회선별 해상도 변환, 패킷 손실 격리 |
| 02 | 어르신 맞춤형 화면 제어 | 1+N, 4·9·16분할, 화자 자동 강조, 대형 TV 시인성 |
| 03 | 하울링 억제·무인 운영 | 다중 오디오 간섭 제거, 원격 Mute, Auto-Answer(버튼 조작 없이 연결), 중앙 세션/스케줄 |
| 04 | 표준/보안 | H.323·SIP, H.264/265·Opus, H.460·ICE/TURN, AES-256·국정원 |

### 2.3 RFP 6대 요구사항 (핵심 규격)
| 영역 | 요구 |
|---|---|
| 시스템 용량 | 50~150개소 Full HD 수용 + 채널 증설 |
| 표준 프로토콜 | H.323·SIP 동시, H.264/265·Opus |
| 네트워크 보안 | H.460·ICE/TURN, AES-256·국정원 준수 |
| 통합 관제 | TMS 실시간 모니터링, 일괄 초대, FECC·음소거 |
| 부가·연동 | 녹화, RTMP 송출, 표준 API/SDK |
| 안정성·보수 | HA 이중화·Failover, 1~2년 무상 출동 |

### 2.4 제안 전략 3체크포인트 / 아키텍처 결정
- 구축 형태 확인(온프레미스 포트 기반 vs 클라우드 동시접속 과금)
- 기구축 타사 코덱 SIP/H.323 게이트웨이 연동
- 관내 전체 확대·스마트 헬스케어 연동 로드맵

## 3. 문서 ② 분석 — RFP 예비 (GRND-2026-001)

### 3.1 개요/목표
- 배경: 제품군 확장, 글로벌 경쟁력, **국내제조 4K 지원 100% MCU 출시**
- 개발 대상: 하드웨어 화상장비 + 소프트웨어 단말
- 핵심: 범용 4K MCU(기본 Full-HD), **레이아웃 100가지 이상**, **최소 100 · 최대 200자간 동시접속**

### 3.2 기능/비기능 요구
| 구분 | 요구 |
|---|---|
| 기능 | 4K 기본 FHD, 레이아웃 100+, 100~200자간, 표준 프로토콜·OS·타사 호환 |
| 비기능 | 정량 응답/처리 용량, 서버 탑재형·H/W 구축형, 데이터 암호화, KC·CE·FCC |

### 3.3 시스템 모듈 12종
MCU, Registrar, Traversal, Meeting Mgmt, Device Mgmt, Enterprise Directory, SIP Trunk(A/V), WebRTC, GK & H.460, SfB(Lync) Gateway, Recording, Collaboration Server

### 3.4 첨부사양(YMS 동등이상) 핵심
- Video: 1080p60, 4K/1080p/720p/360p/4CIF/CIF, H.265/H.264 High/VP8
- Audio: Opus, G.722.x, G.711, G.729, AAC-LC 등
- **FEC: 영상 30% · 음성 70% 패킷 손실 방어**
- MCU: Continuous Presence, Universal Transcoding, MCU 스택, Equal NxN/onePlusN/twoPlusN/Overlay, IVR, SIP URI, Cascading, SfB 연동
- Registrar: 100,000 accounts, EXCEL 가져오기, AD 동기화, H.323/SIP 등록

### 3.5 규제·추진·검수
- 행정안전부고시 제2021-83호(공공기관 영상회의 상호연계 표준)
- 4단계 마일스톤(기획설계 → 시제품 → 테스트인증 → 양산이관)
- 산출물: 회로도·3D CAD·소스·API 명세, 시제품, 성적서
- 검수: QA 100% 통과, Critical/Major 0건
- 권리: 신규 IP 단독귀속, NDA, 12개월 하자보수

## 4. 교차 검토 — 정합성 매트릭스

| 항목 | 문서① | 문서② | 판정 |
|---|---|---|---|
| 동시접속 | 50~150개소 Full HD | 최소 100 · 최대 200자간 | **불일치** — 기준 확정 필요 |
| 해상도 | Full HD(1080p) | 4K 지원(기본 FHD) | 문서② 상위, 4K 필수 여부 확인 |
| 코덱(영상) | H.264/265, Opus | H.265/264 High/VP8 + 다수 | 부분 상충 — 공집합은 H.264/265 |
| 오디오 | Opus 중심 | Opus+G.7xx+G.729+AAC | 문서② 광범위, 호환성 부담 |
| 레이아웃 | 1+N, 4·9·16분할 | 100가지 이상, NxN/onePlusN/twoPlusN | 문서② 상위집합, 구체화 필요 |
| 보안 | AES-256·국정원 | SRTP/TLS·AES256·KC/CE/FCC | 상호 보완(국내+글로벌) |
| 네트워크 | H.460·ICE/TURN | ICE/TURN/STUN/H.460 | 일치 |
| 관제/연동 | TMS·FECC·RTMP·API/SDK | Meeting/Device/Directory/Recording/Collab | 상호 보완 |
| 안정성 | HA·Failover·1~2년 | 12개월 하자보수 | 유사(기간 상이) |
| 인증 | 국정원 준수 | KC·CE·FCC + 행안부 고시 | 통합 인증 계획 필요 |

## 5. 현재 Kibal 역량 대비 실현 가능성 (제안자 관점)

### 5.1 현재 구현 근거 (실측/설정)
| 항목 | 현재 값 | 근거 |
|---|---|---|
| Asterisk | 22.8.1 | Docker image |
| ConfBridge | **max_members=10**, video_mode=sfu/follow_talker | `server/asterisk/config/confbridge.conf` |
| RTP 포트 | **10000~10200 (201개)** | `deploy/dev/.env`, `rtp.conf` |
| SIP endpoint | 12개(1001-1004, 1101-1106, 1201, 7001) | `pjsip.conf.template` |
| 동시 등록 contact | 약 25개(브리지당 10명) | 기존 수용량 분석 보고서 |
| 코덱 | opus, vp8, h264, ulaw, alaw, g722 | `pjsip.conf.template` |
| 전송 | SIP over WS(8088), WebRTC, DTLS-SRTP | DEV 검증 이력 |
| 부하 테스트 | 최대 3자 회의, 1101↔1102 1:1 | `docs/테스트/*` |

### 5.2 요구사항별 격차
| RFP 요구 | 현재 Kibal | 판정 | 필요한 보완 |
|---|---|---|---|
| 100~200자간 동시접속 | 10명/브리지, RTP 201포트(~100 스트림) | **미달** | 전용 MCU or 다중 브리지+RTP 확장+자원 증설 |
| 4K / 1080p60 | WebRTC 720p/1080p 협상, H.264 High 미사용 | **미달** | 4K 인코딩 파이프라인, H.265 HW 가속 |
| H.323 / H.460 / GK | 미구현(SIP only) | **미달** | H.323 게이트웨이 별도 도입 |
| FEC 영상 30%/음성 70% | 미적용(WebRTC 기본 FEC 일부) | **미달** | FEC 설계·검증 |
| 12개 시스템 모듈 | Asterisk + OPS + Web 클라이언트(3종) | **부분** | Registrar/Traversal/GW/Recording/Collab 모듈 추가 |
| 100,000 accounts | endpoint 12개 | **미달** | 별도 DB/Registrar 스케일링 |
| TMS/FECC/IVR/녹화/RTMP | OPS 관제(연락처·회의실) 일부 | **부분** | FECC·IVR·녹화·RTMP 모듈 |
| AES-256·국정원·KC/CE/FCC | DTLS-SRTP(WS) 수준 | **미달** | 암호화/인증 체계 신규 구축 |
| HA/Failover | 단일 컨테이너 | **미달** | 이중화 구성 |
| Auto-Answer/어르신 UX | 수동 수락, 주소록 UI | **부분** | Auto-Answer, 대형 TV UI |

### 5.3 전략 권고 (하이브리드)
1. **제어 평면**: 기존 Kibal OPS(연락처/회의실/키/감사/시각화)를 그대로 활용 → 사업 관리·관제 UI 강점
2. **미디어 평면**: 100~200자간은 전용 MCU(예: YMS 동등 제품) 또는 Asterisk 다중 브리지+H.323 게이트웨이로 구성
3. **파일럿**: 현재 Kibal SFU로 소규모(10명 이하) 실증 → 레이아웃/오디오 제어 개념 검증(PoC) 후 확장
4. **규제 트랙**: 행안부 고시 제2021-83호 준수 여부를 별도 검증 항목으로 편성(현재 미검토)

## 6. 리스크 및 결정 필요사항

| # | 결정 사항 | 권고 |
|---|---|---|
| 1 | 동시접속 기준(50~150 vs 100~200) | 발주자 확인 후 **단일 기준 확정** — 제안서는 큰 값(200) 기준 설계 권고 |
| 2 | 4K 필수 여부 | "기본 FHD + 4K 옵션"으로 제안, 비용/성능 협상 여지 확보 |
| 3 | H.323/H.460 구현 주체 | 자체 개발 대신 호환 게이트웨이 도입(일정 단축) |
| 4 | 국정원/KC/CE/FCC 인증 범위 | 어느 기관이 어떤 인증 비용 부담하는지 계약서 명시 |
| 5 | IP 귀속 | "신규 결과물 단독귀속" 조항은 기존 Kibal 자산 재사용 범위와 충돌 가능 → **기존 자산은 별도 명시** |
| 6 | 검수 기준 | QA 100% + Critical 0은 명확하나, 성능 수치(지연/프레임/동시접속) 측정 방법 합의 필요 |
| 7 | 하자보수 기간 | 문서① 1~2년 vs 문서② 12개월 → 단일화 |

## 7. 결론 및 권고 (제안자 관점)

- **수주 가능성**: 제어 평면(OPS)은 이미 검증되어 강점이나, **미디어 평면(대용량 MCU) 격차가 큼**. 단독 Kibal 스택으로 응답은 위험 → 파트너 MCU 연동 하이브리드 제안 권고.
- **제안서 작성 전 체크리스트**:
  1. 동시접속/4K/FEC 기준 확정(발주 확인)
  2. MCU 파트너(YMS 등) 사양 비교표 및 라이선스 산정
  3. H.323/H.460 연동 범위 decided
  4. 인증(국정원·KC·CE·FCC) 책임/비용 분담 명시
  5. 기존 Kibal IP 재사용 범위 계약에 명기
  6. PoC(10명 이하 SFU) → 확장 로드맵 제시
- **본 의견서는 v1.0(제안자 관점)** 이며, 발주자 관점 보완이 필요하면 후속.v2로 작성한다.
