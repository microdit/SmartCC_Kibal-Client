## 1. 요약

외부망 WSS/TLS를 적용한 뒤 ① 6700 테스트 회의실에서 AI봇 영상이 보이지 않고, ② 외부망 1103 인증이 실패하며, ③ 내부 1101↔1102 통화에서 영상 프리즈·음성 끊김이 발생했다. 원인은 다음 네 가지로 정리된다.

| ID | 증상 | 직접 원인 |
|----|------|-----------|
| BUG-01 | 6700에 AI봇(7001) 참가자 자체가 없음 | 진단봇 데몬이 종료된 Chromium 인스턴스를 재사용하며 `newContext` 실패 무한 반복 |
| BUG-02 | 외부망 1103 `서버 연결 실패` 인증 실패 | OPS 8091을 외부에 열지 않아 설정 화면의 `/api/client/contacts` 검증 불가 + 로그인 성공 시 로컬 인증 미설정 |
| BUG-03 | 1102 영상 프리즈/음성 끊김, 1101 media stall | 외부용 공인 IP를 전역 `media_address`로 적용 → 내부 RTP가 NAT hairpin 경로 강제 통과 |
| BUG-04 | BUG-03 수정 후에도 끊김 지속 | 클라이언트가 Google STUN srflx 후보로 SDP `c=`를 공인 IP로 생성 → 여전히 hairpin |

## 2. BUG-01 — 6700 AI봇 미표시

### 2.1 증상

- 6700 입장 시 사용자 자신만 보이고 "AI봇(7001)" 참가자가 없음.
- 원격 영상이 "수신 준비중"으로 표시됨.

### 2.2 원인

`tests/diagnostic-bot/diag-room-bot-daemon.mjs`는 `chromium.launch()`를 `main()`에서 **한 번만** 수행하고 재시도 루프에서는 같은 `browser` 객체로 `newContext()`를 호출했다. Chromium이 종료된 뒤에는 모든 재시도가 다음 오류로 실패했다.

```
diag-bot error: browser.newContext: Target page, context or browser has been closed; retry in 5000ms
```

프로세스는 살아 있었으나 `confbridge list 6700`에는 7001 채널이 없었다.

### 2.3 판정

서버 다이얼플랜(7001 → 6700)과 ConfBridge 프로파일은 정상. **봇 런타임 결함**이다.

## 3. BUG-02 — 외부망 1103 인증 실패

### 3.1 증상 (사용자 로그)

```
EVENT UI SETTINGS action=connectionSaved params=domain=appletreeda.synology.me secureWs=false secureOps=false
WARN OPS client auth failed count=1/2/3
EVENT AUTH event=verifyResult state=failed ext=1103 ... reason=서버 연결 실패
WARN 서버 설정 갱신 실패: OPS 응답 없음 (후보 http://appletreeda.synology.me:8091, http://MacPro.local:8091, http://192.168.11.5:8091)
```

### 3.2 원인

- 보안 정책상 OPS 8091은 외부에 개방하지 않았다(8100번대 관리 평면 노출 금지).
- 그런데 `SettingsScreen._verifyAgainstServer()`는 `$base/api/client/contacts`를 호출해 인증을 판정하므로 외부망에서는 항상 연결 실패가 난다.
- 로그인 화면은 SIP 등록 성공 후 `ClientAuthStore`를 갱신하지 않아, OPS 검증을 거치지 않은 사용자는 주소록/통화 진입이 차단됐다.
- 저장된 `opsBaseUrl`이 `http://192.168.0.3:8091` 같은 과거 주소여서 후보 목록에 쓸모 없는 주소가 남아 있던 것도 갱신 실패를 가속화했다.

### 3.3 판정

1103 비밀번호 문제가 아니라 **인증 경로 설계 문제**(OPS 의존)이다.

## 4. BUG-03 — 내부 통화 품질 급락 (1차)

### 4.1 증상

사용자 로그 `v0.0.38 테스트 로그.txt`:

| 시각 | 1102 | 1101 |
|------|------|------|
| 15:16~15:18 | `audioLost` 624→2754 누적, `freeze=40`, `pli=42`, `vLost=4543`, `in=1280x720@4fps` | `audioLost=0`, 30fps 정상 |
| 15:25:29 | 계속 끊김 | `media stalled (20s no RTP)` → `force SIP re-init` → `autoCloseOnCallEnd` |

### 4.2 원인

외부망 대응 과정에서 `SDP_MEDIA_ADDRESS=211.253.173.236`(공인 IP)을 endpoint `media_address`에 전역 적용했다. 내부 단말(1101은 Mac Pro 자체, 1102는 Wi-Fi `192.168.11.59`)까지 SDP `c=`가 공인 IP를 받아 RTP가 **IPTime1 NAT hairpin**을 통과했다. TCP hairpin(8089 WSS)은 동작했지만 UDP RTP hairpin은 불안정해 손실·프리즈·stall이 발생했다.

### 4.3 1차 조치

`SDP_MEDIA_ADDRESS=192.168.11.5` 복구 + `rtp.conf`에 `stunaddr`와 `[ice_host_candidates] 172.21.0.4 => 192.168.11.5,include_local_address` 추가(내부 LAN 후보 + 외부 공인 srflx 후보 동시 광고).

## 5. BUG-04 — 1차 조치 후에도 끊김 (2차 원인)

### 5.1 확인 방법

`asterisk -rx 'pjsip set logger on'` 상태에서 1:1 통화를 열고 클라이언트 offer SDP를 확인했다.

```
m=audio 60730 UDP/TLS/RTP/SAVPF ...
c=IN IP4 211.253.173.236
a=candidate:... 192.168.11.5 60730 typ host ...
a=candidate:... 211.253.173.236 60730 typ srflx raddr 192.168.11.5 ...
```

### 5.2 원인

서버 `media_address`는 LAN으로 되돌렸지만, **클라이언트가 Google STUN으로 srflx 후보를 생성하면서 WebRTC가 SDP `c=`를 공인 IP로 선택**했다. 즉 클라이언트 offer 자체가 내부 통화에도 공인 주소를 광고했고, 1차 서버 조치만으로는 hairpin을 완전히 제거하지 못했다.

### 5.3 판정

LAN과 외부망을 **같은 ICE 프로필(항상 STUN)**로 처리한 것이 설계 결함이다.

## 6. 부수 결함 — probe 도구 초기화 누락

`register_probe.dart`, `call_probe.dart`, `conference_probe.dart`는 `main.dart`의 `AppLogger.init()`/`RemoteLogForwarder.start()`를 호출하지 않아 WSS 검증 시 다음 오류로 실패했다.

```
LateInitializationError: Field 'settings' has not been initialized.
```

앱 자체 결함은 아니며 검증 도구 결함이다.

## 8. 결론

- 외부망 기능 자체(WSS/TLS, REGISTER)는 정상이었으나 **내부망 경로를 외부 설정이 오염**시킨 것이 품질 저하의 핵심이다.
- NAT 환경에서는 `media_address`, ICE `c=`, STUN 후보가 **동일한 주소 정책**을 따라야 한다. 서버만 고치고 클라이언트 프로필을 남겨두면 문제는 재발한다.
- 관리 평면(OPS 8091)을 열지 않는 설계를 유지하려면 클라이언트에 **OPS 비의존 인증 경로**가 필요하다.
- 상시 봇 같은 백그라운드 프로세스는 브라우저/세션 종료 시 **매번 재생성**되어야 한다.
