## 1. 요약

- 분석 대상으로 제공된 로그는 **"1103 로그"가 아니라 1102 로그**였다. OPS `1102.log:249-267`과 한 글자까지 동일하며, 진짜 1103 로그는 별도로 `1103.log`(709KB)에 존재한다.
- `1102 → 1103`의 `404 Not Found`는 **1103 AOR에 유효 contact가 없는(미등록) 상태**에서 `Dial(PJSIP/1103)`이 실패한 결과로 **서버 로그로 확정**했다. 다이얼플랜·코덱·영상 협상은 무관하다.
- A10(1201)의 원격 영상 미표시는 **SDP 협상 문제가 아니다**. `video-1 sendrecv / h264`가 정상이며, ConfBridge `follow_talker`의 발화자 영상 전달 지점으로 좁혀졌다.
- 장시간 품질 저하는 **단일 원인이 아니라 3개의 독립 현상**이며, 이전에 의심했던 "카운터 집계 버그"는 **WebRTC 누적 카운터의 정상 동작**으로 정정했다.
- 클라이언트 코드에서 **신규 결함 2건**(re-INVITE 옵션 누락, 원격 스트림 누적)을 발견했다.

## 4. 항목별 결론

### A. `1102 → 1103` 404 【원인 확정】

| 항목 | 값 |
|------|-----|
| 다이얼플랜 | `exten => _1XXX,1,Dial(PJSIP/${EXTEN},60,tT)` — **정상** (`extensions.conf:17-19`) |
| 1103 endpoint | 존재(`webrtc-endpoint`, `allow=(opus\|ulaw\|alaw\|vp8\|h264)`) — **정상** (`pjsip.conf.template:227-242`) |
| 실패 지점 | AOR `1103`에 **유효 contact 없음** → outgoing session 생성 실패 → 404 |
| AOR 정책 | `max_contacts=3`, `remove_existing=yes`, `default_expiration=3600`, `qualify_frequency=30`, `remove_unavailable=false` |
| 현재 상태 | `pjsip show aor 1103` → contact 1개 `Avail`, `1103`은 `6100` ConfBridge에 `In use` |
| 1103 로그 | 해당 시각 기록 없음, `security`에 1103 인증 없음 |

> **개선 방향**: `remove_existing=yes`가 재등록 순간 contact를 비우는 구간을 실측(TC-A6)하고, `remove_existing=no`·qualify·expiration 조합을 서버 ADR-004로 결정한다. 클라이언트는 WS 재연결 시 재REGISTER를 보장한다.

### C. A10(1201) 원격 영상 미표시 【지점 특정】

`core show channel PJSIP/1201-00000010` (현재 6100 통화 1h45m):
```
NativeFormats: (g722|h264)
 WriteFormat : slin48   WriteTranscode: Yes (slin@48000)->(slin@16000)->(g722@16000)
 ReadFormat  : slin48   ReadTranscode : Yes (g722@16000)->(slin@16000)->(slin@48000)
 -- Streams --
 Name: audio-0  Type: audio  State: sendrecv  Formats: (g722|ulaw|alaw)
 Name: video-1  Type: video  State: sendrecv  Formats: (h264)
```

| 판단 | 결과 |
|------|------|
| SDP 협상 | **정상** (`sendrecv`, h264). `recvonly`/`inactive` 문제 배제 |
| 오디오 | g722 ↔ slin48 트랜스코딩 정상 |
| 1103 수신 | `1103.log` 최신 `in=1920x1080@30fps`, `videoKB≈183`, `ice=Completed` → 정상 |
| 제약 | `1201` `max_video_streams=1`(`pjsip.conf.template:146`), 브리지 `kibal_bridge_ft` = follow_talker |
| 남은 후보 | ① 발화자 영상 미전달 ② 자기 영상 루프백 ③ 단일 스트림 선택 로직 |

> **개선 방향**: `confbridge show profile bridge kibal_bridge_ft` + 발화자 전환 계측(TC-C4)으로 3후보를 판정한다.

### D. 클라이언트 코드 결함 2건 【신규 발견】

| ID | 위치 | 내용 |
|----|------|------|
| D1 | `macos-client/lib/src/sip/sip_client.dart:624-638` | `_acceptReinvite`가 `accept(<String, dynamic>{})`로 **빈 옵션** 전달. ADR-006 `_receiveVideoOptions()`는 발신(`:307`)·착신(`:356`)에만 적용되고 **재협상에는 누락** |
| D2 | `macos-client/lib/src/media/media_manager.dart:377-410, 575-590` | 재협상마다 `_remoteSessions`에 스트림이 추가되고 통화 종료 전까지 정리되지 않음 → `session(video=1→3→6)` 누적, 렌더러 4개(`:117-121`) 상시 유지 |

부수 확인: 제공 로그에 `SIP accept video=sendrecv`(`:358`)가 없어 **제공 로그는 현재 소스보다 이전 빌드**임을 확인. 현재 로컬 `app.log`는 21:17 세션(`mwdij3x9-12xi1m4`), `app-prev.log`는 20:20 세션으로 모두 다른 세션이다.

### B. 장시간 통화 품질 【3현상 분리】

| 시각 | 현상 | 계층 | 근거 |
|------|------|------|------|
| `01:11:03~01:11:28` | 첫 키프레임 대기 ~50초 | ConfBridge/디코더 | `videoKB=97 → 3181 → 9176`, `pli=1`, `decodedFrames+841` |
| `01:37:33` / `01:54:33` | 이산 손실 버스트 2회 | 네트워크 | `audioLost 0→15→29`, `vLost 0→42→134`, `pli 1→3→4`, `decodedFrames+720/+811` |
| `02:44:03~02:46:33` | out fps `14→16→15→16→12→15` 붕괴 | **로컬 인코더/CPU** | in `1280x720@30fps`, `decodedFrames+900`, `videoKB≈9185`, `target=1700kbps`, `limit=none` 전부 정상 |
| `02:47:03~` | out 29fps 회복, `freeze=109` 고정 | 정상 | 이후 프리즈 0건, 손실 0건 |

`freeze` 추이: `0→2→7→13→16→19→20→21→22→23→26→37→44→64→74→91→104→109(02:47:03)→109 고정`.
`keyframes`는 `109` 고정 이후에도 `63→67`로 계속 증가(주기적 키프레임, 정상). `nack=0`은 손실이 없었으므로 정상.

`01:15:03` out `1280x720@2500kbps → 640x480@1684kbps` 하향은 `qualityLimitationReason=none`이므로 **대역폭 적응이 아니라 앱/협상 측 재설정**(원인 미확정, TC-B5).

## 6. 미해결 / 다음 조치 (v1.1 정정 반영)

> **v1.1 정정 (23:15 실기)**: 발언자가 **1201로 자동설정**되고 그 영상이 1103에 정상 표시·음성 수신됨이 확인되었다. 따라서 4-C의 "후보 ① 발화자 영상 미전달"은 **기각**이며, `confbridge list`의 빈 `Flags`를 "발화자 미선정"으로 읽은 것도 오진이었다(Flags는 talker를 표시하지 않음). `Enable Events: no`는 이벤트 발행 설정이라 영상 전달과 무관 → **`confbridge.conf` 변경 불필요**. 상세는 [[wiki/08_Experiments/20261112_C_발화자영상_검증_v1.0]].

1. **C 잔여(실기 의존 2건)** — ① A10(1201) 실제 화면 캡처, ② 발화자를 1103으로 전환했을 때 A10에 1103 영상이 뜨는지. 지금까지 증거는 전부 **A10→1103 방향**이며 최초 증상 "A10이 원격 영상 못 봄"은 **1103→A10 방향**이라 미검증. `max_video_streams=1` + `follow_talker`에서 발화자가 자기 자신이면 원격 영상이 없는 것은 설계상 정상일 수 있음
2. ~~A6 contact 공백 실측~~ → **완료(23:58, A5 회귀 합격)**: `register_expires=300`이 294초 주기 재REGISTER를 만들고 `remove_existing=yes`가 갱신마다 contact를 비우는 것이 404의 정확한 메커니즘. 서버 ADR-004 구현(8개 AOR `remove_existing=no`/`remove_unavailable=yes`/`qualify_frequency=15`, `1201` 제외) + 클라이언트 A4 재연결 재REGISTER 구현(analyze 0 / test 17). **잔여**: 실통화 종료 후 컨테이너 재생성으로 런타임 반영 + A5 3시점 회귀
3. D1/D2 코드 수정 → v0.0.23+ 빌드
4. B3 인코더 부하 계측 → 60분 회귀
5. D3 `1102.meta.json` app_version으로 로그 빌드 기준선 확정
6. USB B′(A10 Yealink 미열거)는 별건으로 [[wiki/07_Logs/작업인계_20261112_A10_T0C]]에서 계속 추적

> 순서 `C → A → D → B` 유지. C 잔여 2건은 실기 캡처가 필요하므로 A로 먼저 넘어가도 무방하다.
