# 버전 역행 원인 분석 및 복구 보고서 v1.0

- 작성일: 2026-11-26 KST
- 대상: SmartCC_Kibal-Client `macos-client/pubspec.yaml`
- 상태: 분석 완료 / 복구 진행

## 1. 결론

6700 원격 트랙 누적 수정 커밋(`aac71569`)에서 버전을 **`0.0.63+64` → `0.0.58+58`로 잘못 역행**시켰다. 상위 버전 커밋은 삭제되지 않았고, **버전 번호만 잘못 기재**된 것이다.

## 2. 관측 근거

| 저장소/브랜치 | HEAD | 버전 |
|---|---|---|
| 로컬 `feature/external-network-access` | `aac71569` | `0.0.58+58` (잘못) |
| `origin/feature/external-network-access` | `aac71569` | `0.0.58+58` |
| `dev/feature/external-network-access` | `df9432cc` | `0.0.63+64` |
| `prd/feature/external-network-access` | `df9432cc` | `0.0.63+64` |

`aac71569`의 부모는 `df9432cc`(v0.0.63+64)이다. 즉 v0.0.63 상위 커밋은 그대로 있고, 그 자손 커밋에서 버전만 0.0.58로 되돌려진 상태.

## 3. 원인

- 작업 세션 시작 시점의 버전을 `0.0.55`로 기억하고 있어, 실제 최신(`0.0.63+64`)을 확인하지 않고 `sed -i 's/^version: .*/version: 0.0.58+58/'`로 강제 변경
- 브랜치가 `feature/external-network-wss`(서버) ↔ `feature/external-network-access`(Client)로 오가며 로컬 인식이 오래된 상태로 고정됨
- 빌드 전 원격 브랜치 pubspec 대조 절차가 없었음

## 4. 영향

- 코드 수정(트랙 누적)은 유효 — analyze/test 통과, DMG 생성됨
- 버전 역행으로 단말이 "이전 버전"으로 인식 → 업그레이드 안 할 수 있음
- dev/prd와 origin 간 HEAD 불일치(5커밋 차이)

## 5. 복구

1. `version: 0.0.64+65`로 변경 (최신 v0.0.63+64의 다음)
2. `Info.plist` CFBundleShortVersionString/CFBundleVersion 동기화
3. 재빌드 → DMG `macos_client_v0.0.64.dmg`, SHA256 기록
4. `origin` → `dev` → `prd` 순서로 3-way 푸시

## 6. 예방

- 빌드 전 아래 명령으로 기준 버전 확인:
  ```bash
  git show origin/feature/external-network-access:macos-client/pubspec.yaml | grep '^version:'
  ```
- 버전은 **최신 +1**만 허용, 절대 수동 지정 숫자로 되돌리지 않음
