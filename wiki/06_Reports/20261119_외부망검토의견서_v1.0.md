## 1. 요약 (Executive Summary)

- **현재 구현은 내부망(LAN) 전제**다. 외부망 접근은 코드에 구현된 상태가 아니라 실행 계획서 단계이며, 문서도 "외부망 실기검증 미수행"을 명시한다(`docs/보고서/20261114_외부망접근_실행계획_v1.0.md:101`).
- 클라이언트 기본값은 사설 IP(`ws://192.168.11.5:8088/ws`, `ws://192.168.11.2:8088/ws`)이고 시그널링은 평문 `ws://`다(`macos-client/lib/src/utils/constants.dart:20-35`, `macos-client/lib/src/sip/sip_client.dart:1067-1070`). DEV 서버 `192.168.11.5`는 현재 Mac Pro의 실제 주소와 일치한다.
- **STUN은 이미 설정·동작 중**이다(Google 공개 STUN, srflx 실측 확인: `wiki/06_Reports/20261111_원격오디오_ICE문제_개발보고서_v1.0.md:79`). 그러나 서버가 사설 주소를 광고하면 외부 클라이언트→Asterisk 미디어 경로는 열리지 않는다.
- **TURN은 미구성**이다. 코드에는 주석만 존재하며(`constants.dart:123-127`), 자격증명(username/credential) 전달 스키마도 없다(`sip_config.dart:30-31`, `sip_ua_helper.dart:927-935`).
- **TUN/VPN은 이 앱의 NAT 탐색 수단이 아니다.** OPS(8091) 관리 접근용으로만 권장되고, 일반 사용자의 인터넷 통화에는 부적합하다(`docs/_명령어/보안검토_v0.1.md:12-17`).
- 사용자가 WSS/TLS 우선을 결정함에 따라 **외부 시그널링 포트는 8088이 아니라 8089/TCP**가 된다(Asterisk HTTPS 기본 포트). 8088은 내부 전용으로 유지한다.

## 2. 현재 상태 분석

### 2.1 네트워크 토폴로지 (2026-11-19 사용자 확인으로 정정)

```
[인터넷/KT 공인 IP (동적)]
   │  DDNS: appletreeda.synology.me (Synology, 인증서 발급 완료)
   ▼
[IPTime1 — 단일 NAT / 공인 IP 보유]  (DDNS 갱신 주체)
   │  단일 대역 192.168.11.0/24
   ▼
[ L2 스위치 ]
   ├── Mac Pro 192.168.11.5   — Asterisk DEV/OPS (WS 8088 내부 / WSS 8089 외부 / RTP 10000-10200/udp)
   ├── PRD NAS `nas2` 192.168.11.3 — SSH 4949, Git dev/prd remote, DSM
   └── iMac/기타 단말 192.168.11.x
```

- **이중 NAT(IPTime2 `192.168.0.1`)는 더 이상 사용하지 않는다.** 2026-11-14 실행계획서의 `192.168.0.3`/IPTime2 DHCP 예약/2단 포트포워딩은 **폐기된 정보**다.
- 포트포워딩은 **IPTime1 한 곳**에서 `192.168.11.5`로만 걸면 된다.
- 근거: 사용자 확인(2026-11-19), 서버 `.env` `MEDIA_ADDRESS=192.168.11.5`, `docs/AGENTS.md` 환경표 갱신(본 작업 반영).

### 2.3 서버 측 현재 설정 (SmartCC_Kibal 리포 직접 확인, 2026-11-19)

```
server/asterisk/config/pjsip.conf.template:9-15
[transport-ws]
type=transport
protocol=ws
bind=0.0.0.0:${SIP_WS_PORT}
local_net=10.0.0.0/8
external_media_address=${MEDIA_ADDRESS}
external_signaling_address=${MEDIA_ADDRESS}

server/asterisk/config/http.conf.template:1-10
[general]
enabled=yes ; bindaddr=0.0.0.0 ; bindport=${SIP_WS_PORT}
tlsenable=no

deploy/dev/.env (현재값): MEDIA_ADDRESS=192.168.11.5
deploy/dev/.env.example: SIP_WS_PORT=8088, RTP_START=10000
```

**중요**: Asterisk 공식 문서에 따르면 `external_media_address`/`external_signaling_address`는 **ws/wss 전송에는 적용되지 않는다**(`pjsip.conf.sample`: "Note: This option does not apply to the ws or wss protocols"). 따라서 기존 transport-ws의 `external_*` 설정은 실질적으로 무시되고 있었을 가능성이 높다. 외부망 미디어 주소는 **endpoint 레벨 `media_address`**(Asterisk 18.22+/20.7+/21.2+)로 명시해야 한다(§4.3).

### 2.4 문서 간 정합성 문제 (확인 필요)

| 문서 | `external_*`/`MEDIA_ADDRESS` 기술 |
|------|----------------------------------|
| `20261111_원격오디오_ICE문제_개발보고서_v1.0.md:45-60` | `media_address=192.168.11.39`, `external_*=192.168.11.39` (사설) |
| `20261114_외부망접근_실행계획_v1.0.md:83-88` | `EXTERNAL_IP=<DDNS>` "이미 반영" |
| `docs/_명령어/보안검토_v0.1.md:7` | `external_media_address 없음 → 외부 클라이언트에 사설IP 광고` |
| 서버 `.env` (실제) | `MEDIA_ADDRESS=192.168.11.5` |

→ **Q2 해결**: 서버 `.env`의 `MEDIA_ADDRESS=192.168.11.5`가 현재 Mac Pro 주소와 일치한다. 다만 위 문서들의 `192.168.0.3`/`192.168.11.39`/`192.168.11.2`는 모두 이전 대역 기록이므로, 고문서는 토폴로지 정정 사실을 명시해 두고 신규 작업은 `192.168.11.5` 기준으로 진행한다. Asterisk SDP에 광고할 `media_address`는 **사설 `192.168.11.5`가 아니라 공인 IP**여야 한다(§4.3).

## 3. STUN / TURN / TUN 판정

| 기술 | 현재 | 필요성 | 판정 |
|------|------|--------|------|
| **STUN** | Google 공개 STUN 설정·동작 중, srflx 후보 실측 확인 | 필수 | **이미 충족.** 다만 서버가 공인 IP/포트포워딩을 가져야 srflx가 의미 있음. 공개 STUN 의존을 줄이려면 자체 STUN(coturn) 고려 |
| **TURN** | 미구성, 자격증명 주입 경로 없음 | 조건부 필수 | 대칭NAT/이동통신 CGNAT/UDP 인바운드 차단 환경에서는 **relay 필수**. coturn 구축 후 `iceServers`를 `List<Map>`(username/credential)로 확장해야 함. `turns:`(TLS) 권장 |
| **TUN/VPN** | 미사용 | 통화에는 불필요 | IP 라우팅 자체를 터널링하는 기술로 NAT 탐색 대안이 아님. OPS 8091 관리 접근에만 권장(`보안검토_v0.1.md:12-17`). 전체 통화를 VPN으로 돌리는 안(안3)은 "통화용에는 부적합"이라고 문서가 명시 |

**결론**: 포트포워딩 + 공인 `media_address` + WSS만으로 **일반적인 cone NAT 환경의 외부 1:1/다자간 통화는 성립 가능**. TURN은 "모든 단말에서 동작 보장"이 필요해지는 시점(대칭NAT/CGNAT 지원)에 추가한다.

## 4. 권장 구현 설계 (WSS/TLS 우선)

### 4.1 포트 매트릭스 (최종 요청안)

| 서비스 | 외부 프로토콜/포트 | 내부 대상 | 비고 |
|--------|-------------------|-----------|------|
| SIP WSS 시그널링 | **TCP 8089** | `192.168.11.5:8089` | Asterisk HTTPS/WebSocket 기본. **사용자 승인 완료** |
| RTP/RTCP 미디어 | **UDP 10000-10200** | `192.168.11.5:10000-10200` | 201개 포트, 1:1 매핑 유지 |
| SIP WS (평문) | 미개방 (내부 8088 유지) | `192.168.11.5:8088` | 외부 노출 시 계정/다이제스트 평문 전송 |
| OPS 8091 | 미개방 | — | VPN(WireGuard/Tailscale) 경유만 |
| SIP UDP 5060 | 미개방 | — | 본 클라이언트는 WS/WSS만 사용 |

**적용 위치: IPTime1 단 한 곳**(단일 NAT). IPTime2는 폐기되었으므로 이중 포트포워딩·DHCP 예약 작업은 불필요하다.

### 4.3 서버 변경점 (별도 리포, 실통화 종료 후 적용)

1. `server/asterisk/config/http.conf.template`
   ```ini
   [general]
   enabled=yes
   bindaddr=0.0.0.0
   bindport=8088
   tlsenable=yes
   tlsbindaddr=0.0.0.0:8089
   tlscertfile=/etc/asterisk/keys/fullchain.pem
   tlsprivatekey=/etc/asterisk/keys/privkey.pem
   ```
2. `server/asterisk/config/pjsip.conf.template`
   ```ini
   [transport-wss]
   type=transport
   protocol=wss
   bind=0.0.0.0
   ; ws/wss에서는 transport의 external_* 가 무시됨 → endpoint에서 설정
   ```
3. endpoint 템플릿에 `media_address=${PUBLIC_IP}` (또는 `media_address` + `bind_rtp_to_media_address=yes`) 추가. **DDNS 호스트명은 SDP `c=`에 사용 불가 → 리터럴 공인 IP 필요.**
4. `deploy/dev/.env` / `.env.example` / `entrypoint.sh` / `init-env.sh`에 `PUBLIC_IP`, `WSS_PORT=8089`, 인증서 경로 변수 추가.
5. 공인 IP 변경 대응: DDNS 해석 → `PUBLIC_IP` 갱신 스크립트를 컨테이너 기동 시 실행하고 Asterisk 완전 재시작(transport 변경은 reload 불가).
6. RTP 포트 범위 방화벽 허용은 10000-10200만. OPS 8091은 계속 내부/VPN.
7. DTLS: `dtls_verify=fingerprint`는 DEV 한정 결정(ADR-005:61) — PRD 인증서/CA 정책 재검토.

### 4.4 WSS 인증서 전제 (Q3 해결)

- **사용자 확인(2026-11-19)**: `appletreeda.synology.me` 도메인에 맞는 인증서가 **Synology(PRD NAS `nas2`, `192.168.11.3`)에 이미 발급되어 존재**한다. 신규 발급 불필요.
- 남은 작업: 해당 인증서의 **fullchain + private key를 Asterisk 컨테이너(`192.168.11.5`)가 읽을 수 있는 경로로 내보내/read-only 마운트**하고 `http.conf.template`의 `tlscertfile`/`tlsprivatekey`에 지정. DSM UI의 "인증서 내보내기"로 확보 가능.
- 인증서가 공인 CA(Let's Encrypt) 서명이면 클라이언트는 `wss://`를 **기존 코드 그대로** 사용 가능(`sip_ua`는 유효 인증서를 `WebSocket.connect()`로 처리, `websocket_dart_impl.dart:28-34`). `allowBadCertificate` 플래그는 불필요.
- 인증서 갱신(Let's Encrypt 90일) 시 Asterisk에 반영되는 경로/재시작 절차를 함께 정리해야 한다.

## 6. 검증 절차 (포트 개방 후)

```bash
# 1) 외부(휴대폰 테더링)에서 포트/인증서 확인
nc -zv appletreeda.synology.me 8089
openssl s_client -connect appletreeda.synology.me:8089 -servername appletreeda.synology.me
# 2) UDP RTP 도달 확인 (라우터 로그/서버 tcpdump 병행)
nc -zu appletreeda.synology.me 10000
# 3) 서버(내부) 확인
asterisk -rx 'http show status'     # HTTPS 8089 /ws URI 확인
asterisk -rx 'pjsip show transports'
# 4) 클라이언트
# 로그인: wss://appletreeda.synology.me:8089/ws
# 등록 → 1102↔1103 1:1 통화 → ConfBridge 6000 3자 통화
# OPS 로그: audioBytes>0, recovered=true, ICE failed 0
```

성공 기준: WSS TLS 핸드셰이크 성공, REGISTER OK, 양방향 오디오/영상 바이트 증가, 2분 이상 통화 유지, ICE failed 0.

## 7. 실행 순서

1. **사용자**: Q4/Q5 회신 → **IPTime1 단일 라우터**에서 `192.168.11.5`로 8089/TCP·10000-10200/UDP 포워딩 적용. Synology에 이미 있는 DDNS 인증서를 내보내어 Mac Pro에 배치.

3. **클라이언트**: §4.2 변경 적용 → `flutter analyze` / `test` → WAN 프로필 빌드.
4. **실기**: §6 검증 → 실패 시 OPS 클라이언트 로그 + Asterisk 로그 교차 분석.
5. **TURN 단계(별도)**: coturn 구축 후 대칭NAT/CGNAT 단말 검증, ADR 신규 등록.
6. **문서 후속**: 검증 결과 반영해 본 의견서 차기 버전 갱신, `docs/AGENTS.md`/작업이력 갱신, `git-sync.sh --auto --no-deploy` 동기화.

## 9. 환경별 대비책 — DEV(Mac Pro) vs PRD / 기타 외부 서버

### 9.1 환경 비교

| 항목 | DEV (Mac Pro) | PRD (`deploy/prd`) | 기타 외부 서버 / VPS |
|------|---------------|--------------------|---------------------|
| 배치 | IPTime1 NAT 뒤 `192.168.11.5`, 로컬 Docker, L2 스위치 단일 대역 | `network_mode: host`, 별도 `.env`/`ops.env`, `kibal-prd-*` 컨테이너 | 공인 IP 직접 보유 또는 클라우드 NAT 뒤 |
| 공인 주소 | DDNS `appletreeda.synology.me` (기존, 인증서 발급 완료) | **`MEDIA_ADDRESS=CHANGE_ME_PUBLIC_IP` placeholder 미설정** (`deploy/prd/.env:15`, `.env.example:25`) | 고정 공인 IP + 별도 DNS/DDNS 필요 |
| RTP 범위 | 10000-10200 (`deploy/dev/.env`) | **10000-20000** (`deploy/prd/.env.example:4-5`) → 방화벽/포트포워딩 범위 다름 | 서버 설정에 따름, 할당 범위만 오픈 |
| 시그널링 | WSS 8089/TCP 신규 (8088 내부 전용) | 동일 구조, **PRD 전용 호스트명·인증서 필요** | 동일. 필요 시 443/TLS 리버스 프록시 뒤에 배치 가능 |
| 인증서 | Synology에 DDNS 도메인용 이미 발급 → 내보내기/마운트 | 자체 ACME(Let's Encrypt) 발급·갱신 체계 별도 구축 | 도메인별 ACME, certificate rotation 자동화 |
| OPS | 8091 내부/VPN 전용 | `OPS_PUBLIC_HOST`, `OPS_PORT=8091` (`compose.yaml:86-91`) — **외부 노출 금지**, 별도 인증/네트워크 | 동일 원칙, 관리 평면은 VPN/SG로 격리 |
| 클라이언트 연결 | `wss://appletreeda.synology.me:8089/ws` | `wss://<PRD_DDNS>:8089/ws` | `wss://<SERVER_DNS>:8089/ws` |
| 기본값/프리셋 | `constants.dart:20-35` DEV 프리셋 (사설) | `sip_config.dart:172-190` PRD 프리셋은 **사설 `192.168.11.2` + `ws://`** → 갱신 필요 | 동일하게 하드코딩 프리셋 미적용, OPS 프로필로 주입 |

> `nas2`(`192.168.11.3`)는 **Git dev/prd remote·Synology 호스팅 역할**이며 SIP 미디어 서버가 아니다. PRD Asterisk는 `deploy/prd`가 배포되는 호스트를 의미한다.

### 9.2 환경 전환 시 반드시 분리해야 할 설정

1. **시그널링 주소와 SDP 미디어 주소 분리**
   - `wss://<hostname>:8089`는 DDNS/도메인으로 연결(인증서 검증).
   - SDP `c=`/`a=candidate`는 **리터럴 공인 IP**만 사용. 호스트명 불가.
   - 환경별 "공인 IP 해석 → endpoint `media_address` 반영" 스크립트를 두고, IP 변경 시 Asterisk 재시작(transport 변경은 reload 불가).
2. **프로필 기반 클라이언트 설정** (`server_config.dart:80-105`, `:141-162`)
   - `ServerConfig`에 `profile`(dev/prd/external), `secure`(wss 여부), `iceServers`/TURN 자격증명 필드를 추가.
   - OPS `/api/client/config`가 **프로필별** `wsServer`, `sipDomain`, `opsBaseUrl`, `publicHost`, `iceServers`를 배포.
   - 로그인 화면의 수동 WS 입력은 유지하되, OPS 갱신값이 기본이 되게 하고 mDNS(`MacPro.local`)는 LAN 전용 discovery로 강등.
   - `withScheme(secure:)`는 정의만 있고 호출처가 없음(`:141`) → OPS `secure=true` 수신 시 호출하도록 배선 필요.
3. **인증서/신뢰 경계**
   - 환경마다 다른 호스트명 → **공통 self-signed 인증서 재사용 금지**. 각 도메인에 맞는 공인 CA 인증서 사용.
   - `badCertificateCallback => true`(전면 허용)는 DEV 한시적 예외로 두고 PRD/외부 프로필에서는 제거.
   - Let's Encrypt 갱신(90일) 후 Asterisk reload/restart 자동화까지 포함.
4. **방화벽/포트**
   - DEV: `8089/TCP`, `10000-10200/UDP` → `192.168.11.5`.
   - PRD: `8089/TCP`, `10000-20000/UDP` → PRD Asterisk 호스트. OPS 8091·5060/UDP는 개방 금지.
   - 외부 VPS: 보안그룹에서 위 포트만 허용, 관리 SSH는 별도 SG/VPN.

### 9.3 NAT/네트워크 유형별 대비 매트릭스

| 상황 | 1차 대응 | 대비책 |
|------|----------|--------|
| 일반 cone NAT (현재 DEV 가정) | IPTime1 포트포워딩 + STUN srflx + 공인 `media_address` + WSS 8089 | DDNS/IP 변경 감시, 인증서 갱신 자동화 |
| 대칭 NAT / 모바일 CGNAT | STUN 후보 무효 → **coturn TURN relay** (`turns:` 443 권장) | `iceServers` 자격증명 주입, OPS 프로필로 배포 |
| 서버 측 공인 IP 없음 (통신사 CGNAT 등) | 포트포워딩 불가 → **공인 VPS 중계/SBC** 또는 호스팅으로 이전 | OPS만 VPN으로 유지해도 통화는 불가 → 별도 미디어 릴레이 필수 |
| 8089/TCP 차단 회사 방화벽 | WSS를 443/TLS 리버스 프록시 뒤에 배치 | 인증서 SNI 호스트명 일치 확인 |
| UDP RTP 전량 차단 | TURN over TCP/TLS(443) relay | 화질/지연 저하 감수, 모니터링 지표 추가 |
| DDNS 다운/갱신 지연 | 마지막 확인 공인 IP 캐시 + 수동 서버 설정 override | 다중 DDNS 공급자, 로컬 캐시 만료 정책 |
| 인증서 만료/불일치 | 클라이언트 오류 노출 + 수동 재설치 유도 | 갱신 자동화 및 만료 전 알림 |
| 장애 발생 시 롤백 | WSS → 내부 WS(8088) LAN 전용 전환 | 외부 경로는 차단 상태 유지, OPS 로그로 원인 분석 |

### 9.4 환경별 검증 체크리스트

| 환경 | 필수 확인 |
|------|-----------|
| DEV(Mac Pro) | `nc -zv appletreeda.synology.me 8089`, WSS REGISTER, `media_address`가 공인 IP, 1:1/3자 통화 2분 유지 |
| PRD | `.env`의 `MEDIA_ADDRESS` placeholder 해소, PRD 도메인 인증서, RTP 10000-20000 방화벽, OPS 8091 미노출, 클라이언트 PRD 프로필 주입 |
| 외부 서버/VPS | 고정 IP/DNS, 도메인 인증서, 8089/TCP + RTP 범위 SG 허용, TURN(선택), OPS 접근 경로, 로그 수집 |
