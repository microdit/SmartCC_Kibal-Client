## 2. 상세 분석

### 2.1 외부망 프로파일 기본값이 DEV 외부망으로 고정

- 근거: `macos-client/lib/src/utils/server_config.dart:45-56`
  - `ConnectionProfile.external.defaultConfig()` → `sipDomain=appletreeda.synology.me`, `sipPort=8089`, `wsServer=wss://appletreeda.synology.me:8089/ws`, `opsBaseUrl=http://appletreeda.synology.me:8091`.
- 근거: `macos-client/lib/src/utils/server_config.dart:58-66`
  - `ConnectionProfile.test.defaultConfig()` → `192.168.11.5:15060`, `ws://192.168.11.5:18088/ws`, `ops http://192.168.11.5:18091`.
- 근거: `macos-client/lib/src/utils/server_config.dart:81-89`
  - external candidates `http://appletreeda.synology.me:8091`, test candidates `18091/127.0.0.1:18091/8091`.

**판단**: 현재 "외부망" 프로파일은 4환경 분리 관점의 EXTERNAL 환경이 아니라, 기존 DEV 외부 접속 기본값으로 구현되어 있습니다. 사용자가 TEST를 외부 DDNS로 시험하려면 TEST 외부용 별도 프로파일/manifest 값 정의가 필요합니다. 단순히 external 기본값을 TEST 포트로 바꾸면 DEV 외부망/EXTERNAL 분리 정책과 충돌할 수 있습니다.

**권장 방향(승인 필요)**:
1. 4환경 정책에 맞춰 `EXTERNAL` 전용 엔드포인트를 manifest/프로파일로 명확히 분리.
2. TEST 외부 접속이 필요하면 `TEST-EXTERNAL` 별도 프로파일 또는 TEST manifest의 public/DDNS 후보를 분리 제공.
3. UI 라벨/설명에 "외부망=DEV 외부"인지 "EXTERNAL 환경"인지 명확히 표기.

### 2.2 연결설정 저장/유지 동작

- 근거: `macos-client/lib/src/ui/settings/settings_screen.dart:288-333`
  - `_saveConnection()`은 입력값을 정규화해 `ServerConfigService.setCurrent`, `cfg.save()`, `ConnectionProfileStore.save/setSelected` 수행.
- 근거: `macos-client/lib/src/ui/settings/settings_screen.dart:171-279`
  - `_switchProfile()`은 현재 입력 저장 후 `refreshProfileManifest` 호출, `resolvedProfileConfig(profile)`를 적용. resolved config는 manifest 우선(`server_config.dart:489-496`).
- 근거: `macos-client/lib/src/utils/server_config.dart:489-496,533-552`
  - `resolvedProfileConfig`는 manifest entry config가 있으면 그것을 우선 사용.

**판단**: 저장 자체는 파일에 기록되지만, 프로파일 전환/자동설정/manifest 갱신 흐름에서 서버 manifest가 우선되면 사용자 수동값이 덮일 수 있습니다. 이는 "서버 최신 프로파일 반영" 의도와 "사용자 수동 저장 유지" 기대가 충돌하는 설계입니다.

**권장 방향(승인 필요)**:
1. 수동 저장값과 manifest 자동값의 우선순위를 명시(예: 수동 오버라이드 플래그).
2. 설정 화면에 "서버 manifest 값 적용됨/수동 오버라이드" 상태 표시.
3. 저장 버튼은 현재 프로파일의 수동 오버라이드로 명확히 저장.

### 2.3 원격 로그 자동전송 주기 저장 누락

- 근거: `macos-client/lib/src/ui/settings/settings_screen.dart:159-170`
  - `_applyLogUrl()`에서 `RemoteLogSettings(...)` 생성 시 `autoSendMinutes`를 전달하지 않음. 생성자 기본값은 5분(`remote_log_settings.dart:23,40,64`).
- 근거: `_applyLogUrl()` 호출 지점: 연결설정 저장(`_saveConnection`), 프로파일 전환/자동설정 적용(`_applyResolvedConfig`) 경로.
- 근거: `remote_log_settings_dialog.dart:57,98,114,215-225`는 주기 UI/저장을 정상 처리.
- 근거: `remote_log_forwarder.dart:131-147,165-179`는 `setAutoSend(minutes)`/`applySettings`에서 주기 반영.

**판단**: 사용자가 1분을 저장해도, 연결설정 저장/프로파일 전환 시 `_applyLogUrl()`이 설정 객체를 재생성하면서 주기를 5분 기본값으로 되돌립니다. 재진입 시 5분으로 보이는 증상과 일치합니다.

**수정안(승인 필요)**:
- `_applyLogUrl()`에 `autoSendMinutes: s.autoSendMinutes` 추가.

### 2.4 주소록 연락처 "연결" 버튼 오류

- 근거: `macos-client/lib/src/ui/home/address_book_screen.dart:414-457`
  - `_quickConnect()`는 연락처 `c.extension/c.sipPassword`로 `SipConfig`를 만들고 `sip.connect()` 후 `/dialer`로 이동.
- 근거: `macos-client/lib/src/ui/home/address_book_screen.dart:333,415-418`
  - `_canCall => _auth.isVerified`만 허용. 오프라인 인증(`isOfflineVerified`)은 허용되지 않음.
- 근거: UI `address_book_screen.dart:698-701`는 연락처에 "연결" 버튼 제공.

**판단**:
1. 기능 의미 혼선: "연결"이 "해당 연락처 번호로 전화"인지 "해당 내선 계정으로 로그인/등록"인지 불명확. 현재 구현은 후자에 가깝습니다.
2. 인증 게이트 불일치: 주소록 일부 흐름은 offline verified를 허용하지만 quick connect는 verified만 허용.
3. 실제 오류 메시지는 런타임 확인 필요. 코드상 `sip.error ?? '연결 실패'` 스낵바가 표시되는 경로가 존재.

**재현/확인 필요 로그**:
- `AppLogger` UI/EVT: `ADDRESSBOOK.quickConnect`, `ADDRESSBOOK.quickConnectResult`.
- 실패 시 스낵바 메시지, SIP error, 선택 프로파일/등록 내선/연락처 extension.

**권장 방향(승인 필요)**:
- 제품 의도 확인 후 분리: "이 내선으로 로그인"과 "이 번호로 전화 걸기"를 별도 액션으로 분리.
- `_canCall` 조건을 offline verified 정책과 일치시킬지 결정.

## 3. 재현 체크리스트

1. 설정 > 연결 프로필 `외부망` 선택 → 기본값이 `8089/8091`로 표시되는지 확인.
2. 원격 로그 설정에서 자동전송 1분 선택/저장 → 연결설정 저장 또는 프로파일 전환 후 재진입 시 5분인지 확인.
3. 주소록에서 연락처 선택 후 "연결" → 오류 스낵바/로그(`quickConnectResult`) 확인.
