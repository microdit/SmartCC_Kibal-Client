## 4. 코드 경로 확인

`macos-client/lib/src/sip/sip_client.dart:162-171`:

```dart
  final target = session.remote_identity?.uri?.user;
  final policy = videoPolicyFor(target);
  if (policy == VideoCodecPolicy.keep) return null;

```

`macos-client/lib/src/sip/sdp_codec.dart:8-13`:
```dart
if (RegExp(r'^61\d\d$').hasMatch(t)) return VideoCodecPolicy.h264Only;
if (RegExp(r'^12\d\d$').hasMatch(t)) return VideoCodecPolicy.h264First;
return VideoCodecPolicy.keep;
```

→ `1201`은 `h264First`로 매핑되도록 **구현돼 있다**. 그러나 발신 offer 시점에 `session.remote_identity`가 null이라 `keep`이 되어 SDP가 무변환. `SipSession`(`sip_session.dart:32,105-111`)의 `remoteParty`는 `call()`(`:313-315`)에서 이미 설정되므로 폴백으로 사용 가능.

`sdp_codec.dart:56-62`는 H.264 중 `profile-level-id=42e01f`·`packetization-mode=1`을 우선 정렬한다(A10 호환 의도).

## 6. 결론

1. **1201 원격 영상 미수신 = 발신 offer의 코덱 정책 누락 → VP8 협상 → A10(H.264 only)과 불일치 → Asterisk 영상 트랜스코딩 불가.** 셀프 영상·음성·A10→1103 방향이 정상인 이유도 모두 설명된다.
2. **1101 튕김 = v0.0.23 A4의 재REGISTER가 WS `close by local` 루프를 유발.** 롤백 필요.
3. 수정안 F1(타깃 폴백)·F2(A4 롤백)와 검증 절차는 [[wiki/06_Reports/20261113_1201_1대1_영상미수신_교차분석보고서_v1.0]] 7장.

> **정정**: 선행 [[wiki/08_Experiments/20261112_C_발화자영상_검증_v1.0]]에서 "A10→1103 정상, 1103→A10 미검증"으로 남긴 방향이, 6100 브리지가 아니라 **1:1 코덱 협상**에서 실패함이 확인됐다.

## 7. 후속 — 6100 단독 입장 스피너 (01:10)

| 항목 | 확인값 |
|------|--------|
| `confbridge.conf:36-43` `kibal_bridge_ft` | `video_mode=follow_talker`만. **`video_source` 없음** |
| `confbridge show profile bridge` | `Video Mode: follow_talker`, `Video Update Discard: 2000`, `REMB Send Interval: 0`, **`Enable Events: no`**, Video Source 항목 없음 |
| `manager show command ConfbridgeSetSingleVideoSrc` | *"Set a conference user as the single video source distributed to **all other participants**"* → 자기 자신 제외 |
| `core show channel PJSIP/1201-0000000e` | `video-1 sendrecv / (h264)`, `NativeFormats (g722\|h264)` — 협상 정상, 분배 대상 0명 |
| `confbridge list 6100` | `PJSIP/1201-0000000b` + `PJSIP/1201-0000000e` — **1201 채널 2개 동시 존재** |
| `messages` 코덱 경고 | 마지막 `15:41:51 UTC`(=00:41:51 KST, 1:1). **이후 신규 0건** → 단독 입장 스피너는 코덱 문제 아님 |

**판정**: 1201이 유일한 참가자이면 `follow_talker`가 분배할 "다른 참가자"가 0명 → 1201 leg의 `video-1 sendrecv`로 RTP 프레임이 오지 않음. `video_source`/빈 회의실 정지영상 미설정이라 대체 화면도 없고, `Enable Events: no` + 원격 트랙 0으로 참석 카드도 구성되지 않는다. 셀프 영상(로컬 프리뷰)·음성(g722↔slin 트랜스코딩)이 정상인 것과 모순 아님.

→ 2번째 참가자 입장 시 해소되는지가 1차 검증(G1). 상시 소스가 필요하면 더미 참가자 + `ConfbridgeSetSingleVideoSrc`(G2), 카드 갱신은 `Enable Events: yes`(G3), 중복 1201 채널 정리(G5). 상세 [[wiki/06_Reports/20261113_1201_1대1_영상미수신_교차분석보고서_v1.0]] 10장.
