## 3. 정정 — 이전 오진

> **이전 서술(분석보고서 v1.0 / 직전 C 착수 보고)**: "`confbridge list 6100`의 Flags가 비어 있음 = 발화자(talker) 미선정 → 후보 ① 발화자 영상 미전달 유력"

**기각합니다.**

- 발언자는 **1201로 자동설정**되었고, 그 영상이 1103에 **큰 화면으로 표시**되며, 음성·영상 바이트가 지속 증가한다.
- 즉 `follow_talker`는 **정상 동작** 중이다.
- Asterisk `confbridge list`의 `Flags` 열은 잠금/뮤트/관리자 등 **사용자 플래그**를 보여줄 뿐, **현재 talker 마킹을 표시하지 않는다**. 빈 Flags는 "발화자 없음"이 아니다.
- `Enable Events: no`는 AMI/Stasis 발화자 변경 **이벤트 발행** 설정이며, 브리지 내부 영상 전달과 무관하다. → **설정 변경 불필요**.

## 4. C4 판정

| 후보 | 판정 | 근거 |
|------|------|------|
| ① `follow_talker`가 발화자 영상을 전달하지 않음 | ❌ **기각** | 발언자 1201 자동설정 + 1103 수신·표시 확인 |
| ② A10이 자기 영상만 루프백 수신 | ⏳ **잔여** | A10 측 화면 미확인 |
| ③ `max_video_streams=1` + 단일 스트림 선택 | ⏳ **잔여(설계상 정상 가능)** | A10은 `max_video_streams=1`, 발화자가 자기 자신이면 원격 영상이 없는 것이 follow_talker 설계일 수 있음 |

### 방향 재정리 (중요)

| 방향 | 상태 |
|------|------|
| **A10(1201) → 1103** | ✅ **정상 확인**(이번 증거). 발언자 영상 + 음성 수신 |
| **1103 → A10(1201)** | ❓ **미검증**. 최초 증상 "A10이 원격 영상을 못 본다"는 **이 방향** |

지금까지의 모든 증거(1103 로그·스크린샷·`BRIDGEPEER`)는 **A10이 보내고 1103이 받는** 방향이다. 최초 문제는 그 반대이므로 C는 아직 종결되지 않았다.

## 5. C에 더 필요한 것 (2건)

| # | 필요 항목 | 방법 | 판정 기준 |
|---|-----------|------|-----------|
| 1 | **A10(1201) 실제 화면 캡처** | A10 단말 화면 또는 A10 HDMI 출력 캡처 | 스피너 / 자기 영상 / 1103 영상 중 무엇이 보이는지 |
| 2 | **발화자 전환 테스트** | 1201 마이크 음소거(또는 1103이 발화) → 발언자가 1103으로 바뀐 뒤 A10 화면 확인 | A10에 **1103 영상**이 표시되면 ③은 "설계상 정상"으로 확정. 계속 스피너면 ②/③ 실버그 |

보조(선택): `Group: 0`(1103) vs `Group: -1`(1201) 차이가 ConfBridge video source 그룹 지정과 관련있는지 `confbridge show profile bridge`·Asterisk 문서로 확인.

> **결론**: C는 **코드·서버 설정 수정 없이** 위 2건의 실기 확인으로 종결 가능하다. `confbridge.conf` 변경안(ADR)은 불필요하며, 작성된 서버 ADR-004는 **A(등록 유지)** 항목에만 적용한다.

## 6. 다음 순서

C 잔여 2건은 실기 캡처가 필요하므로 **A(404 재현)로 먼저 넘어가도 무방**하다. A 완료 후 C 잔여를 재개하거나, A10 화면 캡처가 준비되면 C를 먼저 종결한다. 순서 `C → A → D → B`는 유지하되 C의 미결 2건은 실기 의존 항목으로 명시한다.
