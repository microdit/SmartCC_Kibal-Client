## 1. 테스트 관점 및 한계

| 관점 | 확인 방법 | IP |
|------|-----------|----|
| 내부/헤어핀 | 로컬 셸 `nc`/`openssl`/`curl` | `192.168.11.5` → 공인 IP 경유 |
| 웹 페치 | `webfetch` 도구(외부 egress) | `211.253.173.236` |

`webfetch`의 egress IP가 `211.253.173.236`으로 확인되어, **완전히 다른 ISP/해외 IP 관점은 아닙니다**. 따라서 아래 결과는 "공인 IP/WAN 측 규칙은 동작"을 의미하며, **미국 VPN 관점의 지오블록 검증은 별도로 필요**합니다.

## 2. 결과 요약

| 대상 | 경로 | 결과 | 의미 |
|------|------|------|------|
| `https://appletreeda.synology.me:8089/httpstatus` | HTTPS/WSS | **PASS** | Asterisk HTTPS 8089 외부 도달, TLS 정상 |
| `https://appletreeda.synology.me:8089/ws` | WebSocket | **PASS (HTTP 426)** | SIP `/ws` 엔드포인트 정상 |
| `https://appletreeda.synology.me:8091/api/client/config` | OPS | TIMEOUT | 외부 차단(정책) |
| `http://211.253.173.236:8091/health` | OPS | TIMEOUT | 외부 차단(정책) |
| `http://211.253.173.236:8088/httpstatus` | WS 평문 | TIMEOUT | 외부 미개방(정상) |
| `https://appletreeda.synology.me:8088/httpstatus` | WS 평문 | TIMEOUT | 외부 미개방(정상) |
| `https://211.253.173.236:8089/httpstatus` | IP 직접 | 전송 오류 | 인증서 CN/SNI 불일치(예상) |
| 로컬 헤어핀 8089 | TLS | **PASS** | TLSv1.3, `Verification OK` |
| WSS REGISTER | SIP | **PASS** | `REGISTER_OK` (선행 검증) |

### 2.1 외부 관점 응답 전문

`https://appletreeda.synology.me:8089/httpstatus`:

```html
Asterisk/22.8.1
Bind Address: 0.0.0.0:8088
TLS Bind Address: 0.0.0.0:8089
/ws => Asterisk HTTP WebSocket
```

`https://appletreeda.synology.me:8089/ws` → `426 Upgrade Required`.

## 3. 서버 상태

```text
HTTP Server Enabled and Bound to 0.0.0.0:8088
HTTPS Server Enabled and Bound to 0.0.0.0:8089
/ws => Asterisk HTTP WebSocket
endpoint 1102 media_address = 192.168.11.5
rtp.conf stunaddr = stun.l.google.com:19302
```

---

## 4. 판정

1. **SIP 시그널링 경로(WSS 8089)는 공인 IP 관점에서 정상 동작**한다. DDNS 호스트명과 TLS 인증서가 일치해야 하며, IP 직접 접근(`https://211.253.173.236:8089`)은 인증서/SNI 문제로 실패한다.
2. **OPS/로그 경로(8091)는 외부에서 의도적으로 차단**되어 있다. 사용자가 미국 VPN에서 경험한 timeout은 설계대로이며, 로그는 클라이언트에 로컬 보관 후 내부망 복귀 시 재전송된다.
3. 평문 WS 8088도 외부에 열지 않았다.
4. 완전한 해외 IP 검증은 아래 사용자 확인이 필요하다.

---

## 5. 사용자 확인 필요 (미국 VPN 관점)

```bash
nc -zv appletreeda.synology.me 8089
curl -v https://appletreeda.synology.me:8089/httpstatus
```

- 두 명령이 성공하면 해외에서도 SIP WSS 등록/통화가 가능하다.
- 실패하면 IPTime의 해외 접근 차단이 8089에도 적용된 것이므로 해당 공인 IP/국가에 대한 허용 규칙이 필요하다.
- 8091은 허용하지 않는 것을 권장한다(보안).
