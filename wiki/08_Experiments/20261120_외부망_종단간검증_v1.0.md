## 5. 8091 hang 실측·복구 확인 (MacPro 회신용)

### 5.1 이전 실측 (hang 재발 시점)

- `192.168.11.5:8091`: TCP OPEN, curl **HTTP 000 (6s timeout, 0 bytes)**
- `appletreeda.synology.me:8091`: TCP OPEN, curl **HTTP 000**
- 8089 (`/httpstatus`): 정상 → hang은 8091 프로세스에 한정

### 5.2 현재 실측 (복구 확인)

- `192.168.11.5:8091/health`: **HTTP 200** (0.009s)
- `appletreeda.synology.me:8091/health`: **HTTP 200** (0.78s)
- `appletreeda.synology.me:8091/api/client/config` (no key): **HTTP 401** AUTH_REQUIRED (도달 성공)
- `appletreeda.synology.me:8091/api/client/config` (with key): **HTTP 200**

### 5.3 결론

- MacPro의 "OPS hang 복구, /health 200" 주장은 **내 외부 관점에서도 재현·확인**됨. 이전 hang은 **일시적(transient)** 이었음.
- scheme(HTTP vs HTTPS)은 원인이 아니었음 — 8091은 HTTP-only 이고, hang은 프로세스 무응답이었음. 현재 정상.
- **잔여 이슈 해결 (v0.0.50)**: `probeProfile`에서 외부 프로필은 `defaultConfig()`(외부 URL 유지)를 기준으로 자격증명·메타데이터만 복사하도록 수정. OPS가 내부 IP를 반환해도 외부 URL이 덮어써지지 않음. (커밋 4f209da3)

## 6. MacPro에 대한 재검증 요청 의견 (B)

1. **OPS client_log_url 반환값**: 외부 요청에 대해 내부 IP(`192.168.11.5`) 대신 외부 주소(`appletreeda.synology.me`)를 반환하도록 서버 측 보완 요청. (클라이언트 측은 현재 외부 프로필 기본값으로 우회 가능)
2. **8091 hang 재발 방지**: 일시 hang 원인(컨테이너 unhealthy)의 근본 원인 파악 및 healthcheck/자동 재시작 정책 확인 요청.
3. **DMG SHA256 불일치**: 지시서 기재 `fc5ae6db…` vs 실제 빌드 바이너리 `f41b6545…` / DMG `7a2da5ff…`. 지시서 SHA가 어떤 산출물 기준인지 확인 요청 (기능 영향 없음).
4. **전체화면 진단 패널 지표 캡처**는 GUI 수동 수행 필요 → MacPro/사용자 측에서 캡처 후 보고서 §3 보완 요청.
5. **`collect-test-metrics.sh` 실행** (GUI 로그 즉시보내기 1회) 후 `wiki/08_Experiments/20261120_네트워크전환_품질검증_v1.0.md` 갱신.
