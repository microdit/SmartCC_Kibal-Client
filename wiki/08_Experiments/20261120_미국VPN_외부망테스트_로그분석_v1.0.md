## 1. 요약

미국 IP VPN 상태에서 1102는 **OPS(8091) 접근이 차단**되어 주소록/자동 설정이 실패했으나, **로그 업로드는 지연·재시도 끝에 서버에 도달**했습니다. SIP 등록/통화 이벤트는 해당 구간 로그에 없어, 외부망 실제 통화는 아직 미검증입니다.

---

## 2. 확인된 사실

### 2.1 클라이언트 버전/수신 상태

```text
1101  app=v0.0.46  last=2526s ago  mode=전체
1102  app=v0.0.46  last=87s ago    mode=전체
```

1102는 현재도 로그를 actively 업로드 중입니다.

### 2.2 외부 구간 로그 (18:20~18:39)

| 시각 | 이벤트 | 판정 |
|------|--------|------|
| 18:20:07 | `https://appletreeda.synology.me:8091` contacts/conferences Timeout | 예상된 차단 |
| 18:20:07 | `OPS directory: contacts=0 rooms=0` | 정상 fallback |
| 18:24:12 | 즉시전송 요청 → 0.6초 후 `전송 복구` | 성공 |
| 18:29:12 | 즉시전송 요청 → 12초 후 Timeout → 33초 후 `복구` | 지연 후 성공 |
| 18:34:12 | 즉시전송 요청 → Timeout → `복구` | 지연 후 성공 |
| 18:37:51 | SocketException → `복구` | 지연 후 성공 |
| 18:39:12 | 즉시전송 요청 → Timeout | 재시도 대기 |

→ **로컬 보관 → 지수 백오프 재전송 → 복구** 구조가 설계대로 동작했습니다.

### 2.3 OPS 로그 수신 확인

위 이벤트들이 OPS `/api/client-logs`에 그대로 저장되어 조회되었습니다. 즉 미국 VPN 구간에서도 로그가 **최종적으로 서버에 수집**되었습니다.

---

## 3. 서버 이슈 및 조치

점검 중 `kibal-dev-ops` 컨테이너가 `unhealthy` 상태였습니다.

```text
health=http 000, docker inspect = unhealthy running
```

조치: `docker compose restart ops` → `/health` 200, 정상 복구. 로그 수집 중단 구간은 이 OPS unhealthy 상태와도 일부 겹칩니다.

---

## 4. 미검증 항목

| 항목 | 이유 |
|------|------|
| 외부망 SIP REGISTER | 해당 시간대 로그에 `SIP state -> registered` 없음 |
| 외부망 1:1 통화 | `callEstablished` 없음 |
| 외부망 6700 입장 | conference 이벤트 없음 |
| RTP 품질 | video/media summary 없음 |

설정 화면 테스트와 로그 전송만 수행된 것으로 보입니다.
